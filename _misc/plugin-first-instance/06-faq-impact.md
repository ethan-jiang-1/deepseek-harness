# 06 · 这对 FAQ 26 意味着什么

先记录判断，不动正文。FAQ 26 现在的标题和框架把插件当"客人"——**装在别人的 DSH 里、借别人的家放东西**。而 `deckline` 这种实例里，插件是**主人**：它决定这个 DSH 为什么存在、装了什么、从哪个目录起步、模型能写哪。这是两种不同的读物。

## 现在的 FAQ 26 缺什么

| 现有内容 | 在插件即产品场景下 |
|---|---|
| 五种承诺 P0–P4（引用/派生/项目文件/home 账本/账号配置） | 全部假定"宿主已经有 home、有会话、有工作区"；缺"宿主就是这个产品"这一档 |
| 五个家（内容/历史/状态/派生/客户端） | 仍然成立，但缺"安装层"（bundle/profile）这个落点 |
| 13 作用域（session/workspace/profile/home/device/shared） | 仍然成立；缺"一次安装 = 一个实例"的表述 |
| 42 §8 每项目运行时 | 说的是"每 workspace 一套运行时"，不是"一个产品拥有一个根" |
| 反模式"把项目数据塞进账号配置" | 现在要加一条："把项目清单塞进 profile" |
| 全篇默认"模型直接读写项目文件" | 产品型插件常常**中介写**（模型只调工具）；FAQ 需要承认这条路线，否则沙箱一章会被读成"必须让会话进项目" |

## 三个改法

### D1 · 小改

改名 + 加三节：

- 新增"配置根（`projectsRoot`）"一节：五角色、谁写、判别依据。
- 新增"启动编排"一节：T1/T2/T3/T4、竞态、无门。
- 新增"沙箱与可写根"一节：唯一根、`cd` 不放宽、插件写 vs 模型写。

现有 11–42 的结构全部保留。代价：新旧框架并存，读者要自己拼。

### D2 · 中改（建议）

CN 名候选：

1. **26 · 插件即产品：一个 profile 如何决定安装、启动、编排与数据**
2. 26 · 单插件 Harness：产品型 profile 的目录、数据与编排
3. 26 · Plugin-first 实例：当 DSH 是为一个插件启动的

改动：

- 把"五种承诺"扩成六种，新增 **P5 产品实例**：权威=安装方/产品，落点=profile patch + bundle + 配置根，寿命=一次安装，代价=升级与隔离。
- **把"插件中介写 vs workspace 写"提成开篇分叉**，放在目录/数据讨论之前；`deckline` 是现成的正面样本。
- 新增 archetype **「配置根」**：R1–R5 + 四种判别依据 + 三种权威立场。
- 把"沙箱与可写根"**升为基础词汇**（放 10-foundations，而不是附录），因为所有方案都要过它。
- 41 决策程序的十八问里加 3 问：根从哪来？扫描权威是谁？模型要写根外吗？
- 24/25 交叉引用：24 管发布形态，25 管 workspace 与会话，26 管"产品实例"。

### D3 · 拆篇

26 保留"插件数据模型"；新开 28「产品型 profile：安装、启动、编排」。

代价：两份都要维护，边界容易打架（"启动编排"到底算数据还是算运行时）。

## 无论选哪个，先写沙箱

你的直觉是对的。理由是**顺序依赖**：

1. 沙箱结论决定哪些编排方案可行（组合 C/D 里的"全自动扫根"在模型写根外时会一直撞栅栏）。
2. 读者读"怎么安排目录"时，第一个问题必然是"模型能不能写它"。
3. 这一章的结论最稳定：唯一根、`cd` 不放宽、插件写 ≠ 模型写，短期不会变。先写它不会返工。

建议路径：

```text
1. 先把 03（沙箱可写根）写成 FAQ 26 的一章，独立可读
2. 再决定 D1/D2/D3
3. 重写 00-answer / 00-index（P5 + 配置根 archetype）
4. 回填 13（作用域）、41（决策程序）、42（参考架构）
```

## 需要先验证的三件事

写正文前，这三条不能靠推断：

1. **`sandbox-policy.workspaceRoot` 兜底在真实运行里的实际行为**：宿主插件 `ctx.fs` 无 session 写入时，是否真的按配置根放行（而不是 `process.cwd()`）。建议用一个 patch overlay 实测。
2. **Windows ACL 后端的 `partial`** 对"根外根"的影响；如果产品只跑 macOS/Linux，可以在 FAQ 里标注范围。
3. **`agent/created` 里写脚手架的代价**：它是 serial 且 await 的，抛错会让会话创建失败；要测一下磁盘 IO 在这条路径上的可接受度。
