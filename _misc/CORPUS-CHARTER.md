# 语料维护宪章

本文件是所在语料目录的行为准则。它约束**怎么写引用、怎么跟版本、怎么改语料**，不描述产品机制。与具体轮次的记录冲突时，本文件优先；记录只说明某一轮做了什么，本文件说明**为什么这样做、以后必须怎么做**。

它存在的理由只有一条：**同一个错误不要犯第二次**。下面每条规则都对应一次已经付过代价的返工。

## 一、引用的唯一形态

**指向 DSH 仓库内容的链接，一律指向默认分支 `master`。**

```
正确  https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/testing.md
正确  https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/core/agent
错误  https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.5/docs/testing.md
错误  https://github.com/deepseek-ai/deepseek-harness/blob/1f81c047fc48fa19.../docs/testing.md
```

理由不是风格，是**寻址语义**：`docs/testing.md` 是**内容**，`dsh-v0.2.1-rc.5` 是**时间点**。把时间点写进内容地址，等于给每一条引用都绑上一个会过期的坐标。实测过代价——128 个被引用的目标路径里，125 个在 rc.2 与 rc.5 之间逐字节相同，版本号在那些 URL 里**不承载任何信息**，但它们让每轮同步产生 322 行纯 URL 的 diff，还在 git 历史里留下大量并不存在的「修订」。

### 唯一的例外：事件与讨论的永久链接

```
允许  /commit/<sha>
允许  /pull/<n>
允许  /issues/<n>
允许  /discussions/<n>
```

这类标识索引的是**一个不可变的已发生事件**，不是「某个文件在某个版本的样子」。PR #5004 永远指 PR #5004，它不会因为上游发版而失效。固定 SHA 在这里是**正确**的，不是错误。

判据一句话：**问它会不会随时间漂移**。会漂移的（文件内容）指向 `master`；不会漂移的（已发生的事件）可以固定。

## 二、基线只有一个家

核验基线是必要的元信息：读者要能知道「这条结论是对着哪个版本核过的」。但它**只登记一次**：语料维护清单（`catalog.json`；等价实现是一个集中维护页，例如语料根下的 `00-baseline.md`）的 `baseline` 字段。

- 页面不写**当前基线**（release tag / commit / 「本页基线：…」）。需要说明可信度时写「核验状态见维护清单」，或链到该页的核验记录。正文引用历史 commit 作为证据时，按 §4 标注为历史。
- 每页的最后核验点登记在同一清单的 `verifiedAt`。它允许早于 `baseline`，但必须标为 `carried`，不得写成「与当前基线一致」。
- 历史跨度、OLD 侧、某轮修了什么属于 `_change_log/`；机制页只写当前行为。
- 实测记录可以写日期，但不得把日期或版本号写成当前基线。

判据：同一基线的声明数应为 1。第 2 份起就是维护负债——每轮同步都会多一处要改，而且必然漂移。页面里的每一次版本重复，都让「换版本」这个动作多一个假修订。

## 三、版本升级时改什么、不改什么

| 动作 | 做不做 |
|---|---|
| 改维护清单的 `baseline` 一处 | 做 |
| 逐条复核受影响结论 | **做**（这是升级的实质工作） |
| 改页面里的基线副本 | 不做（不应存在） |
| 改链接里的 tag 或 SHA | 不做（链接指向 `master`） |
| 删掉 `_misc/_references/` 等**冻结存档**里的原始引用 | 不做（那是文献原样存档，改写等于篡改） |
| 改历史记录 | 不做（只追加新记录，或在记录内加迁移注记） |
| 新增或移动页面 | 改清单与页面文件；覆盖矩阵由生成器产出，专题 map 的链接由校验器检查 |

关键区别：**改 URL 不等于复核**。把 322 个 URL 从 rc.2 扫成 rc.5，一个结论都没复核，却消耗了一轮全部注意力，还制造出「修订了很多」的错觉。真正的升级工作是第二行。

## 四、机器强制

规则必须可执行，否则下次换人、换上下文就会重犯。每份语料自带的 `verify.mjs` 至少覆盖以下检查：

- **外部链接白名单**：

```js
const dshExternalUrl = /^https:\/\/github\.com\/deepseek-ai\/deepseek-harness\/(?:(?:blob|tree)\/master(?:[/?#]|$)|(?:commit|discussions|issues|pull)\/)/
```

- **维护清单与文件树双向一致**：每个入库页面在清单里恰好一次，每个清单条目都存在；每条有 `role`、`verifiedAt`、`status`。
- **基线唯一**：全目录只能有一处**当前基线**声明（清单的 `baseline`）。页面不得再出现 `产品源码基线：` / `专题基线：` 形式；正文引用历史 commit 作为证据时，必须明确标为历史（`OLD`、`历史`、删除线、`0008 复核` 等标记，或紧随 `_change_log` 链接），不得写成当前基线。`_change_log/` 与冻结存档豁免。
- **表格列数**：Markdown 表每行必须与表头同列。覆盖矩阵曾因多塞四个单元格，把页面链接和 commit 移出渲染范围。
- **宪章副本逐字一致**：四份语料的 `CORPUS-CHARTER.md` 比对哈希。
- **计数可追**：正文不复制硬数字；包数、服务数、工具数只从 `claims.json` 的指标或生成目录读取。

`_misc/` 是冻结存档的例外：它的 `verify.mjs` 只做卫生检查，因为 `_references/` 是外部文献的原样保存，其中固定 SHA 的引用是文献本身的一部分，改写等于篡改；`_scratch/` 是可丢弃草稿。对这类内容**保留原样就是正确做法**，加白名单反而会逼人篡改存档。新增的散文仍遵守第一节。

校验器只校验**入库内容**：被 `.gitignore` 挡掉的本地研究笔记不参与，因为它们不是发布物，按设计可以引用仓库外的路径。

## 五、语料之间不互相依赖

每份语料都必须能**单独取走使用**：

- 机制页可以把另一份语料作为延伸阅读，但不得把它作为本页结论的唯一依据，也不得假设它存在。
- 索引与维护页可以链接兄弟语料作导航；导航链接不构成内容依赖。
- 跨语料链接失效时，本页结论仍需成立。
- 本文件在每份语料里各有一份副本，**内容必须逐字一致**；改一处时四份一起改，并由校验器比对。

## 六、每个事实只有一个家

| 事实 | 家 |
|---|---|
| 基线、页面清单、核验状态 | 语料维护清单（`catalog.json`；本语料的等价实现是 `00-baseline.md`） |
| profile 组合、`PROFILE_TEMPLATES`、bundle 层叠 | `runtime-profiles/` |
| 入口清单、CLI/SDK/ACP 契约、输出与退出、认证载体 | `surfaces-entrypoints/` |
| 两棵树的运行时、client/remote 机制、Typert | `two-tree-runtime/` |
| 插件的组合、生命周期、货架 | `plugin-system/` |
| 包数、服务数、工具数 | `claims.json` 指标或 `docs/` 生成目录 |
| 历史、退役、每轮改了什么 | `_change_log/` |

跨卷只允许「摘要 ≤3 行 + 链接」。同一张表、同一组数字、同一段对照不得在两卷并列维护：那会让下一轮同步出现两个必须同时改、又可能改得不一致的地方。

## 七、页面类型与核验状态

- `00-map.md`：概念、问题入口、阅读顺序、边界。不放机制细节、基线、轮次注记。
- 编号页：当前行为、不变量、失败面、源码入口。不放历史、计数、基线。
- playbook / 实测页：可复现步骤与实测原文；日期标为 `T`，不得冒充当前基线。
- 每页在清单里登记 `role`（`map` / `mechanism` / `playbook` / `experiment`）、`verifiedAt`、`status`（`reverified` / `carried` / `unrecorded`）。`carried` 不得写成「已按当前基线核验」。

## 八、改语料前先自问

1. 我加的这个链接，五年后还能打开并且指向**当时的同一份内容**吗？
2. 我把版本号写进 URL 了吗？能不能挪到维护清单？
3. 我改 URL 的时候，是不是假装自己在做复核？
4. 这个改动会不会让下一轮同步也要改同样一批文件？如果是，说明地址选错了。
5. 我改的是发布内容，还是冻结存档？
6. 这条事实的家在哪里？我是在改那个家，还是在复制一份副本？

第 4 条最重要：**任何「每轮都要重复一次」的动作，都说明方案本身错了**，不是执行不够勤快。
