# 诊断地图：六类症状，每条都有判定命令

## 一句话

「插件没生效」不是一个问题，是六个不同位置的问题。它们有各自的**判定命令**和**失败信号**，按顺序走一遍就能定位到段，而不是靠猜或重装。

## 三个诊断入口（先记住这三个）

| 入口 | 看什么 | 权威 |
|---|---|---|
| `dsh --profile <p> --dump-config` | 组合出来的**层与行**（含每行被谁覆盖） | `renderConfigDump` |
| 启动 stderr | **失活、跳过、缺服务**（`did not activate`、`skippedBundles`、`PENDING` 点名） | `auditStartupEntries`（`packages/boot/app-boot/src/index.ts:1153`） |
| `$DSH_HOME/profiles/<p>/.plugin-manager/logs/` | 装/卸的 pnpm 输出与失败原因 | 实测落盘路径（`operation-*/pnpm.log`） |

顺序固定：**先 dump 看组合，再看 stderr 看激活，最后看日志看安装**。跳步会把「没装进去」误判成「装了没生效」。

## 六类症状

### 1 · 装了，但列表里没有

|  |  |
|---|---|
| **判定** | 看 profile 的 `package.json`：`dependencies` 有没有它、`dsh.profile.bundles` 有没有它；再看包自己的 `package.json` 有没有 `dsh.bundle` |
| **信号** | CLI 通道：exit 0 但 roster 不变，stderr 一句 `declares no dsh.bundle — installed as a plain dependency, not a profile layer`；应用内通道：以 `not-bundle` 失败并回滚 manifest |
| **修复** | 给包补 `dsh.bundle.patch`，重装。没有这一层，它永远只是普通依赖 |

### 2 · 在列表里，但行没激活

|  |  |
|---|---|
| **判定** | `dsh --profile <p> --dump-config \| grep -A3 <row-id>`；再启动看 stderr |
| **信号** | 启动期 `warning: N entry did not activate`；装的时候可能已经 `installation rejected … nothing was installed`（版本门）。粒度的差别看动词：**bundle 级**是 `dsh: skipping profile bundle "X": …`，**行级**是 `dsh: disabling profile plugin row "X": Plugin … is incompatible with …`——后者行还在 dump 里，但启动时不会挂载，且进程照常起（实测：token URL 仍打印） |
| **修复** | 改 `engines.dsh`；或用精确豁免 `allow-version <pkg>@<ver> --dsh-version <ver> --accept-risk`（只在确实要冒险时） |

### 3 · 行在，但服务不可用

|  |  |
|---|---|
| **判定** | 启动 stderr 会点名**缺哪个服务**；也可以在该 fiber 的 ctx 上用 `ctx.get('<svc>')` 自查 |
| **信号** | `dsh: warning: 1 entry did not activate` 紧跟一行 `pending-row (@deepseek-ai/dsh-tool-todo): pending (waiting for service: nopeService)`；进程照常起，token URL 仍打印 |
| **修复** | 补上 provider 行；或检查 `inject` 里的名字拼写；或确认那个 provider 行没被 `disabled` |

### 4 · 改了配置，不生效

|  |  |
|---|---|
| **判定** | 先看 `--dump-config` 的层注释（谁最后覆盖了它）；再看该行是不是被写成了**字面值**（覆盖掉 `!!js` 表达式后，`--port` 这类参数就失效）；最后看 `hmr` 行是否启用 |
| **信号** | `--port 0` 不生效但**无报错**；或 HMR 抛 `Profile HMR requires application readiness` |
| **修复** | 把值改到正确的层（见 [`09`](./09-配置与设置面.md)）；保留 `!!js` 表达式；启用 `hmr` 行 |

### 5 · 首屏 401 或白屏

|  |  |
|---|---|
| **判定** | 三步 curl：无 token → 预期 **401**；带 token → 预期 **303 + `set-cookie: dsh-auth-<authority>`**；带 cookie → 预期 **200** 且页面里有 `__DSH_BOOT__` |
| **信号** | 任一步不符：401 说明 token 没带上或 authority 不匹配；303 后没 cookie 说明反代丢了 `set-cookie`；200 但无 `__DSH_BOOT__` 说明注入行没到 |
| **修复** | 用启动时打印的带 token URL；远程部署要让反代保留 cookie 与 authority（`--trusted-host`） |

### 6 · 卸载了，数据还在

|  |  |
|---|---|
| **判定** | `dsh plugin --profile <p> remove <pkg>`，然后看 `$DSH_HOME` 里你自己的数据目录 |
| **信号** | 无报错——这就是设计：移除只回收包与 patch 层 |
| **修复** | 在自己的 README 里写清数据位置与清理方法；DSH 不会替你删 |

### 7 · 手改 `cordis.patch.yml` 后启动失败

|  |  |
|---|---|
| **判定** | 看报错是不是 YAML 层：`failed to parse overlay <path>/cordis.patch.yml: YAMLException: end of the stream or a document separator is expected` |
| **信号** | 报错会带行号指针，指向你新加的第一行 `- insert:` |
| **修复** | profile 模板生成的 `cordis.patch.yml` 内容是 `[]`（空列表）。要加行，先把 `[]` 删掉，再写列表项；保留 `[]` 再追加会得到「一个文档里两个根节点」 |

## 一张速查表

| 症状 | 第一条命令 | 看什么 |
|---|---|---|
| 装了没有 | `cat $DSH_HOME/profiles/<p>/package.json` | `dependencies` / `dsh.profile.bundles` |
| 行有没有 | `dsh --profile <p> --dump-config \| grep <row-id>` | 层注释与行 |
| 活没活 | 启动并看 stderr | `did not activate` / 缺服务 |
| 生效没 | `--dump-config` 的层注释 | 最后覆盖者是不是你以为的那层 |
| 首屏通没通 | `curl` 三步 | 401 / 303+cookie / 200+`__DSH_BOOT__` |
| 装失败原因 | `ls $DSH_HOME/profiles/<p>/.plugin-manager/logs/` | 最近一次 `operation-*/pnpm.log` |

## 自证

```sh
# 一份可重复的诊断脚本骨架
P=demo
cat "$DSH_HOME/profiles/$P/package.json" | python3 -m json.tool | head -20
dsh --profile "$P" --dump-config | sed -n '/^# == /p'
dsh --profile "$P" --no-open --port 0 2>&1 | grep -E 'did not activate|skipped|missing' | head
ls -t "$DSH_HOME/profiles/$P/.plugin-manager/logs" | head -3
```
