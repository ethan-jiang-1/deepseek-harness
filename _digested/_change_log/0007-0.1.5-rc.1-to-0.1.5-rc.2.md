### 0007 第三轮新发现的一条上游生成文档缺口（未修，登记）

**`docs/capability-seams.md` 的 `ctx.tools` 消费者行不含 `mcp-client`**，而该包明确声明 `inject = ['tools']`（`packages/mcp/mcp-client/src/index.ts:32`）并在 `apply` 里注册它桥接来的外部工具。这是**生成器**的消费者识别缺口，不是语料问题：`docs/capability-seams.md` 是 freshness-gated 生成物，手改会被 `verify-doc-graphs` 打回，因此本轮只登记、不修。影响面：以该表为口径的 P/C 计数（FAQ 08）对 `ctx.tools` 的 consumer 数会少算 `mcp-client` 一个；因为 `mcp-client` 是 opt-in 且默认不挂，实际部署里它并不总是消费者，这一点也让「生成器该不该把 inject 当消费边」成为一个需要上游裁定的问题，而不是简单的漏列。

### 附：`_agent_ready_development/` 的双语配对排除

`scripts/translation-pairing.manifest.json` 的 scope 覆盖「每个非 vendor README」，而该语料是中文单语研究材料，其 8 个 `README.md` 因此长期让 `doc-quick` 的 translation pairing 一项失败（`_digested/` 与 `_faq_on_digested/` 没有 README，所以只有它命中）。本轮按该语料维护页预告的方式关闭：manifest 的 `excluded` 增加目录项 `"_agent_ready_development/"`（尾斜杠是路径边界）。之后 `npx tsx scripts/run-gates.ts doc-quick` **16 项全绿**，`verify-translation-pairing` 报 789 对全部一致。该语料维护页 2026-08-24 条目余下的两项（`doc-typecheck` 构建入口、documentation build 的 host Corepack `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`）仍需目录外工具链修复，`pnpm run test:docs` 也因此无法在本机跑通——门禁改由 `npx tsx scripts/run-gates.ts doc-quick` 直接驱动其 16 个 leaf 验证。
