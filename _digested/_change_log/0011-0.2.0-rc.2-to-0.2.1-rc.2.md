### 没有 merge 这回事

「产品源码只差 5 个目录，所以 merge 一下就行」是错的。`git merge-base(ethan, dsh-v0.2.1-rc.2)` 停在 `46a7f68b09`（`dsh-v0.1.7-rc.1`）——因为 0008、0009 两轮的整树照搬是 `read-tree`，它**不推进 merge base**。于是「0.1.7-rc.1 → 现在」这一整段在两个分支上都被改过，`git merge-tree --write-tree` 试算直接给出 **2047 个冲突文件**（`.agents/notes` 512、`packages/client` 368、`snapshots/session` 107、`packages/experimental` 82……）。

正确动作是**对齐，不是合并**：

```
git read-tree -u --reset dsh-v0.2.1-rc.2
git checkout HEAD -- _digested _faq_on_digested _dsh_plugin_agent_ready_development _misc .pi
```

零冲突，且结果树与「期望的 merge 结果」相同。验收判据只有一条，必须为空：

```
git diff --name-only master -- . \
  ':(exclude)_digested' ':(exclude)_faq_on_digested' \
  ':(exclude)_dsh_plugin_agent_ready_development' ':(exclude)_misc' ':(exclude).pi'
```

本卷实测结果：`0` 个差异路径。

### 由此退役：manifest 的本地排除行不再允许存在

0008 起唯一保留的本地口径行是 `scripts/translation-pairing.manifest.json` 的三行排除（`_dsh_plugin_agent_ready_development/`、`_faq_on_digested/17_dsh-native-development-process/`、`_misc/_eval_harness/README.md`）。它是**5 个目录之外的本地修改**，与新口径直接冲突，本卷起全部退役。

退役还暴露了它本就不可靠：`17_` 那行早已失效（目录后来改名 `19_dsh-native-development-process`），而排除是**前缀字符串匹配**，所以那行匹配不到任何东西——**修正前的 pairing 门禁本来就是红的**，只是没人跑到。

治本方案是**5 个目录内部不使用 `README.md` 作为落地页**。仓库的 bilingual pairing 门禁把任意 `README.md` 当产品文档语料，而 `_dsh_plugin_agent_ready_development/verify.mjs` 原先强制每个目录必须有 `README.md`，两条门禁在 10 个文件上正面对撞；`_digested/` 早就绕开了（理由写在 `_digested/00-index.md`），所以这只是把另两个目录拉到同一约定上。

| 落地页新名 | 适用 | 文件 |
|---|---|---|
| `00-index.md` | 该目录本无卷内容页 | `_dsh_plugin_agent_ready_development/` 根、其 `_coverage/`、三个 `figures/`、`_faq_on_digested/19_dsh-native-development-process/figures/`、`_misc/_eval_harness/` |
| `00-map.md` | 该目录已有卷内容页 `00-index.md` | `native-development-model/`、`repo-harness/`、`sdlc-reference/` |

`verify.mjs` 的规则同步改为接受这两个名字；`_digested/verify.mjs` 也已把两者列为 orphan 豁免，两处口径一致。结果：pairing 门禁 **1014 对全绿**，且 manifest 是上游原版、零本地行。

### 本卷新增的两条反查纪律

按「引用变动的产品路径」求交得到的 191 文件清单**不完备**，本卷实测发现两类会整批漏掉的文件，后续同步应各自单独扫一遍：

1. **按数字陈述、不引用任何变动路径的文件。** 例如 `plugin-inventory/00-map.md` 写「dsh 出厂自带 316 个包、92 个 `ctx` 服务」，一个变动路径都没引用，按路径求交永远找不到它。本卷因此建了一致性检查器（扫「仍以现行口吻出现的旧基线数字」），首轮即抓出 **14 个这样的文件，其中 6 张 SVG 图**——图里的硬数字（`316 个包`、`seam（33）`）最容易被漏。
2. **引用了已整族删除的机制、但该删除不在变动路径交集里的文件。** 例如 `harness-idea/claims.json`、`_digested/verify.mjs`、`sdlc-reference/figures/agent-contract-evidence.svg`：它们把 `packages/core/agent-loop/src/invariant.ts` 当现行机制引用，而该文件属于「整包删除」而非「路径迁移」，容易在按 `.md` 文件反推清单时被排除。本卷实测：提到 invariant 一词的有 83 个文件，**真正引用已删除 invariant 面的 39 个**，其中 **12 个不在按路径推导的清单内**。

**教训**：`path:line` 求交只是反查的**第一刀**，它天然覆盖不到「按数字陈述」与「引用被删机制」两类。判据应加上「该文件是否陈述了某个会随同步漂移的量」与「该文件是否引用了被删除的机制」，而不只是「它引用了变动的路径」。
