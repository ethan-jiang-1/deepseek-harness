## 唯一的产品树例外

`scripts/verify-repository-references.ts` 与同名 `.spec.ts` 保留本地版本（本地提交 `65b1fae6b9`）。它做两件事：

- `_digested/` 等研究语料前缀**只做 commit-hash 之外的检查** —— 语料按设计引用历史 commit 作为证据，那不是「维护中的引用」。
- 锁文件（`pnpm-lock.yaml`、`package-lock.json` 等）跳过 commit-hash 检查 —— 完整性摘要可能偶然命中某个对象名。

没有这个补丁，`pnpm run verify-repository-references` 会对语料里的历史 commit 报红。**它是本地语料的配套机制，只是因为门禁脚本住在产品树里才落在这 2 个文件上**；若上游日后允许在门禁配置里声明语料路径，这个例外即可回收。

## 语料吸纳

本轮在两个语料目录上做了改动：`_digested/` 只换基线锚点与索引；`_dsh_plugin_agent_ready_development/` 除此之外还改了链接寻址政策（下节）。`_misc/` 与 `_faq_on_digested/` 未改。
### 链接寻址政策（本轮生效）

语料的外部链接此前固定到 release tag（`blob/dsh-v0.2.1-rc.N/…`），使「换一个版本核验」这个动作被迫表现为改 322 行文本。实测：**128 个目标路径中 125 个在 rc.2 与 rc.5 之间逐字节相同**，版本号在那些链接里不承载任何信息，纯属噪音；且每轮同步都会在 git 历史里留下大量并不存在的「修订」。

改为：**链接一律指向 `blob/master/`**，不带版本号。核验版本只记在各自语料的维护页（本卷对应 `_dsh_plugin_agent_ready_development/_coverage/00-corpus-maintenance.md`，即本语料之外）与各自的根索引，一条引用在各轮同步之间保持同一 URL，版本升级不产生语料 diff。

机器强制（`../verify.mjs` 的 `dshExternalUrl`）：只接受 `deepseek-harness/{blob,tree}/master`；`main`、任意 `dsh-v*` tag、commit SHA、`master-extra` 这类近似名一律拒绝（`verify.test.mjs` 逐条断言）。这保留了「证据必须指向一个可解析、有维护的 DSH 资源」，只放弃了「钉死到已核验版本」。

落地：395 处 URL 改为 `master`（含 322 处本轮批量改的）；`verify.mjs` 白名单与其测试同步换口径；5 处描述钉版策略的正文改写。实际 diff：33 个文件、658 行纯 URL、33 行实质文字。

**下一轮同步不需要再碰这批链接。** 只有真依赖版本的东西（升级指南、历史样本）才用 tag，并优先以路径 + 文字描述引用而非裸 URL。

[`_misc/_references/`](../../_misc/_references/) 下的冻结存档保留其原始引用（如 `tree/dsh-v0.1.2-alpha.2`）：那是外部文献的原样存档，不是本语料维护中的引用，改写它等于篡改存档。
