# 03 · 不再使用的写法

这张表只记一件事：**哪些写法本语料不再用，以及换成 DSH 的哪个说法**。表里的词都不属于 DSH——这正是它们被列在这里的原因。

## 退役表

| 不再写 | 问题 | 换成 |
|---|---|---|
| 产品型插件 / 产品 profile / 产品 bundle / 产品 project | `product` 在 DSH 里指整台运行的 dsh，不修饰单个对象 | 说清是 bundle、profile，还是整份组合 |
| 入口 profile / 应用面 | 两个字都是中文自造；DSH 的原词是 `profile` 与 `app surface` | `profile`、`app surface` |
| 五个家 / 内容家 / 历史家 / 状态家 / 派生家 / 客户端家 | 「家」是隐喻；DSH 只有 `Harness home` 这个具体路径概念 | 直接点名机制：files、session log、storage domain、derived、client state |
| 四个空间 | 与「五个家」同构，且没有 DSH 依据 | 说清是哪几类资产、各自由谁拥有 |
| 一个事实一个权威 | 转写 DSH 原句时换掉了词 | **一个事实一个家（one home per fact）** |
| gate 泛指一切「拦住」 | DSH 的 `quality gate` 专指可机械失败的检查；`docs/AGENTS.md` 要求写具体检查名 | 写具体检查名，或写 refuse / reject / skip 这类动作 |
| 把外部生态的说法写成「DSH 的做法」 | 典型例子：`paved road` 在 repo 里 grep 不到 | 写成「外部生态常说」，并给出 DSH 自己的原话 |

## 两条判定

1. **能 grep 到吗？** 搜不到 DSH 原文的说法，就不能以 DSH 的名义出现。
2. **它是在描述 DSH，还是在描述我们？** 描述我们的（分类、指标、阶梯、评分），不进本目录；它在自己的专题里，最多引用这里。

## 为什么不收「本语料的分类」

本语料为了分析造过一些名字——阶梯、比例、平面、卡片一类。它们不是 DSH 的类型、字段或官方命名，因此：

- **不进本目录**，也不在 [`GLOSSARY`](./GLOSSARY.md) 里与 DSH 的词并列；
- 需要时由各自的专题定义，并写明「这是本篇的说法」；
- 一旦发现某个词被读成了 DSH 的机制，就在这里加一行，说明它退役了、换成了什么。

## 加一行的条件

同时满足两条才加：

1. 这个词已经在正文里出现过，并且真的让人误以为它是 DSH 的东西；
2. 能给出一个 DSH 的原词或原句来替换它。

只是「我不喜欢这个说法」的，不加。
