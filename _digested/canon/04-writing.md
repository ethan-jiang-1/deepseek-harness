# 04 · 措辞与引用纪律

本篇是三件具体的事：怎么引用 repo、怎么写判断、怎么让中文不把英文词吃掉。

## 一、引用 repo 的三种形态

| 想引用什么 | 怎么写 | 为什么 |
|---|---|---|
| 一份文档的当前内容 | `https://github.com/deepseek-ai/deepseek-harness/blob/master/<path>` | 内容会漂移，指向默认分支；换版本时只改陈述基线的那一句 |
| 一个已经发生的事件 | `.../pull/<n>`、`.../commit/<sha>`、`.../issues/<n>` | 事件不可变，固定标识是正确的 |
| 一条具体源码事实 | 相对路径 + 符号名，如 `packages/boot/app-boot/src/profile.ts` 的 `bundlePatchFiles` | 符号比行号稳定 |

反面写法：把 release tag 写进内容 URL；把「本页基线是 rc.X」写进正文；用 SHA 指向一份还在改的文档。

## 二、三种句子必须能分开

读者要能一眼看出哪句是 repo 说的、哪句是本卷的判断：

| 句子类型 | 长什么样 | 例子 |
|---|---|---|
| **repo 事实** | 给出处，转述不改义 | 「`--dump-config` 报告的是配置出来的组合，不证明插件已挂载」 |
| **本卷归纳** | 明写是归纳，或带「本卷」「本篇」 | 「本卷把这条判断拆成三档来源」 |
| **外部样本** | 带等级标记，且不推出 DSH 行为 | 「某第三方包 README 称它支持 X（`[R]`），本卷未安装验证」 |

最容易犯的错是第三种冒充第一种：把一个社区词写成「DSH 的说法」。写之前问一句——**这句能在 repo 里 grep 到吗？**

## 三、中文不许吃掉英文词

承重词保留英文原文，理由是可检索：读者拿着 `roster`、`app surface`、`storage domain` 能在 repo 里搜索，拿着中文译名搜不到。

| 场景 | 写法 |
|---|---|
| repo 有中文译名 | 用中文，首次出现给英文：**组合包**、会话日志、具名组装、一个事实一个家 |
| repo 没有中文译名 | 保留英文：`app surface`、`roster`、`storage domain`、`scope key`、`waterfall` |
| 本卷自造的装置 | 中文名 + 英文锚点，并在 [`03`](./03-retired.md) 登记 |
| 代码标识符 | 一律原样，用反引号包起来 |

判据：**把中文词拿去 repo 搜得到吗？** 搜不到就换成英文原词。

## 四、四类禁写

1. **隐喻当机制**。「皮」「壳」「内核页表」这类比喻只能出现在解释的下一层，不能当术语。
2. **同一概念两个词**。一页里出现两种叫法，读者会以为是两件事；要么统一，要么在首现处说明是同一物。
3. **没有主语的断言**。「DSH 会拒绝」要说清是哪一步拒绝、看哪条证据。
4. **循环引用**。`A 见 B`、`B 见 A`，两页都不给定义——这是术语没有家的典型症状。

## 五、改词之前先问

1. 这个词在 [`GLOSSARY`](./GLOSSARY.md) 里吗？在里面就按表改，不要另起。
2. 它背后对应 [`02`](./02-thinking.md) 的哪一条判断？对应不上的，多半不是术语而是修辞。
3. 改完以后，读者能在 repo 里 grep 到吗？
4. 这次改的是发布内容，还是冻结存档？（存档不改，见语料宪章）
