# 04 · 措辞与引用纪律

写页之前对一遍。三条：怎么引用 DSH、怎么让两种句子分得开、中文怎么不把英文词吃掉。

## 一、引用 DSH 的三种地址

| 引用什么 | 怎么写 | 为什么 |
|---|---|---|
| 一份文档的当前内容 | `https://github.com/deepseek-ai/deepseek-harness/blob/master/<path>` | 指向默认分支；换版本时只改陈述基线的那一句 |
| 一个已发生的事件 | `.../pull/<n>`、`.../commit/<sha>`、`.../issues/<n>` | 事件不可变，固定标识是正确的 |
| 一条源码事实 | 相对路径 + 符号名，如 `packages/boot/app-boot/src/profile.ts` 的 `bundlePatchFiles` | 符号比行号稳定 |

反面写法：把 release tag 写进内容 URL；在正文里复述「本页基线是 rc.X」；用 SHA 指向一份还在改的文档。

## 二、两种句子必须分得开

读者要能一眼看出哪句是 DSH 说的、哪句是我们说的：

| 句子类型 | 长什么样 |
|---|---|
| **DSH 说的** | 给出处，转述不改义；加引号的必须是原文 |
| **我们说的** | 明写「本卷」「本篇」，或直接陈述为推论 |

最容易犯的错是第二种冒充第一种。写之前问：**这句能 grep 到吗？**

## 三、中文不许吃掉英文词

承重词保留英文，理由是可检索：读者拿着 `roster`、`app surface`、`storage domain` 能在 repo 里搜到，拿着中文译名搜不到。

| 场景 | 写法 |
|---|---|
| DSH 有中文译名 | 用中文，首次出现给英文：**组合包**、会话日志、具名组装、一个事实一个家 |
| DSH 没有中文译名 | 保留英文：`app surface`、`roster`、`storage domain`、`scope key`、`waterfall` |
| 代码标识符 | 原样，用反引号包起来 |

判据：**把中文词拿去 repo 搜得到吗？** 搜不到就换成英文原词。

## 四、四类禁写

1. **隐喻当机制**。「皮」「壳」「页表」这类比喻只能出现在解释的下一层，不能当术语。
2. **同一概念两个词**。一页里出现两种叫法，读者会以为是两件事。
3. **没有主语的断言**。「DSH 会拒绝」要说清是哪一步拒绝、看哪条证据。
4. **循环引用**。`A 见 B`、`B 见 A`，两页都不给定义。

## 五、改词之前先问

1. 这个词在 [`GLOSSARY`](./GLOSSARY.md) 里吗？在里面就按表改。
2. 它对应 [`02-judgements`](./02-judgements.md) 的哪一条判断？对应不上，多半不是术语而是修辞。
3. 改完以后，读者能在 repo 里 grep 到吗？
4. 这次改的是发布内容，还是冻结存档？（存档不改，见语料宪章）
