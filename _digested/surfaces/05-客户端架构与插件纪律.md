# 客户端架构与插件纪律

核验入口：[`docs/subsystems/web-client.md`](../../docs/subsystems/web-client.md)、[`packages/client/AGENTS.md`](../../packages/client/AGENTS.md)、[`docs/subsystems/slots.md`](../../docs/subsystems/slots.md)、[`docs/subsystems/client-modules.md`](../../docs/subsystems/client-modules.md)、[`docs/subsystems/conversation.md`](../../docs/subsystems/conversation.md)、[`docs/web-styling.md`](../../docs/web-styling.md)。机检方：[`scripts/verify-client-domain-graph.ts`](../../scripts/verify-client-domain-graph.ts)、[`scripts/verify-client-ui-i18n.ts`](../../scripts/verify-client-ui-i18n.ts)、[`scripts/verify-client-packages.ts`](../../scripts/verify-client-packages.ts)。`packages/client/` 下当前 63 个包目录（0009 独立反查重测），本页每条规则都覆盖它们。（0008 复核注记：`ui-permission` 包已改名 `@deepseek-ai/dsh-client-ui-permission-presets`，目录 `ui-permission-presets/`，slot 行 id 仍是 `ui-permission`；0009 复核注记：`ui-settings-account` 与 `ui-sidebar-terminal` 已登记进 `packages/bundle/web-app/cordis.patch.yml` 的罗盘（`:137`、`:282`）。）

## 一句话

Web Client 是浏览器侧一棵由独立载入的插件组装成的 Cordis 应用（`docs/subsystems/web-client.md:5`）；它复用四块基础设施 —— Client Modules 载插件图、API Gateway 做类型化 Host 通信、Slots 组合 React、Conversation 把 Session 窗口变成目标自有的视图 —— 其余规则都是在这四块之上规定「谁拥有一份状态、谁能 import 谁、一个值走哪条通道」。

## 层与单向依赖链

`docs/subsystems/web-client.md:9-16` 把 Web Client 分成六层，并逐层指定 owner：

| 层 | 主要 owner | 职责 |
|---|---|---|
| Host application | 业务服务与 `packages/api/*-controller` 的 Host 入口 | 拥有权威状态、持久化、mutation 顺序、访问策略与流的生产 |
| Transport 与 API assembly | `client/connection`、`api/gateway`、`api/remotes` | 建立 Client generation、暴露生成的 `ctx.remote` 方法与流、转发选定 Cordis 事件、承载取消与结果 |
| Client models | `api/session-controller/client`、`api/workspace-controller/client` | 维护 Host 状态的 React-free 镜像，解决 stream/unary 竞态，拥有对象身份与订阅，暴露窄命令服务 |
| UI adapters | `client/ui-session`、`client/ui-workspace` | 把 model observable 转成 root 或 Session scope 的标准 slot source，不接管业务状态 |
| Conversation data | `client/ui-conversation` 与 `ui-chat`、`ui-trajectory` 等目标包 | 把标准事件与压缩的历史 Assistant run 组装成各目标自己的快照，并拥有共享 shell 与输入流 |
| Composition 与 rendering | `client/ui-slots`、`client/ui-renderer`、`client/ui-layout` 与 feature UI 包 | 声明扩展位、派生组件 props、把 observable 绑到 React hook、挂载最终树 |

依赖方向是单向的，原文一句话钉死：**Host state → Remote transport → Client model → UI adapter → Conversation or presentation → Slots → React**；用户动作沿回调反向走，回调闭合在注入的 Client service 或生成的 Remote namespace 上（`docs/subsystems/web-client.md:20`）。

```text
Host state ──► Remote transport ──► Client model ──► UI adapter ──► Conversation/presentation ──► Slots ──► React
     ▲                                                                                                        │
     └──────────── 回调闭合在注入的 Client service / 生成的 Remote namespace 上 ◄──────────────────────────────┘
```

同一句还给出硬约束：**presentation component 永远不接收 Cordis `ctx`、transport 对象，或另一个 feature plugin 的实现**（`docs/subsystems/web-client.md:20`）。`ctx` 只属于 apply 世界 —— plugin body 与闭包住它的 inject factory；组件只通过派生的 props share 拿数据与回调，不调触达 ctx 的 hook、不 import service class 去戳它、不读 React context（`packages/client/AGENTS.md:41`）。`docs/subsystems/slots.md:64` 用同样口径复述：组件拿到的 owner 值、store、service 都在 binding site 组装，service 与 model 对象留在 `apply` 闭包里。

跨包边界另有一条：feature plugin 可以用 `import type` 共享声明，但**不得** runtime-import 或 re-export 另一个 feature plugin 的值（`docs/subsystems/web-client.md:91`）；共享运行时值只能放进没有 feature 生命周期的窄静态 owner，如 `client/store`、`ui-primitives` 或 browser-safe utility 包（`docs/subsystems/web-client.md:93`）。Client model 不是第二份业务真相：Host controller 决定耐久状态与 mutation 结果，Client model 只维护最新可用的本地投影并编码「延迟响应与替换基线如何合并」（`docs/subsystems/web-client.md:54`）。

六条数据路径是这六层的具体走法（`docs/subsystems/web-client.md:66-75`；0009 起新增 Background jobs 一条：Host job registry → `job.list`/`job.follow` → `ClientJobs` 名册与输出视图）：durable Session display（Host log → packed Remote `follow`/`page` → `SessionEventLikeEntry` 窗口 → Conversation Context → target snapshot → slot view → React）、transient Session control、Workspace state、scoped interaction、user command。恢复语义也分层：durable journal 每个 generation 用开窗快照替换窗口，control/Workspace 流保留最后值再原子替换，普通转发的通知**不重放**（`docs/subsystems/web-client.md:77-85`）；不存在 monolithic Client `Runtime`、`HostFrame`、`events.mux` 或万能 `resync()`（`docs/subsystems/web-client.md:87`）。

## slot 与 props 纪律

组合只有一个 API：插件只能通过 `ctx.slots.register({ name, children?, store?, inject? }, Component)` 组合 UI，没有独立的 slot 定义调用、没有 whitelist face 对象、没有 face-minting helper；`'root'` 只由 shell 渲染（`packages/client/AGENTS.md:11`、`docs/subsystems/slots.md:19`）。

`children` = 声明 + 授权：组件能渲染的 slot 恰好是 register 调用 `children` 对象的 key（spec 值为 `kind`/`scope`），渲染未声明的 slot 或声明别人已声明的 slot 在 load 时失败；slot 名镜像组合路径 `<domain>.<entry>.<hole>`，例如 `'tool.call.toolview'`（`packages/client/AGENTS.md:12`）。声明 `root` 以外的子 slot 只在拥有并渲染该位置的组件里做，其他包用 `ctx.slots.inject(key, callback)` 等待声明后 `ctx.slots.register()` 贡献；owner 折叠时贡献递归移除，owner 重新挂载时 callback 重跑（`docs/subsystems/slots.md:13`、`docs/subsystems/slots.md:19`）。注册进别人的 slot 时 apply 顺序不受约束，用 `ctx.slots.inject(name, () => ctx.slots.register(...))`，多个贡献要原子安装与回滚时返回 generator（`packages/client/AGENTS.md:141`）。

组件 props 是**五个 share，全部派生**（0009 起 Factory 组件加入第五个）：`PropsRuntime<K>`（SlotMap：owner params + session scope 的 `useSession`/`sessionId` + 全局 `useSessions`/`useWorkspaces`）、`PropsRenderSlots<S>`（children key）、`PropsRenderFactories`（`renderFactorySlot`，Factory children）、`PropsStore<H>`（store factory）、以及 inject face；已由 share 派生的成员不得手写，share 不得在本地重新 `type`（`packages/client/AGENTS.md:13`）。`docs/subsystems/slots.md:62-73` 是这几项加 `PropsLocale<N>` 与 chain `matched` 的来源表。

framework hook 只由框架制造：`useSession`、`useSessions`、`useWorkspaces`、`useStore`、`renderSlot`、`renderFactorySlot` 是 standing seat（Factory 定义另收 `useFactorySlot`），加上 renderer 从 provide 贡献与 inject `hooks` 隔间绑定的 `use<Name>`；业务代码不得把 hook 或 selector 当 prop 值传，只传 plain data 与 callback（`packages/client/AGENTS.md:14`）。`docs/subsystems/slots.md:79-95` 列全了按 scope 发放的标准 props（`usePanelInfo`、`useProjection`、`useConversation`、`useInput`、`useChat`、`useTrajectory` 等），`:95` 说明 `useStore` 与本地化 `t` 是 registration 派生而非全局标准 props，`:97` 规定标准集只能由 framework 与 domain adapter 经 `provideRoot()`/`uiSession.provide()` 扩充，feature 组件不得自己造 hook prop 或为 entry 私有数据加全局标准 prop。

活数据只有三条通道：parent 已知 → renderSlot 站点上的 owner props；只有组件自己知道 → local state；跨 entry 共享或跨 remount 存活 → register 时声明的 store；派生数据是对 framework-hook 数据的纯函数（`useMemo`），不是自己的订阅（`packages/client/AGENTS.md:15`）。读共享状态用 `props.useStore`，写用 `props.actions.*`，声明的 actions 就是完整 mutation API；store 写成导出的 `createXXXStore()` factory，模块级 handle 是被禁止的 de-facto singleton，同一个 handle 在 `apply` 内传给多个 register 共享；生产代码不得在 `apply` 之外调 factory 或 `.create()`，测试可以（这是指定的零机械路径）（`packages/client/AGENTS.md:16`）。

inject 从 apply 闭包自己的 ctx 返回 **plain data 与 callback**：不得手造 hook、不得产 ReactNode、不得给整个 service 对象；registrant 私有的响应式事实走保留的 `hooks` 隔间（renderer 把 `hooks: { status }` 转成 `useStatus(selector)` prop，组件拿不到 source 本身），插件只能用 `inject` 声明命名的依赖，没有更宽的 ctx 可伸手（`packages/client/AGENTS.md:17`、`docs/subsystems/slots.md:101-105`）。owner props、registration `inject`、slot-level `inject`、声明 store 各有适用面：一次渲染已知道的值走 owner props，一个 entry 的回调与私有 observable 走 registration inject，slot owner 控制的 capability 走 slot-level inject，跨 entry 或跨 remount 的可变视图状态走 store，React node 一律走子 slot（`docs/subsystems/slots.md:107`）。

配套的读纪律：render 读到的一切可能脱离 React 变化的值都必须经 framework hook 进来，render code 订阅、event-handler code 可读 live snapshot（`packages/client/AGENTS.md:24`）；业务组件里没有任何订阅机械 —— 不许 `useSyncExternalStore`、不许手接 subscribe、不许把外部快照镜像进 local state 或第二个 store（`packages/client/AGENTS.md:25`）；需求按「framework hook → 声明 store（`useStore`/`actions`）→ inject 回调 → 其他一律算新框架扩展点并需主线程裁决」这条 data-access ladder 解决（`packages/client/AGENTS.md:26`）。UI 域之间只共享 JSON-compatible 数据与回调，例外只有瞬态文件读与 document preview 的 `Uint8Array`（发布出去即只读借用，Worker 传输前复制，绝不进 layout 或 Session JSON），`hooks` 隔间是放裸 observable 的唯一位置，ReactNode 走 slot（`packages/client/AGENTS.md:27`）。observable source 保持两层身份稳定 —— source 对象本身（hook binding 按 source 缓存）与两次变化之间的 snapshot（`getSnapshot` 在事实未动前返回同一引用）（`packages/client/AGENTS.md:28`）；重建了已发布值的人必须在同一步经同一 source 重新发布，可能在消费者存在之后才跑的注册路径也要在注册时通知活消费者（`packages/client/AGENTS.md:29`）。完整层级树见 `docs/subsystems/slots.md:109-191`。

## export 纪律（`/client` 入口）

UI 插件包的 `/client` 入口是它的公开浏览器 API，不是便利 barrel（`packages/client/AGENTS.md:33`）。三条包级规则：插件导出的值不超出 cordis 载入所需 —— `apply`/`inject`（有 `Config` 时加 `Config`），加上被组件 type-only 消费的 store factory（`ReturnType<typeof createXXXStore>`），共享类型（owner data、注入值、合成 prop alias）也可导出，实现组件、纯 helper、常量与 store handle 留在包内，**新增任何值导出都要用户签字**而不是「有消费者就加」（`packages/client/AGENTS.md:35`）；同包测试直接 import 内部（包测试写相对 `../src/client/xxx.ts`，spec 在包外时用 `./src/*` 子路径），**绝不为让测试编译而放宽公开 API**（`packages/client/AGENTS.md:36`）；feature plugin 不得 runtime-import 或 re-export 另一个 feature plugin 的值，也不得为了拿到它们而声明 `dsh.client.external`，两条路都不通就停下升级，不许加个导出给自己解围（`packages/client/AGENTS.md:37`）。

## 模块身份：baseline、`external` 与激活顺序

客户端 baseline 集中在 [`packages/client/web/src/platform.ts`](../../packages/client/web/src/platform.ts)：`PLATFORM_MODULES` 命名 shell 播种的 React、Cordis 与静态 Client 库，`PRELOADED_CLIENT_EXTERNALS` 留给必须在 shell boot 前到达其 factory 的动态行、当前为空（`packages/client/AGENTS.md:75`）。实际清单是 `react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store`、`@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-ui-primitives`、`@deepseek-ai/dsh-client-ui-dockkit`（`packages/client/web/src/platform.ts:8-13`、`packages/client/web/src/platform.ts:16-18`）。

baseline external 对每个动态 bundle 都是隐式的：**不要**在包 manifest 里重复 React、Cordis、`client/store`、`ui-primitives`、`ui-slots`、`ui-dockkit`（`packages/client/AGENTS.md:78`）；`verify-client-packages` 把重复 baseline 的条目直接判 fail 并要求删掉显式声明（`scripts/verify-client-packages.ts:327-334`）。

`dsh.client.external` 不是 feature plugin 的依赖机制，只有 infrastructure、transport 或 generated assembly 才能加一个包级非 baseline 值请求，且必须写精确 import specifier，只有尾部 `/client` 会把包行别名（`packages/client/AGENTS.md:79`）；gate 对 `packages/client/` 下的包请求某个运行时 external 直接拒绝，提示「只共享类型或调注入的 Cordis service」（`scripts/verify-client-packages.ts:341-348`）。沉默即私有副本：普通第三方实现库可以各自打包，只经 `import type` 到达的值被擦除、不产生请求（`packages/client/AGENTS.md:80`）。

一个请求只有两个可能供给方：动态包供给自己的行，或 `PLATFORM_MODULES` 供给一个精确的静态表 key；不存在 `dsh.client.provide` 别名协议（`packages/client/AGENTS.md:81`）。gate 会逐条查 baseline 重复、空值、重复值、自己的行、无 supplier、无生产源码 import 的过期声明，并拒绝同步请求环（`scripts/verify-client-packages.ts:324-386`），环的判定沿 `external` 边做 DFS 并打印 `synchronous dsh.client.external cycle` 链（`scripts/verify-client-packages.ts:389-425`、`scripts/verify-client-packages.ts:434-440`）。0009 起另有一条：包内动态 chunk 必须自包含，源码用 `import()`、preset 发 `require.async(...)`，entry/chunk 不得保留同步相对 `require("./client*.js")`（`packages/client/AGENTS.md:83`）。环被拒绝的根因是 module 请求是同步的：seam 是 `loader.internal = modules`，cordis 经 `EntryTree.import` 到达插件代码，所以每个 module 请求都必须在 cordis 能把它排到激活之前就可满足；modules node 半边按拓扑序发行，`ClientModuleSystem.import`/`prefetch` 递归注册动态 provider factory 后才让消费者物化（`packages/client/AGENTS.md:95`）。

**模块顺序与 Cordis 激活不是一回事**，两者不可互换（`packages/client/AGENTS.md:85`、`packages/client/AGENTS.md:87-93`）：Cordis service `inject` 的单位是 service 名、时机是 runtime（fiber 等待）、不满足则 PENDING 无超时、任何提供该 service 的插件都可满足且可替换、允许成环；module graph `external` 的单位是 module specifier、时机是物化（交给 factory 的 `require` 是同步的、不能等）、不满足当场抛错、只能由唯一 module 身份满足且不可替换、成环被拒。Browser boot 里这也是原文口径：Cordis service injection 决定激活，module graph 顺序只决定同步 import 能否物化（`docs/subsystems/web-client.md:26`、`docs/subsystems/client-modules.md:64-67`）；`immediately` 只标 stage-one 预取屏障，`inject` 是信息性的包名边（preflight 展示、HMR diff），既不排 entry 激活也不排 apply 顺序（`packages/client/AGENTS.md:144`）。两个反例要点：`packages/client/web` 不是 Loader entry，它的静态 import 播种 `PLATFORM_MODULES`（`packages/client/AGENTS.md:99`）；bundle route 是 `GET/HEAD /plugins/??<package-a>/client.js,<package-b>/client.js&rev=<rev>`，起始 URL 上限 3 KiB，未知/改动过的资源列表、缺失或过期 rev 一律 404 而不是回落到 SPA 的 HTML（`docs/subsystems/client-modules.md:88`）。

缓存修订也有一条纪律：`rebuilt(id)` 是变更后的 bundle 内容进入 graph 的**唯一入口**，它把 bundle 与当前 source map 一起重哈希，只有 rev 真变了才重组 graph 并通知；`onGraphChanged` 是 pull 模型（`docs/subsystems/client-modules.md:106`）。

## 层间的不可谈判项

三条 layering red line 先定层：数据对象层 React-free —— `client/connection` 拥有 transport generation，`api/session-controller/client` 拥有 `ClientSessions` → `SessionManager` → `Session`，`api/workspace-controller/client` 拥有 Workspace 状态，`client/store` 拥有 snapshot-store 引擎（`defineStore`、`createSnapshotStore`、`shallowEqual`），store 产物是没有 hook 成员的裸 observable source（`packages/client/AGENTS.md:47`）；渲染机械（`ui-renderer`，动态插件）承担全部 ctx-to-React 集成 —— slot renderer/outlet、`SessionProvider`、uSES adapter，每个 hook 在 binding site 由裸 source 合成，生产业务代码不带 ui-renderer 值依赖（`packages/client/AGENTS.md:48`）；presentation component（各插件包 `src/client/`，pure props）是可整批重写的耗材，业务逻辑不得渗进去（`packages/client/AGENTS.md:49`）。

跨层的四条不可谈判（`packages/client/AGENTS.md:50-54`）：**业务数据住在对象层，永远不住 store** —— entry 声明的 store 只装共享的查看/交互状态（selection、draft、panel 宽度），sessions、frames、connections 留在对象层；**`rpcId` 严格双向** —— initiator mint、responder echo，mint 只发生在 Connection；**notifier 发布纪律** —— `notifyNow` 只是用户手势的直接回显，结构性更新用 microtask 批处理的 `markDirty`，可见的流式 chunk 用累积的 `markFrameDirty`；**web 层是纯展示** —— 只是「怎么画」的东西不进 session log，tool card 在 Client 从原始 call/result 事件与持久化结果元数据派生，进程内控制状态用各自的 snapshot 与 frame，未知或畸形 tool 数据回落到通用形态，而任何新的 **model-visible** 输入仍按仓库级规则需要一条 session event。

## Conversation Node 纪律

一个 Chat 业务特性注册**一个** `ConversationNodeDefinition` 加它的 keyed `conversation.chat.node` renderer；不得把该特性的事件 switch 或 fold 加进 `Session`、`SessionManager` 或某个中央 built-in dispatcher（`packages/client/AGENTS.md:106`）。`match(event)` 只读当前 `SessionEventLike`；多输入 Context 里的每个标量事件或 packed Assistant run 都要携带或独立派生出**同一个稳定业务 id**；`update` 把一次 Match 折进 State，并且必须能按逻辑 log `seq` 确定性地重放；packed 行是 update-only；消费 Assistant delta 的 Definition 必须同时实现标量与 `chunkrow/*` 两个分支而不展开成员（`packages/client/AGENTS.md:102`）。append 热路径与 renderer **绝不扫描**完整事件窗口、Contexts 或 Chat Nodes：累积靠 State，同一 Turn/Step 的事实经 `buildLocationData()` 发布，消费侧只用最终 Node 数据或受限的 Location hook（`packages/client/AGENTS.md:103`）。

引擎侧的对应事实：`ui-conversation` 每 Session 一个 identity-stable binding、一个 `ConversationNodeAssembler`，对每个已注册 Definition 全量施加并给每个已注册 view target 发布独立 source（`docs/subsystems/conversation.md:11`）；`match` 是身份提取器而不是 fold，只收当前事件并返回 Definition 局部 id 与生命周期 role（`docs/subsystems/conversation.md:246`）；`target` 与 `buildViewNode(context)` 必须同时出现，`context.key` 是 React 面身份，Node 发布后必须持续返回同一 key，离开可见流时用 `visibility: 'hidden'` 而不是 `null` 撤回（`docs/subsystems/conversation.md:250`）。

重放与热路径的边界由引擎给出：window 更新有三条路径 —— 开窗/重同步/补洞时 replace、prepend 一页旧历史、append 一条 live 事件，append 只对匹配到的 Context 做恒定时间查表（`docs/subsystems/conversation.md:262-266`）；因此有 D 个 Definition 时，一条标量事件或 packed run 只做 D 次当前输入匹配加匹配后的恒定时间 key 查找，Definition 代码必须保住这条性质（`docs/subsystems/conversation.md:268`）。Live Assistant delta 以 Client-only 的 `assistant/live-chunk` 到达（0.1.7 线起 transient 记录也可作 `start`，旧「update-only」限制已删），重连基线把活跃的进程内 compact stream 展开成同样的 transient 事件，而持久的 `assistant/message`/`assistant/attempt` 内嵌完整 compact stream 供历史重放；同一 Definition 在同一个 `match()`/`update()` 里同时处理 live chunk 与 durable settlement（`docs/subsystems/conversation.md:72`）。需要更早同类 State 时用 `start` 收到的 `ConversationContextReader` 调 `reader.previous<State>(kind)`，而不是接整个 Context 集合或扫描事件（`docs/subsystems/conversation.md:254`）。`publication` 控制 State 变化何时物化：结构性/终态用 `immediate`，高频可见 delta 用 `animation-frame`，只喂后续发布用 `none`（`docs/subsystems/conversation.md:270`）。

## 包内目录制度

一个 UI feature = 一个 plugin package（`src/client/` 浏览器半边）；多域包在「其代码以后可能拆成独立包」的地方拆 —— `ui-conversation` 是范例：`contract/` 是**唯一**共享 API，各 domain 目录**永不 import 兄弟 domain**，`apply.ts` 是唯一的跨域组装点；注册一律在 `apply` 里经 `slots.register` 完成，绝不用模块级副作用（`packages/client/AGENTS.md:107`）。

`scripts/verify-client-domain-graph.ts` 把这条落成可机检的三层模型：第 0 层 `contract/` 共享契约 API，第 1 层 `<domain>/` 与 service 实现，第 2 层 `apply.ts`/`index.ts` 组装点与 re-export 壳（`scripts/verify-client-domain-graph.ts:8-12`）；`CONTRACT_DIRS` 只认 `contract`（`scripts/verify-client-domain-graph.ts:24`），`ASSEMBLY_FILES` 是 `apply.ts`/`index.ts`/`index.tsx`（`scripts/verify-client-domain-graph.ts:26`）；兄弟 domain 间的 import 会以「route shared API through contract/」报 fail，顶层非组装文件 import 任何 domain 也报 fail（`scripts/verify-client-domain-graph.ts:73-76`）。

## 依赖声明

npm section 描述的是安装与开发关系，每个 build face 各自决定自己的产物里放什么（`packages/client/AGENTS.md:60`）：`verify-package-dependencies` 查并修这些规则，`verify-client-packages` 管 Client 载入与 module 请求（`packages/client/AGENTS.md:60`）。七条：每个 client 包在 `peerDependencies` 与 `devDependencies` 里保持匹配的 Cordis（静态包也算，因为它们的 Node 半边参与同一 Cordis 插件契约）（`packages/client/AGENTS.md:62`）；`packages/client/` 下的包永远被覆盖，`dsh.client` 用来标记该目录之外的 Client/Host 包，被覆盖包的 Host 入口会被 scan，而只有 `./client` export 并不触发依赖策略（`packages/client/AGENTS.md:62`）；browser 与 type 关系是 development-only —— workspace 与第三方 Client import、type-only import、module augmentation、TypeScript project reference、`dsh.client.inject`、metadata-only peer 只能进 `devDependencies`，不出现在 import 里的配置项登记在 dependency policy，Node companion 值 import 走下面的 Host 规则（`packages/client/AGENTS.md:64`）；Host 值 import 需要分类过的 export —— 从 Host 入口到达的 workspace 值，只有当其精确 module specifier 与 runtime export 出现在 `safeHostDependencyExports` 时才进 `dependencies`，身份或 module state 必须共享的 export 进 `peerRequiredHostExports` 且整条包边保持 peer+dev 匹配，verifier 在 `--fix` 写 manifest 之前先拒绝未分类 export（`packages/client/AGENTS.md:65`）；只有 Host runtime 库需要安装依赖，browser-only 第三方实现无论在 `lib/client.js` 里内联还是作为静态 browser 库的裸 import 都进 `devDependencies`（`packages/client/AGENTS.md:66`）；Browser 与 Node build face 独立声明 externality —— 动态浏览器半边用 baseline 加 `dsh.client.external`，静态链接 face externalize 每个裸 specifier，Node face externalize 其 production dependencies，**把一个名字在 npm section 之间搬动不得悄悄改变 bundle 内容**（`packages/client/AGENTS.md:67`、[`packages/client/tsdown.client.ts`](../../packages/client/tsdown.client.ts)）；发布的 payload 要闭合，每个相对 runtime import 与产出的 asset 都必须被 `files` 覆盖（`packages/client/AGENTS.md:68`）。

## 样式与本地化

`docs/web-styling.md` 是样式权威（`packages/client/AGENTS.md:111`）：`ui-theme` 拥有 `--dsw-*` 静态刻度、语义 alias、typography、motion、gradient、shadow、scrollbar 与明暗偏好，`ui-layout` 把解析后的 theme snapshot 应用到 document，feature 包只消费语义 alias 且不得定义第二套全局主题（`docs/web-styling.md:9`）。全局样式表住在 `ui-theme/src/styles/`，组件样式以 CSS Modules 与其组件同处；组件可以在值属于该组件布局/呈现契约时定义局部 custom property，但共享颜色、typography、elevation、motion 属于 theme 包（`docs/web-styling.md:11`；0009 起另要求菜单类控件用 `Menu`/`MenuSurface`，显式列名的 schedule 容器除外——`packages/client/AGENTS.md:113`）。feature 组件用 `--dsw-alias-*` 语义 token，不复制静态 palette 值、不写字面颜色，不引组件库、不上 Tailwind（`docs/web-styling.md:17-18`、`packages/client/AGENTS.md:111`）。

本地化：每个产品可见字符串 —— 文本、可访问名、tooltip、placeholder、状态/单位 formatter、primitive chrome —— 都住在 typed locale dictionary，经标准 `t` seat 或已本地化的 prop 到达组件；Cordis-free primitive 要求完整的 label props 且自身不持有 fallback copy；user/model/wire 数据与 code token 原样保留；内部匹配用 discriminant 或稳定 id，绝不用本地化文本（`packages/client/AGENTS.md:113`）。gate `pnpm run verify-client-ui-i18n` 强制 source 归属（`packages/client/AGENTS.md:116`）：只有 locale 字典源文件可以拥有译文，判定上 `locale.ts`、`locales.ts` 或路径含 `/locales/` 的文件被视为 locale owner 而跳过（`scripts/verify-client-ui-i18n.ts:70-75`），检查覆盖 JSX 文本与承载 copy 的属性，并在发现文件数低于 450 时直接抛错以防 discovery 被收窄（`scripts/verify-client-ui-i18n.ts:15`、`scripts/verify-client-ui-i18n.ts:338-345`）。

## 测试阶梯

GUI 测试的三层结构与 lane map 由 GUI testing system note 定案，仓库级策略在 `docs/testing.md`（`packages/client/AGENTS.md:120`）。阶梯按改动面选最窄一级（`packages/client/AGENTS.md:132-134`）：**每个 GUI 代码改动**跑 `pnpm run test:gui`（秒级，无浏览器无服务器，是内循环，可以像 typecheck 一样随便跑）；**任何可能改变组装后浏览器或可见 conversation/UI 输出的改动**（client 组件或文案、`apps/web`、Vite、`dsh-host-webserver`、connection/handler/SSE）额外跑 `DSH_SNAPSHOT=replay pnpm run test:web`，它会重建 frontend dist 再跑 browser smoke 对（无 `DEEPSEEK_API_KEY` 时 real-host case 自跳过）加 keyless 重放 e2e；`DSH_SNAPSHOT=refresh` 只在确认输出变化是有意的之后用，`DSH_SNAPSHOT=record` 带 key 重录 fixture；**PR 之前**用 dsh-pre-push-checks 选窄检查，仓库没有全量 pre-push 聚合。

覆盖率与环境的硬规定：Client source 包在 per-file 100% coverage gate 内（`pnpm run test:coverage`），真的不可达的防御分支用 `/* v8 ignore -- <reason> */` 写真实理由，绝不用裸 ignore（`packages/client/AGENTS.md:123`）；组件 spec 用真实 props 或驱动的 fixture runtime 渲染并断言用户可见行为，而不是 class 名、hook 内部或 render 次数（`packages/client/AGENTS.md:124`）；jsdom 环境来自 spec 第一行的 per-file `// @vitest-environment jsdom` pragma，共享 config 保持 node-env（`packages/client/AGENTS.md:125`）；每一级只断言自己那层 —— 数据层语义归 runtime 与 host 套件，组件 spec 覆盖呈现行为（`packages/client/AGENTS.md:126`）。若 `test:gui` 在你没碰的代码上红，既不静默修也不忽略，写进 handoff 让它落进下一轮 PR 窗口（`packages/client/AGENTS.md:136`）。

## 新包必须补的三处注册面

起一个 `packages/client/<name>` 插件包时，**三处注册面缺一不可，缺任一处会在不同的、更晚的点失败**（`packages/client/AGENTS.md:143`）：一是 [`tsconfig.client.json`](../../tsconfig.client.json) 聚合里的 `references` 条目（该数组在 `tsconfig.client.json:52`，示例条目见 `tsconfig.client.json:58`）；二是 [`packages/bundle/web-app/cordis.patch.yml`](../../packages/bundle/web-app/cordis.patch.yml) 里的一条 `dsh.client` 行（browser roster 段落见 `packages/bundle/web-app/cordis.patch.yml:40-43`）；三是 [`packages/bundle/web-app/package.json`](../../packages/bundle/web-app/package.json) 的依赖（既有条目示例见 `packages/bundle/web-app/package.json:112`）。第三处的原因写得明确：profile boot 通过 healed 的 `$DSH_HOME/profiles/node_modules` fallback 解析裸行名，该 fallback 镜像 app 与每个 bundle 声明的依赖，所以**一个没有任何 manifest 声明的行会 import 失败**（`packages/client/AGENTS.md:143`）。

配套的 manifest 与流程语义：`dsh.client` 声明里 `platform: 'web'` 恒定，且该声明要求包有 `./client` export（没有时 scan 直接抛错）；`immediately: true` 只给 stage-one 预取的 infrastructure 行；`inject` 列的是包名依赖边，仅供 preflight 展示与 HMR diff，**不**排 entry 激活或 apply 顺序，激活顺序只由 Cordis fiber 对 service 的 inject 等待决定（`packages/client/AGENTS.md:144`）。新包骨架还包括 `package.json`（包名 `@deepseek-ai/dsh-client-<name>`、exports `.`/`./client`/`./src/*`/`./package.json`、可选 `./invariant`、`dsh.client` manifest、`files`）、`tsconfig.json`、`tsdown.config.ts` 的 `clientBundle(id, ['lib/types/index.js'])`、空的 node 半边 `src/index.ts`、使用 CSS Modules 时的 `src/css-modules.d.ts`，以及带 Model Experience 段的 `README.md`（`packages/client/AGENTS.md:142`）。要在本地 `dsh web` 服务器上验证，先 `pnpm --filter <pkg> bundle` 重建 bundle，因为 registry 服务的是 `lib/client.js` 而不是源码（`packages/client/AGENTS.md:146`）。

## 构建期浏览器环境

Client 业务代码可以静态读 `process.env.DSH_CLIENT_*`，每个被引用的值都是公开产物内容（`packages/client/AGENTS.md:71`）。共享的 build-environment helper 让 Vite 与动态 tsdown bundle 拿到同一批 build-process 值，未设置的变量解析成 `undefined`，且**不暴露**动态查找或枚举（`packages/client/AGENTS.md:71`）：前缀常量是 `DSH_CLIENT_`（`scripts/client-build-environment.ts:14`），bundler 替换把 `process.env` 兜底成 `{}` 并对每个精确的 `process.env.<name>` 注入字面量，因此未设置的静态读取求值为 `undefined` 而不需要浏览器 `process` 全局（`scripts/client-build-environment.ts:254-271`）。一次完整 root build 记录确切的公开值与全部 client 产物的 digest，release 与 built-artifact 消费者拒绝缺失或过期的记录（`packages/client/AGENTS.md:71`）：记录落在 `.dsh-build/client-build-environment.json`（`scripts/client-build-environment.ts:32`），digest 覆盖 `apps/web/dist/**/*` 与各包的 `lib/client.js`/`lib/client.js.map`（`scripts/client-build-environment.ts:35-38`），按排序后的路径与内容算 SHA-256 与文件数（`scripts/client-build-environment.ts:338-345`），读取时若 count 或 digest 与当前产物不符即抛错要求重跑完整 build（`scripts/client-build-environment.ts:365-375`）。需要在 build 之后仍能改变的选项走 runtime configuration，而不是 build-time 变量（`packages/client/AGENTS.md:71`）。
