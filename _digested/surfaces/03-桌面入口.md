# 桌面入口：Electron 壳 + 私有 host

核验入口：[`apps/desktop/README.md`](../../apps/desktop/README.md)、[`apps/desktop-host/src/index.ts`](../../apps/desktop-host/src/index.ts)（0.1.7 线起 desktop profile 由 `loadProfileDirectory` 在安装期组装，仓库内不再有 `desktop.cordis.patch.yml`；surfaces 深读将复核这一面）。决策记录：`.agents/notes/implemented/architecture/2026-08-25-electron-desktop-packaging-and-updates.md`。

桌面是第 5 个产品应用面，也是唯一不经 `dsh` CLI 启动的那个。它用 Electron 壳套住同一份 dsh Web UI：壳起一个私有 host 子进程，host 用 `@deepseek-ai/dsh-app-boot` 的 `boot()` 组合并启动 `desktop` profile，渲染端拿到的仍是同一个 Web client。上游文档把它单列在 `docs/architecture.md:51-55` 的 `## Desktop application`，不在 `:43-49` 的 `## Application launch` 里。

## 三个否定

| 不是 | 证据 |
|------|------|
| 不是 `dsh --profile desktop` | `apps/cli/src/args.ts:68-71` 的 `rejectElectronProfile()` 用 `profile.toLowerCase() === 'desktop'` 拦下大小写变体，`:70` 直接 `program.error`（`profile "desktop" is managed exclusively by the Electron application`）。CLI 既不能 boot 也不能改这个 profile |
| 不是 spawn `dsh --profile web` | 壳 spawn 的是私有 host 包入口 `node_modules/@deepseek-ai/dsh-desktop-host/lib/index.js`，只传 projectDir（开发态另加 `--allow-linked-profile`）：`apps/desktop/src/host-process.ts:99-113`，`:112` 的 `stdio` 是 `['ignore', 'pipe', 'pipe', 'pipe', 'pipe', 'ipc']` |
| 不是把 Web app 打进壳 | [`apps/desktop/electron-builder.config.mjs`](../../apps/desktop/electron-builder.config.mjs) 的 `files`（`:54-59`）只收壳自己的 `lib/*.js`、`lib/*.cjs`、`renderer/**/*`、`package.json`；Node 运行时与离线 seed 走 `:60-63` 的 `extraResources`，Web 前端产物由 host 从安装好的 profile 里 `require.resolve` |

`apps/desktop` 与 `apps/desktop-host` 都是 `private: true` 且**没有** `bin`（`apps/desktop/package.json:2`、`:5`、`:8`；`apps/desktop-host/package.json:2`、`:5`）；`apps/desktop-host` 同样不发布 npm 产物，`files` 只列 `lib/index.js` 与 `config/desktop.cordis.patch.yml`（`apps/desktop-host/package.json:9-12`），由打包流程本地 pack 进 seed。

## 复用面

桌面换掉的是进程与传输，不是产品组合：

- 同一套 bundle：`apps/desktop/src/project-manager.ts:105` 的 `DESKTOP_PROFILE_BUNDLES = ['@deepseek-ai/dsh-base', '@deepseek-ai/dsh-web-app']`。
- 同一份前端产物：host 用 `require.resolve('@deepseek-ai/dsh-web-frontend/dist/index.html')` 定位（`apps/desktop-host/src/index.ts:187`），该包由 `apps/web/package.json` 定义。
- 同一套 HTTP 处理：`connection.createSharedFetchHandler('/api')`（`apps/desktop-host/src/index.ts:305`）。
- 同一套 client 模块分发：`/plugins/` 前缀交给 `ctx.clientModules.fetchBundle`（同文件 `:200`）。

差异集中在 overlay `apps/desktop-host/config/desktop.cordis.patch.yml`：禁用 `web-startup` / `webserver` / `web-runtime` / `client-hmr` / `open-in-app` / `ui-open-in-app` / `directory-picker` 七行，给 `connection` 注入 `credentials`，并插入两个 native 目录选择器包（`directory-picker-native`、`ui-directory-picker-native`）。因为 `webserver` 不在树里，Web 的「Open In...」在桌面被禁用（`apps/desktop/README.md:177`）。

桌面复用 `packages/boot/app-boot` 的 profile 解析，但**拒绝**它的 flat module fallback：`.agents/notes/implemented/architecture/2026-08-25-electron-desktop-packaging-and-updates.md` 要求生产启动不得解析到 desktop profile 之外的 bundle，落点在 `apps/desktop-host/src/index.ts:156-158` —— 逐层检查 `isProjectPath(projectDir, layer.packageDir)`，否则抛 `resolved outside the desktop profile`（`packages/boot/app-boot/src/profile.ts:19`、`:152`、`:542` 描述的那条 `$DSH_HOME/profiles/node_modules` 回退对桌面不适用）。

## 传输：无端口、`dsh-app://`、分帧字节管道

```
Electron 主进程 ──dsh-app:// / fetch──→ 私有 host 子进程（无监听端口）
   请求帧 → fd3（DESKTOP_REQUEST_PIPE_FD）
   响应帧 ← fd4（DESKTOP_RESPONSE_PIPE_FD）
   生命周期 ↔ Node IPC（ready / fatal / shutdown）
```

协议常量在 `apps/desktop-host/src/wire.ts`：`DESKTOP_HOST_PROTOCOL_VERSION = 3`（`:4`，壳与 host 在 `ready` 事件里对齐）、`DESKTOP_REQUEST_PIPE_FD = 3`（`:7`）、`DESKTOP_RESPONSE_PIPE_FD = 4`（`:10`）、`DESKTOP_PIPE_CHUNK_BYTES = 64 * 1024`（`:13`）。帧带 magic、类型、`streamId` 与长度头，控制帧另有 1 MiB 上限；响应体按 64 KiB 切片。`dsh-app://` 由 `apps/desktop/src/main.ts:30-40` 的 `protocol.registerSchemesAsPrivileged([...])` 注册（scheme 常量在 `:23`），所以渲染端只走自定义协议，不落 HTTP。

渲染端的接缝是注入的全局对象：host 把 `DESKTOP_TRANSPORT_SCRIPT`（`apps/desktop-host/src/index.ts:99-120`）作为 head 脚本注入 `index.html`，它提供 `globalThis.__DSH_TRANSPORT__`，其中 `ownsHost: true`，`openStream(endpoint, payload, signal)` 对 `/.dsh/remote-stream` 发 POST 并把响应体当 NDJSON 逐行 `JSON.parse` 后 yield（路径常量 `:97`）。

客户端 `connection` 插件读这个全局对象：`packages/client/connection/src/client/index.ts:186` 取 `__DSH_TRANSPORT__`，`:188` 把它交给 `createWebConnectionRpc(transport?.fetch, transport?.openStream)`。于是 Gateway 走了旁路：`packages/api/gateway/src/client/index.ts:162` 只在 `connection.rpc.open === undefined` 时启动 WebSocket mux，`:227` 优先用 `connection.rpc.open?.('/api', endpoint, payload, signal)`，只有它为 `undefined` 才回落到 mux。桌面因此不开 `/api/remote.mux`，WebSocket 那条路整条空转。

## profile、seed 与版本

`$DSH_HOME/profiles/desktop` 被 Electron 独占（`apps/desktop/src/paths.ts:34`），同目录下另有 `$DSH_HOME/desktop/{staging,rollback,pnpm/store,...}` 由壳管理。CLI profile 与桌面共享 `$DSH_HOME` 下的产品数据，但**不**共享可执行包、插件激活、lockfile 或 `node_modules`。

发布身份是「一个组合」：Electron 与 `@deepseek-ai/dsh` 恒为同一精确版本，升级 dsh 就是一次桌面发布。签名的应用自带第一方离线 seed，启动时用捆绑的 pnpm 把该版本装进可写 profile，同时保留旧 profile 里的桌面插件精确版本。安装是串行事务：迁移中断日志 → 校验 seed 清单 → 装到 staging → 启停一次 staged backend 做健康检查 → 激活（旧 profile 移到 rollback）。这些契约由 `apps/desktop/README.md` 与上面那篇 note 承载；`apps/desktop-host` 自身没有 README，运行时契约只由这两个来源定义。

发布目标是 macOS arm64 / x64 与 Windows x64，Linux 不是受支持的桌面发布目标（`apps/desktop/README.md:99`）。开发用 `pnpm run dev:desktop`（根 `package.json:28`，说明在 `apps/desktop/README.md:56-62`），它在 `apps/desktop/.desktop-build/` 下投影一个一次性的 desktop npm 项目，默认 Harness home 也在那里。

## 阅读顺序

1. [`apps/desktop/README.md`](../../apps/desktop/README.md)：Key technical decisions 表回答「为什么这么设计」，Installation ownership 与 Seed installation 回答「profile 归谁、怎么装」。

5. `apps/desktop-host/config/desktop.cordis.patch.yml`：相对 web-app 的增删行。
