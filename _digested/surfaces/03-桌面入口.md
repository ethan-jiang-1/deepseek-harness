# 桌面入口：Electron 壳 + 私有 Host

产品源码基线：`46a7f68b09`（`dsh-v0.1.7-rc.1`）。

核验入口：[`apps/desktop/README.md`](../../apps/desktop/README.md)、[`apps/desktop-host/src/index.ts`](../../apps/desktop-host/src/index.ts)。0.1.7 线 desktop-host 重构为 `loadProfileDirectory` + 共享 `runProfile`：仓库内不再有 `desktop.cordis.patch.yml` 覆盖层，也不再有 `wire.ts` 分帧协议。决策记录：[`.agents/notes/implemented/architecture/2026-09-10-desktop-web-wrapper.md`](../../.agents/notes/implemented/architecture/2026-09-10-desktop-web-wrapper.md)（本页结构的直接来源）、[`.agents/notes/implemented/architecture/2026-09-11-desktop-electron-node-runtime.md`](../../.agents/notes/implemented/architecture/2026-09-11-desktop-electron-node-runtime.md)。

桌面是第 5 个产品应用面，也是唯一不经 `dsh` CLI 启动的那个。它用 Electron 壳套住同一份 dsh Web UI：壳起一个 Electron Node 模式的私有 host 子进程，host 用 `@deepseek-ai/dsh-app-boot` 的 `loadProfileDirectory` 装载 `desktop` profile、经共享 `runProfile` 启动完整 web 应用（webserver 监听 `127.0.0.1:19387`），渲染端从 `dsh-app://app/` 拿到的是同一个 Web client，页面内的应用请求由壳转发给这个已认证 Host。上游文档把它单列在 `docs/architecture.md:51-55` 的 `## Desktop application`，不在 `:43-49` 的 `## Application launch` 里；`:55` 原文「Desktop defaults to port `19387`; profile configuration can override it.」

## 复用面

桌面换掉的是进程与传输载体，不是产品组合：

- 同一套 bundle：desktop profile 的 `dsh.profile.bundles` 就是 `PROFILE_TEMPLATES.web` 的两个 bundle（`apps/desktop/src/project-manager.ts:32`，`initProfile` 写入 `:174-175`）；用户插件经共享 Web Plugin Manager 追加（`apps/desktop/README.md:78`）。
- 同一份前端产物：壳把 `resources.dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist` 的静态文件挂在 `dsh-app://app` 下发出，并给 index 注入 `__DSH_BOOT_READY__` 等待 Host 的启动注入（`apps/desktop/src/main.ts:566-568`；`apps/desktop/src/web-document.ts:18-40`）。
- 同一套 HTTP 处理：`connection.createSharedFetchHandler('/api')`（`packages/client/connection/src/index.ts:144`），经 webserver 的 `/api` 路由服务。
- 同一套 client 模块分发：`/plugins/` 前缀由 host 的 modules 行经 webserver 发出，壳转发并改 `no-store`（`apps/desktop/src/web-document.ts:77-99`）。

与 web 的可见差异只有两条壳侧适配：目录选择共用 `directory-picker` auto 行，native 面的对话框由壳的窗口 IPC 承担（`apps/desktop/src/directory-picker.ts:10-30`）；沙箱 HTTP(S) Browser 侧栏行**只在 desktop 启用**（`packages/bundle/web-app/cordis.patch.yml:253-254` 的 `disabled: !!js "ctx.get('profileContext')?.name !== 'desktop'"`）。~~旧基线 disable `web-startup` / `webserver` / `web-runtime` / `client-hmr` / `open-in-app` / `ui-open-in-app` / `directory-picker` 七行、插 native 目录选择包的应用私有 overlay~~（0.1.7 线退役：host 经共享 `runProfile` 起完整 web 应用，见 [`../runtime-profiles/06-desktop.md`](../runtime-profiles/06-desktop.md)）。

## 传输：`dsh-app://` + 认证 HTTP 转发

```
渲染进程 ──dsh-app://app/──→ Electron 主进程 protocol.handle
   静态 dist → 打包资源直读（index 等待 Host 启动注入）
   其余请求 → forwardWebRequest(认证 cookie) → http://127.0.0.1:19387（host 子进程）
   WebSocket ws://127.0.0.1/* → onBeforeSendHeaders 只对主窗口附 cookie 与 origin 改写
生命周期/控制 ↔ Node IPC（ready / fatal / shutdown / update-tasks / platform-session）
```

`dsh-app` 在 `apps/desktop/src/main.ts:111-122` 注册为 privileged scheme（常量在 `apps/desktop/src/ipc.ts:73`），带 `standard` / `secure` / `supportFetchAPI` / `stream` / `codeCache`。`protocol.handle`（`apps/desktop/src/main.ts:561-575`）分两类：`dsh-app://shell` 的更新对话框与强制更新页是壳自有文档，从应用包的 `renderer/` 目录直读、不经过 Host（`apps/desktop/src/update-dialog.ts:37`、`apps/desktop/src/mandatory-update-window.ts:47`）；`dsh-app://app` 的静态资源直读打包 dist，其余请求转发到认证 Host。

认证就是 web 的 process-token + HMAC cookie：host 把 `ctx.connection.authenticatedUrl('http://127.0.0.1:<port>')` 报回壳（`apps/desktop-host/src/index.ts:81-82`），壳对它发一次 `GET` 完成 token 换 cookie（`apps/desktop/src/web-document.ts:43-53`），此后所有转发请求只附壳自己持有的 cookie；`set-cookie` 与连接级响应头不透传给页面（`:64-73`）。秘钥持久化在凭据库的 `client-connection/browser-session` 记录，cookie 绑定 authority、默认 30 天、`HttpOnly; SameSite=Strict`（`packages/client/connection/src/browser-auth.ts:12`、`:161-178`、`:223-227`、`:246-262`）。`/api` 准入先过 401/403（`packages/client/connection/src/index.ts:145-152`）。

~~旧基线的分帧字节管道（`fd3`/`fd4` 请求/响应帧、64 KiB 切片、`__DSH_TRANSPORT__` 注入脚本、Gateway 旁路 WebSocket mux）~~（0.1.7 线退役：`apps/desktop-host/src/wire.ts` 与 `DESKTOP_TRANSPORT_SCRIPT` 已删除；渲染端经 `dsh-app://app` 走认证 HTTP/SSE/WebSocket，Gateway 走标准 `/api` 路径）。Node IPC 现在只承载生命周期与控制，fatal 诊断截到 64 KiB（`apps/desktop-host/src/index.ts:86`、`:94-99`）；壳侧关闭升级是 10 s SIGTERM、再 5 s SIGKILL（`apps/desktop/src/host-process.ts:249-255`）。

## profile、runtime 与版本

`$DSH_HOME/profiles/desktop` 被 Electron 独占并加 `lock`（`apps/desktop/src/paths.ts:17-21`；写锁与陈锁回收在 `apps/desktop/src/project-manager.ts:93-130`），壳进程另取进程级单实例锁（`apps/desktop/src/single-instance.ts:16-20`）。CLI 与桌面共享 `$DSH_HOME` 下的产品数据（会话、设置、凭据、工作区），但**不**共享可执行包、插件激活、lockfile 或 `node_modules`（`apps/desktop/README.md:46`）。

生产 runtime 是签名应用自带的一棵可搬迁树：打包期用本地签名包集（`desktop-packages.json` + `desktop-packages/*.tgz`，`apps/desktop/src/core-package-set.ts:8-14`）物化出 `resources/app.asar/dsh`，再封 `desktop-runtime.json` 完整性描述符（`apps/desktop/src/runtime-tree.ts:12`、`:124-143`）。启动时只校验描述符、准备 profile、摘除旧投影，**不跑 pnpm**（`apps/desktop/src/project-manager.ts:83-91`；`apps/desktop/README.md:73`、`:76`）；host 用 `installAnchor` 指向这棵树解析 `dsh-base` / `dsh-web-app`，外部插件装在 profile 自己的 `node_modules`。原生恢复可在 Host 起不来时禁用第三方 bundle 并备份 profile patch（`apps/desktop/src/project-manager.ts:76-78`；`packages/boot/app-boot/src/profile-sanitize.ts:18`）。

发布身份是「一个组合」：Electron 与 `@deepseek-ai/dsh` 恒为同一精确版本，升级 dsh 就是一次桌面发布；签名更新单元 = 壳 + 匹配 dsh runtime + pnpm（`apps/desktop/README.md:43`、`:49`）。安装/更新交接经 host 的 `update-tasks` inspect / lock / unlock 完成：lock 拒新请求、排空已准入请求后再查运行中的 agent 与 job（`apps/desktop-host/src/index.ts:57-69`；`apps/desktop-host/src/update-tasks.ts:13-51`）。发布目标是 macOS arm64 / x64 与 Windows x64，Linux 不是受支持的桌面发布目标（`apps/desktop/README.md:180`）。

开发用 `pnpm run dev:desktop`（根 `package.json:29`），它把 CLI 与私有 host 包连同 workspace 依赖投影进一次性 npm 工程（`apps/desktop/.desktop-build/development/project`），默认 Harness home 也投影到 `.desktop-build/development/home`；`pnpm run start:desktop`（根 `package.json:30`）跳过构建复用既有产物（`apps/desktop/README.md:96-108`）。
