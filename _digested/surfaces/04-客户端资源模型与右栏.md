# 客户端资源模型与右栏

核验入口：[`docs/subsystems/client-resources.md`](../../docs/subsystems/client-resources.md)、[`docs/subsystems/sidebar-right.md`](../../docs/subsystems/sidebar-right.md)、[`packages/client/resources/README.md`](../../packages/client/resources/README.md)。决策记录：`.agents/notes/implemented/architecture/2026-09-05-client-resource-model.md`、`.agents/notes/implemented/architecture/2026-09-05-sidebar-tab-types-and-navigation.md`、`.agents/notes/implemented/architecture/2026-09-07-workspace-files-dual-face-package.md`。

`a66e470204`（`dsh-v0.1.2-rc.1`）→ `183f08e9c6`（`dsh-v0.1.5-rc.1`）是 client 侧最大的一次结构性变化：给 Web UI 加内容不再只等于「找一个 slot 注册组件」，而是「声明一条资源协议 → 注册该协议的 provider → 用地址读」。右栏是这套模型的第一个消费者。旧写法（每个消费者自己拉数据、自己管取消）在这条路径上被替换成：一个地址只有一条流，谁持有谁负责释放。

## 资源地址

一个资源地址是 `dsh-resource://<type>/…` 形式的 URL（`packages/client/resources/src/client/resources.ts:46` 的 `RESOURCE_SCHEME = 'dsh-resource'`）。host 段是协议键，必须是 `ResourceProtocolMap` 的成员（该 map 由 `packages/client/ui-slots/src/index.ts:44` 声明，各 provider 包用声明合并扩充）；host 之后是协议自己的 path，由协议所有者逐段百分号编码。

模型只读 scheme 与 host：`protocolOf(address)` 返回 `dsh-resource://` URL 的小写 host，其它一律 `undefined`。所以 `sidebar://guide` 这类**导航地址**不指向任何资源，读作 `none`；拼错的协议与畸形地址同样静默读作 `none`（`docs/subsystems/client-resources.md:90-92`）。

`file` 协议的 path 带自己的作用域：`dsh-resource://file/session/<sessionId>/<path>` 是「某个 Session 工作区根下的相对路径」，`dsh-resource://file/absolute/<path>` 是绝对路径（Windows 盘符的 `:` 保持字面）。两个构造函数在 [`dsh-util-workspace-path`](../../packages/util/workspace-path/README.md)：`fileAddressFor(sessionId, cwd, path)` 生成，`parseFileAddress(address)` 读回或返回 `undefined`。地址按字符串比较，`openResource` 只接受 `fileAddressFor` 产出的规范小写拼写。

## provider 契约

协议所有者在自己的 `ctx.effect` 里用 `ctx.resources.register(provider)` 注册，注册返回 disposer；同一协议第二次注册抛错。`register`、`pin`、`source` 三个操作在 `packages/client/resources/src/client/contract.ts:100`、`:106`、`:114` 声明。

provider 是 `{ protocol, open(address, { signal }) }`（同文件 `:71-85`）：`open` 返回 `AsyncIterable<RemoteResult<Value>>`，第一帧是当前状态，之后每帧一次变化；`signal` abort 时流必须结束。**失败是 `ok: false` 帧，不是抛出**：`open` 内部 throw 属于编程错误，模型不接。帧流结束则保留最后状态。

## `useResource` 与四态

`useResource` 是**每个 slot component 都有的全局标准 prop**，不论 scope（`packages/client/resources/src/client/contract.ts:21-26` 的声明合并）。`useResource<P>(address)` 以类型参数指定协议，返回 `{ status, value, failure }`（`ResourceSnapshot`，`:47-53`），`status` 就是四态（`ResourceStatus`，`:44`）：

| `status` | 含义 | `value` | `failure` |
|---|---|---|---|
| `none` | 该协议没有 provider，或地址不是资源地址 | `undefined` | `undefined` |
| `loading` | 流已打开但还没有帧 | `undefined` | `undefined` |
| `live` | 最新帧成功 | 最新 `ok` 值 | `undefined` |
| `failed` | 最新帧报错 | 保留上一个 `ok` 值 | 该帧的 `RemoteFailure` |

**生命周期是「有 holder 就活着」**：holder 是订阅中的 `useResource`，或一次 `ctx.resources.pin(address, signal)`；第一个 holder 打开 provider 的流，后来的 holder 直接读最新值，最后一个释放时 abort 流并丢弃值（有 provider 则回到 `loading`，没有则回到 `none`）。右栏给每个开着的 tab 记录 pin 住它的地址，所以**切 tab 会卸载 body 但不关流**（`docs/subsystems/client-resources.md:86`）。`ctx.resources.source(address)` 是 hook 背后的裸 observable，按地址保持引用稳定，供 React 之外调用。

限定（原文即写明，`docs/subsystems/client-resources.md:90-92`）：地址记录活到页面生命周期，最后一个 holder 离开后记录仍在内存里（不持流、不持值）；provider 若忽略 `signal` 会一直跑到下一帧；`failed` 的失败类型是 Remote 面的 `RemoteFailure`，所以源不是 Remote 调用的 provider 得自己造一个。

## 右栏

右栏是每个 Session 一个的 docking surface。四个包分工（`docs/subsystems/sidebar-right.md:5`）：

| 包 | 角色 |
|----|------|
| `packages/client/ui-sidebar-right` | 拥有 surface、tab 类型注册表、导航服务 `ctx.sidebarRight` |
| `packages/client/ui-dockkit` | 内部布局引擎；是 `ui-sidebar-right` 的内部依赖，不是稳定接口 |
| `packages/client/resources` | `ctx.resources`、`useResource`、协议到值类型的名册 |
| `packages/api/workspace-files` | Host `ctx.workspaceFiles` + `workspaceFiles` Remote namespace + Client `file` 资源 provider |

`ui-dockkit` 不是 Loader row，而是**浏览器平台静态模块**：`packages/client/web/src/platform.ts:13` 把 `'@deepseek-ai/dsh-client-ui-dockkit'` 列进 `PLATFORM_MODULES`，让 seed、bundle external 与 Vite alias 共用同一个模块身份。

### tab 类型注册

一个 tab 类型是**两条共享 `id` 的注册**：`ctx.sidebarRightTabs.register(definition)` 里的静态定义说明它的 `kind` 开哪些地址，加一条 keyed slot 注册提供 body（key 就是定义的 `id`）。定义是静态的，没有 per-tab / per-session 的运行时钩子。

| 字段 | 含义 |
|------|------|
| `id` | 实现身份，跨所有注册唯一（通常写包名）；body 与 title 都挂在这个 key 下 |
| `kind` | 类型的判别式，也就是 `openTab` 的名字。不唯一：扩展可以接管 builtin 的 kind。出货 kind 是 `guide` / `text` / `files` |
| `patterns` | 可选，识别哪些资源地址；按 kind 打开的页面类型不写。含 `:` 的模式匹配整个地址，不含的匹配 URL path 的任意层级。大小写不敏感，语法是 picomatch 的 POSIX 方言 |
| `priority` | 三个字面带（`packages/client/ui-sidebar-right/src/client/tab-registry.ts:48` 的 `SidebarRightTabPriority`）：`extension`（默认且最高）、`builtin`、`fallback` |
| `canOpen(address)` | 可选的同步否决，每次路由决策都跑 |
| `title(address)` | chip 文本，在开 tab 时捕获进布局记录，之后不再改写 |
| `guide` | 可选的 guide 入口框：`{ order, title(), description?(), icon? }`；省略就不上 guide 页 |

路由是一次带排名的认领：`candidates(address)` 先按带、再按最长命中模式长度、最后按注册顺序排；`claim(address, kind?)` 取第一个候选，或直接取被点名的 `kind`（跳过 glob，`canOpen` 仍生效）。没有任何类型认领的地址会抛错——那是接线错误，不是用户错误。一个 `kind` 可以同时有一条 `builtin` 和一条 `extension` 注册，生效的是 extension；extension 注销后 builtin 复位。

### 导航服务

`ctx.sidebarRight` 只有两个 open，所有进入右栏的路径都走其中之一：`openResource(address, options?)` 收 `dsh-resource://` 地址（对话里的文件链接、tool 行的行号引用、文件树的行），`openTab(kind, options?)` 收页面（strip 的添加控件、guide 入口框）。`openTab` 的页面地址由右栏自己写成 `sidebar://<kind>`（`packages/client/ui-sidebar-right/src/client/contract/seed.ts:46`），调用方从不自己拼。

两个 open 都按同样的步骤执行并记成一条历史：认领 → 已有同 `(kind, address)` 的 tab 则聚焦 → 否则落一个新 tab → 展开列。用户看不见的内容不会被打开，所以折叠状态会在同一步展开。`openResource` 对非 `dsh-resource://` 地址或无人认领的地址抛错，`openTab` 对没有注册的 kind 抛错。

其余操作按「读 / 写」分开：`close(tabId)`、`focus(tabId)`、`split(paneId?)`、`float(tabId, rect?)`、`dock(paneId)` 是写；`active()`、`isExpanded()`、`toggleExpanded()` 是读。读在没有挂载 Session surface 时返回 `undefined` 或 `false`，写则抛错，而不是写进没人画的 surface。

### slot

右栏声明四个扩展 slot（`docs/subsystems/sidebar-right.md:95`），它的 document tab 另声明一个 keyed document body：

| Slot | 基数 | 用途 |
|------|------|------|
| `sidebar.right.pane.tab` | keyed by `id`，Session scope | 一个 tab 的 body；按生效实现的 `id` 分发，所以注册者收到它 kind 的每个 tab，docked 或 floating 都是 |
| `sidebar.right.pane.tab.title` | keyed by `id`，Session scope | chip 标题；没有条目时用开 tab 时捕获的 `title(address)` 文本 |
| `sidebar.right.tab.guide` | chain，Session scope | 替换 guide tab 的内容而不替换 tab；第一个不 decline 的条目接管 |
| `sidebar.right.tab.menu.item` | list，Session scope | 内容级动作，追加在 kit 自己的布局动作之后；动作型条目必须调 owner 的 `dismiss()` |
| `sidebar.right.tab.document` | keyed by document `id`，Session scope | document tab 里被选中的文件渲染器；父级拥有共享的加载与工具栏 |

body、title 与 guide 替换都能拿到框架注入的 `useTabInfo()`，返回 `{ sidebar, panel, tab }`；`tab.signal` 在记录消失或插件卸载时 abort，**不**在隐藏或切 Session 时 abort。

### 出货类型与 doc 预览

| kind | 带 | 说明 |
|------|----|------|
| `guide` | `builtin` | `openTab('guide')` 打开；每个贡献的 `guide` 条目一个胶囊，按 `order` 排 |
| `text` | `fallback`，`dsh-resource://file/**`，只认领 Session 地址 | Document Preview 的所有者：用 `useResource<'file'>` 观察元数据，用 Remote 回调读内容，自己拥有渲染器选择、工具栏、per-tab 刷新、滚动与源码导航 |
| `files` | `builtin` | `openTab('files')` 打开；工作区目录树，懒加载 `list`，点文件用 `tab.actions.openResource(fileAddressFor(sessionId, root, path))` 开进自己的 pane |

`text` tab 是共享的 Document Preview owner：它的 root 注册声明 `sidebar.right.tab.document` 并提供 `ctx.documentPreviews`，渲染器在自己的 effect 里注册 `DocumentPreviewDefinition`（唯一 `id`、`extensions`、本地化 `title()`、`loading`、可选 `priority`、可选 `wrap`），再 keyed 到 document slot。渲染器注册表**保留所有**实现（与 tab kind 的接管相反），工具栏列出匹配的备选并按 tab 记住选择；未知扩展名走纯文本。内容按页读 `remote.workspaceFiles.read` / `readAll`（`packages/client/ui-sidebar-documentpreview/src/client/rpc.ts:81` 的分页绑定、`packages/client/ui-sidebar-documentpreview/src/client/index.ts:95` 的整读绑定），HTML 走 `readRelated`（`packages/client/ui-sidebar-documentpreview/src/client/html/index.ts:36`），Host 侧解析路径。

明确**不建**（`docs/subsystems/sidebar-right.md:144-154`）：布局持久化、只读布局快照或订阅、capability 发现数组（`features`）、tab 类型的 `option` 优先级带、用户可见 undo、tab 图标、按实现名开 tab、服务上的地址查找、`sidebar://<kind>` 之外的导航地址。

## workspaceFiles 服务

Host 提供 `ctx.workspaceFiles`，生成的 `workspaceFiles` Remote namespace 让客户端读同一个服务。每个方法都在 wire 上带 Session 身份，客户端从不自己命名 root；Host 读活的 Session header，冷 Session 走 persistence 的 `stat`，不激活 Agent、不读事件体、也不借用父 Session 的 root。七个方法（`packages/api/workspace-files/src/index.ts:232`、`:257`、`:278`、`:300`、`:324`、`:337`、`:365`）：

| 方法 | 返回 |
|------|------|
| `stat(path)` | `{ absolutePath, version, bytes? }`，只给身份、版本与大小，不给内容 |
| `read(path, { offset?, limit? })` | 一页文本行（`offset` 1 起，`limit` 受配置页大小封顶），带 `lines` 与 `eof` |
| `readBytes(path, { offset?, length? })` | 一窗原始字节（`offset` 0 起），base64 编码，不做文本解码 |
| `readAll(path)` | 完整原始字节，超 `maxFileBytes` 直接失败而不是截断 |
| `readRelated(path, relativePath)` | 从基准文件所在目录解析出的关联文件完整字节 |
| `list(path)` | 工作区根内某目录的直接子项，按配置上限截断并置 `truncated` |
| `changes()` | stream：先 `ready` 一次，之后是按发射顺序的工作区观察帧 |

文件操作拒绝最终符号链接并强制传输上限，`read` 另要求 UTF-8 文本；失败用 `workspace-file/*` 码。`dsh-api-workspace-files` 同时是双面包：Host 服务 + Client `file` provider，它的 `dsh.client.inject` 列 `api-gateway` 与 `client-resources`（`packages/api/workspace-files/package.json:42-45`）。Session 地址带上授权的 Session 与相对/绝对路径原样交给 Host；裸 `absolute` 地址没有可授权 Session，失败于 `workspace-file/unknown-workspace`，不借用当前或 Tab Session。任何 UI（包括 Global 组件）读同一个完整地址就共享同一条观察流。
