# 客户端资源、布局与右 Sidebar

源码核验入口：`packages/client/resources/src/`、`packages/client/ui-dockkit/src/`、`packages/client/ui-sidebar-right/src/`、`packages/client/file-upload/src/`、`packages/client/ui-open-in-app/src/`。

本篇说明 Web 客户端在「壳 / wire / slot」之上长出来的三样东西：把 URL 地址解析成活值的资源层、与宿主无关的布局引擎、以及把两者接成产品面的右 Sidebar。三者都住在浏览器侧 Cordis 树里，Host 没有对应节点（见 [`01-启动面与session流.md`](./01-启动面与session流.md)）。

## 资源层：地址是唯一的句柄

一个组件常常只知道「这是个 tab 记录 / 链接 / 提及」的**地址**，而数据属于另一个客户端包。`dsh-client-resources` 就是这两者之间的缝：地址用 `dsh-resource://<type>/…`，需要作用域的协议把作用域编进 path。

每个 slot 组件都从 props 拿到 `useResource`。`useResource<P>(address)` 用类型参数点名协议，返回 `{ status, value, failure }`：没有该协议的 provider（或地址根本不是 `dsh-resource://` URL）时是 `none`，provider 尚未产出时是 `loading`，拿到最新 `ok` 帧时是 `live`，最新帧报告失败时是 `failed` 并把失败与最后一个值并列。**订阅这个 hook 本身就是把资源持有住**：在别的持有者让资源活着时挂载的组件立刻读到最新值。

提供协议的一方在自己的客户端包里往 `ResourceProtocolMap` 声明值类型，并注册**一个** provider（`ctx.resources.register({ protocol, async *open(address, { signal }) })`）。`open` 产出 `RemoteResult` 帧：当前内容先来，此后每次变化一帧；失败是 `ok: false` 的帧而不是抛错；`signal` abort 时必须停止。一个协议**恰好一个** provider，第二个注册抛错。已持有该协议地址时注册 provider 会把它们打开；dispose 结束它们的流并回到 `none`。

`ctx.resources.pin(address, signal)` 不订阅也能让资源保持打开，直到 signal abort——右 Sidebar 用它把每个打开 tab 的地址钉住整个 tab 记录的生命周期，于是切走 tab 卸载 body 却不关流，切回来直接读到最新值。`ctx.resources.source(address)` 是 hook 底下那个裸 observable，供 React 之外的调用方使用。

生命周期是「每个地址一条记录」：快照 store、持有者计数（hook 订阅者加 pin）、以及运行中流的 `AbortController`。第一个持有者打开 provider 的流，后来的共享；最后一个持有者释放时 abort 并重置快照为 idle。记录**保留到页面生命周期结束**，这样 `source()` 在 React「先渲染后订阅」的窗口与 StrictMode 重挂载之间保持引用稳定。失败是帧不是抛错：下一次 `ok` 帧清掉它。provider 流内部的 `throw` 是编程错误，不被捕获。

## 布局引擎：host-agnostic 的 docking

`dsh-client-ui-dockkit` 是布局本身——split tree、它的操作、拖拽手势、浮动面板。它保持 host-agnostic：不知道产品的文案、不知道一个 tab 的 kind 意味着什么、不知道新 pane 该用什么种子。

这条分界是刻意的：产品知识（文案、kind 语义、种子、挂载位置、别的插件怎么够到它）全部留在消费它的包里。右 Sidebar 就是那个消费方，也是这套引擎唯一的稳定使用面；dockkit 自身不承诺稳定 API。

## 右 Sidebar：把两者接成产品面

`dsh-client-ui-sidebar-right` 每个 session 持一个 docking surface，在 frame 右列画成边缘锚定的面板，有两种呈现：

| 呈现 | 轨道 | 面板 |
|------|------|------|
| `push`（默认） | 面板宽度，会话让出空间 | 在轨道内，左边缘与会话右边缘一起移动 |
| `fullscreen` | 宽屏保留常规轨道；窄屏自动全屏时不占轨道 | 覆盖整个 viewport |

两种呈现共享同一棵内容树，所以切换不重挂载 tab。窄于 768px 打开时自动用全屏；窄屏下退出全屏会关掉面板，变宽不会重新打开已关掉的面板。seat 经 `ctx.layout.openRightbar(track, fullscreen)` / `closeRightbar()` 报告呈现；frame 不注入本包。

面板没有 header 行：它的两个控件（呈现开关与折叠按钮）骑在 kit 的 chrome seat 上，位于右上 pane tab 条的最末端。面板隐藏时，会话 header 角落 seat 里的一个按钮是回去的路；它的字形是左 Sidebar 折叠图标的镜像，与面板共享同一个 store（slot runtime 允许一个句柄横跨两个同作用域 seat）。折叠的 Sidebar 因此不向会话索取任何东西：没有 rail、没有宽度，transcript 的滚动条停在列边缘。没有 session 就没有按钮也没有面板。

**状态是可重放的记录序列。** 每个 session id 一个 `SurfaceState`——布局、记录下来的操作序列、以及它 mint 过多少 id。每个动作都是同一形状：先 mint 意图需要的 id，问 kit 的 planner 哪些操作能实现它，记录下来，然后把整个 surface 赋回。**没有任何动作就地改布局**，这是让 kit 的纯函数成为唯一计算布局的地方的原因。把 mint 计数器带在 surface 上，正是记录序列可重放的原因：操作内嵌它们创建的 id，所以从同一初始状态重放会得到同一棵树。每个动作记一条历史，无论它需要几个操作；展开、折叠、切换呈现也记。

动作之后，kit 的 settle planner 保持展开的 surface 有内容：最后一个 tab 被移走或浮出的 docked pane 被合并掉，空掉的根 pane 拿到默认页。折叠的 surface 不做这种回填——session 从折叠且空开始，关闭导致折叠的那次会把列留空，第一次展开才播下默认页。

**状态只在内存里**：reload 让每个 session 回到折叠默认，切换 session 各自保留原处。布局历史只经 `@internal` 的 `_undo()`/`_redo()` 步进，没有面向用户的控件。

## 扩展点：type 与 body 两段

一个 tab 类型分两段注册，两段都在类型自己的 `ctx.effect` 里，所以注册恰好活到做它的插件为止；shipped 的 guide 类型走的正是别的包要走的公开路径（`ui-sidebar-documentpreview` 是活证）。

1. **类型**——`ctx.sidebarRightTabs.register({ id, kind, patterns?, priority?, canOpen?, title, guide? })`，静态声明，无运行时 hook，返回 disposer。`id` 是本实现在 tab 系统里的身份，跨所有注册唯一，重复注册同一个 `id` 抛错；`kind` 一旦允许扩展接管 builtin 就不再唯一，所以实现要给自己命名。资源类型用 `patterns` 写 `dsh-resource://` 地址的 glob：含 `:` 的匹配整个地址，不含的按大小写无关匹配 URI 的 path 任意深度；页面类型（guide、文件树）不写 patterns，按 kind 打开。`canOpen(address)` 可否决匹配，`title(address)` 是打开时捕获的 chip 文案。
2. **body**——`ctx.slots.register({ name: 'sidebar.right.pane.tab', key: definition.id }, Body)`，经框架注入的 `useTabInfo()` 读 `{ sidebar, panel, tab }`。tab 记录里的 `navigation`、`signal`、`actions`、以及区分 body 与 title 的 `visible` 都在这里。

**哪个类型打开一个资源**照编辑器解析器的惯例：`patterns` 命中的类型先按优先级带排序——`extension`（产品外来的类型，最高，也是没点名时的默认）、`builtin`、`fallback`——再按命中 pattern 的长度，再按注册顺序；`canOpen` 摘掉候选。**带宽是字符串字面量**，所以另一个包里的类型不需要从这里做运行时 import。

`ctx.sidebarRight` 是导航控制器：`openResource(address, options?)` 与 `openTab(kind, options?)`，进入该列的每条路径都调其中之一——会话里的文件链接与工具行的行引用、tab 条的添加控件、guide 的入口盒、文件树的行。它暴露的是**操作而非快照**：没有布局快照、没有操作日志、没有按地址查找。`close(tabId)`、`active()`、`isExpanded()`/`toggleExpanded()`，以及给程序化排布用的 `focus`/`split`/`float`/`dock`。命令需要一个已挂载的 session surface；没有时抛错，而不是写进一个没人画的 surface。

## 相邻的客户端能力

- `dsh-client-file-upload`：session 寻址的浏览器文件上传，产出 opaque receipt 供后续 prompt 引用。
- `dsh-client-ui-open-in-app`：会话头的 "Open In..." split button，依赖 Host 侧 `dsh-host-open-in-app`。
- `dsh-client-ui-sidebar-files` / `ui-sidebar-documentpreview`：右 Sidebar 的文件树 tab 与文档预览 tab，都是上面那两段注册路径的消费方。
