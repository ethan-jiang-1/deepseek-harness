# 客户端热更新与模块缓存

核验入口：[`docs/subsystems/client-modules.md`](../../../../docs/subsystems/client-modules.md) 的模块注册表一节、[`packages/client/hmr/README.md`](../../../../packages/client/hmr/README.md)、[`packages/client/hmr/src/`](../../../../packages/client/hmr/src/)（`index.ts` / `client/index.ts` / `events.ts`）。

开发时改一个 client 包，页面不刷新也能变——这条链由两半组成：Host 侧的 bundle 观察者，和浏览器侧的 swap 驱动器。这一页讲它们的分工，以及「为什么 `rebuilt()` 是 build 产物进入模块图的唯一入口」。

## 两半

| 半边 | 文件 | 做什么 |
|------|------|--------|
| Node 半边 | `packages/client/hmr/src/index.ts` | 对每个包的 stamped entry artifact 做 stat-poll（`pollIntervalMs` 默认 `500`），把既有图变化与重建通知经 `/plugins/events` 的 SSE 通道发给页面 |
| 浏览器半边 | `src/client/index.ts` | 订阅 SSE（shell 提供 `__DSH_TRANSPORT__.fetch` 时走它），收到 `rebuilt` 帧后驱动一次 swap |
| 共享帧 | `src/events.ts` | `graph` / `rebuilt` 两类帧与 endpoint 常量 |

## 一次 swap 的顺序

1. `rebuilt` 帧到达，controller 让旧模块失效，并在**旧 fiber 仍在服务**时预取该条目的单资源脚本。
2. 删掉注册表里的旧记录，重新 import。
3. 级联不用 HMR 记账：fiber 的 activation epoch 拼着它依赖的 service provider 的 uid，provider 的 fiber 一换，依赖方由 Cordis 自己重载。
4. 成功后改动立即生效、插件继续工作——代价是被替换插件里的 React state 会丢（`packages/client/hmr/README.md` 的「What a reload does」）。

## 缓存修订只有一个入口

`rebuilt(id)` 是「一份完成的 bundle 产物」进入图的唯一入口；mtime、ctime 与大小都没变就保留原图、不读 bundle。`onRebuilt` 只在 rev 真变时触发，`onGraphChanged` 是 pull 模型——listener 收到通知后自己重读 `graph`（`docs/subsystems/client-modules.md:172-195`，生成自 `packages/client/modules/src/index.ts`）。

## 失败策略

下载失败时**旧插件继续跑**；一旦旧 fiber 已被拆掉，import 或激活失败**不会**回滚到上一份 bundle，失败直接显现在界面上。这条和 Cordis 的「卸载即撤销」一致：没有回头路，只有重试。

## 插件作者视角

- 被热替换会丢 React state：别把「用户正在编辑的草稿」只放在组件 local state 里。
- 你的 apply 必须可重入：依赖方随 provider 级联重载，注册要么走 `ctx.effect()` 自动撤销，要么会重复叠加。
- `pollIntervalMs` 只在开发期的 watch 链里有意义；生产构建不走这条链。
- 改了模块身份（`dsh.client.external`、包名、`./client` 导出）不是热更新能救的，要重启（[`../rules/02-依赖-构建期环境与三处注册面.md`](../rules/02-依赖-构建期环境与三处注册面.md)）。
