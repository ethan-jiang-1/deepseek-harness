# 模块身份：baseline、`external` 与激活顺序

核验入口：[`docs/subsystems/client-modules.md`](../../../../docs/subsystems/client-modules.md)、[`packages/client/AGENTS.md`](../../../../packages/client/AGENTS.md) 的模块图与依赖声明两节。

这一页和上一页是两件事：上一页决定谁能 import 谁，这一页决定插件什么时候活、模块什么时候能物化。

## 模块身份：baseline、`external` 与激活顺序

客户端 baseline 集中在 [`packages/client/web/src/platform.ts`](../../../../packages/client/web/src/platform.ts)：`PLATFORM_MODULES` 命名 shell 播种的 React、Cordis 与静态 Client 库，`PRELOADED_CLIENT_EXTERNALS` 留给必须在 shell boot 前到达其 factory 的动态行、当前为空（`packages/client/AGENTS.md:80`）。实际清单是 `react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`、`@deepseek-ai/cordis`、`zod`、`@tanstack/react-virtual`、`@deepseek-ai/dsh-client-store`、`@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-ui-primitives`、`@deepseek-ai/dsh-client-ui-dockkit`（`packages/client/web/src/platform.ts:7-16`、`packages/client/web/src/platform.ts:19-20`）。

baseline external 对每个动态 bundle 都是隐式的：**不要**在包 manifest 里重复 React、Cordis、`client/store`、`ui-primitives`、`ui-slots`、`ui-dockkit`（`packages/client/AGENTS.md:82`）；`verify-client-packages` 把重复 baseline 的条目直接判 fail 并要求删掉显式声明（`scripts/verify-client-packages.ts:347-350`）。

`dsh.client.external` 不是 feature plugin 的依赖机制，只有 infrastructure、transport 或 generated assembly 才能加一个包级非 baseline 值请求，且必须写精确 import specifier，只有尾部 `/client` 会把包行别名（`packages/client/AGENTS.md:83`）；gate 对 `packages/client/` 下的包请求某个运行时 external 直接拒绝，提示「只共享类型或调注入的 Cordis service」（`scripts/verify-client-packages.ts:358-362`）。沉默即私有副本：普通第三方实现库可以各自打包，只经 `import type` 到达的值被擦除、不产生请求（`packages/client/AGENTS.md:84`）。

一个请求只有两个可能供给方：动态包供给自己的行，或 `PLATFORM_MODULES` 供给一个精确的静态表 key；不存在 `dsh.client.provide` 别名协议（`packages/client/AGENTS.md:85`）。gate 会逐条查 baseline 重复、空值、重复值、自己的行、无 supplier、无生产源码 import 的过期声明，并拒绝同步请求环（`scripts/verify-client-packages.ts:325-387`），环的判定沿 `external` 边做 DFS 并打印 `synchronous dsh.client.external cycle` 链（`scripts/verify-client-packages.ts:389-424`、`scripts/verify-client-packages.ts:433-441`）。0009 起另有一条：包内动态 chunk 必须自包含，源码用 `import()`、preset 发 `require.async(...)`，entry/chunk 不得保留同步相对 `require("./client*.js")`（`packages/client/AGENTS.md:87`）。环被拒绝的根因是 module 请求是同步的：seam 是 `loader.internal = modules`，cordis 经 `EntryTree.import` 到达插件代码，所以每个 module 请求都必须在 cordis 能把它排到激活之前就可满足；modules node 半边按拓扑序发行，`ClientModuleSystem.import`/`prefetch` 递归注册动态 provider factory 后才让消费者物化（`packages/client/AGENTS.md:101`）。

**模块顺序与 Cordis 激活不是一回事**，两者不可互换（`packages/client/AGENTS.md:91`、`packages/client/AGENTS.md:93-99`）：Cordis service `inject` 的单位是 service 名、时机是 runtime（fiber 等待）、不满足则 PENDING 无超时、任何提供该 service 的插件都可满足且可替换、允许成环；module graph `external` 的单位是 module specifier、时机是物化（交给 factory 的 `require` 是同步的、不能等）、不满足当场抛错、只能由唯一 module 身份满足且不可替换、成环被拒。Browser boot 里这也是原文口径：Cordis service injection 决定激活，module graph 顺序只决定同步 import 能否物化（`docs/subsystems/web-client.md:26`、`docs/subsystems/client-modules.md:64-67`）；`immediately` 只标 stage-one 预取屏障，`inject` 是信息性的包名边（preflight 展示、HMR diff），既不排 entry 激活也不排 apply 顺序（`packages/client/AGENTS.md:148`）。两个反例要点：`packages/client/web` 不是 Loader entry，它的静态 import 播种 `PLATFORM_MODULES`（`packages/client/AGENTS.md:103`）；bundle route 是 `GET/HEAD /plugins/??<package-a>/client.js,<package-b>/client.js&rev=<rev>`，起始 URL 上限 3 KiB，未知/改动过的资源列表、缺失或过期 rev 一律 404 而不是回落到 SPA 的 HTML（`docs/subsystems/client-modules.md:88`）。

缓存修订也有一条纪律：`rebuilt(id)` 是变更后的 bundle 内容进入 graph 的**唯一入口**，它把 bundle 与当前 source map 一起重哈希，只有 rev 真变了才重组 graph 并通知；`onGraphChanged` 是 pull 模型（`docs/subsystems/client-modules.md:106`）。
