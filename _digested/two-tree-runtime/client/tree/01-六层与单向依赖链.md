# 六层与单向依赖链

核验入口：[`docs/subsystems/web-client.md`](../../../../docs/subsystems/web-client.md) 的「Layers and ownership」一节；[`packages/client/AGENTS.md`](../../../../packages/client/AGENTS.md) 的 layering 段。

这一页把浏览器侧分成六层，并给出唯一允许的依赖方向；`state/`、`view/`、`rules/` 三格都是在这些层上回答具体问题。

## 层与单向依赖链

`docs/subsystems/web-client.md:9-19` 把 Web Client 分成六层，并逐层指定 owner：

| 层 | 主要 owner | 职责 |
|---|---|---|
| Host application | 业务服务与 `packages/api/*-controller` 的 Host 入口 | 拥有权威状态、持久化、mutation 顺序、访问策略与流的生产 |
| Transport 与 API assembly | `client/connection`、`api/gateway`、`api/remotes` | 建立 Client generation、暴露生成的 `ctx.remote` 方法与流、转发选定 Cordis 事件、承载取消与结果 |
| Client models | `api/session-controller/client`、`api/workspace-controller/client` | 维护 Host 状态的 React-free 镜像，解决 stream/unary 竞态，拥有对象身份与订阅，暴露窄命令服务 |
| UI adapters | `client/ui-session`、`client/ui-workspace` | 把 model observable 转成 root 或 Session scope 的标准 slot source，不接管业务状态 |
| Conversation data | `client/ui-conversation` 与 `ui-chat`、`ui-trajectory` 等目标包 | 把标准事件与压缩的历史 Assistant run 组装成各目标自己的快照，并拥有共享 shell 与输入流 |
| Composition 与 rendering | `client/ui-slots`、`client/ui-renderer`、`client/ui-layout` 与 feature UI 包 | 声明扩展位、派生组件 props、把 observable 绑到 React hook、挂载最终树 |

依赖方向是单向的，原文一句话钉死：**Host state → Remote transport → Client model → UI adapter → Conversation or presentation → Slots → React**；用户动作沿回调反向走，回调闭合在注入的 Client service 或生成的 Remote namespace 上（`docs/subsystems/web-client.md:20`）。

```text
Host state ──► Remote transport ──► Client model ──► UI adapter ──► Conversation/presentation ──► Slots ──► React
     ▲                                                                                                        │
     └──────────── 回调闭合在注入的 Client service / 生成的 Remote namespace 上 ◄──────────────────────────────┘
```

同一句还给出硬约束：**presentation component 永远不接收 Cordis `ctx`、transport 对象，或另一个 feature plugin 的实现**（`docs/subsystems/web-client.md:20`）。`ctx` 只属于 apply 世界 —— plugin body 与闭包住它的 inject factory；组件只通过派生的 props share 拿数据与回调，不调触达 ctx 的 hook、不 import service class 去戳它、不读 React context（`packages/client/AGENTS.md:44`）。`docs/subsystems/slots.md:66` 用同样口径复述：组件拿到的 owner 值、store、service 都在 binding site 组装，service 与 model 对象留在 `apply` 闭包里。

跨包边界另有一条：feature plugin 可以用 `import type` 共享声明，但**不得** runtime-import 或 re-export 另一个 feature plugin 的值（`docs/subsystems/web-client.md:91`）；共享运行时值只能放进没有 feature 生命周期的窄静态 owner，如 `client/store`、`ui-primitives` 或 browser-safe utility 包（`docs/subsystems/web-client.md:93`）。Client model 不是第二份业务真相：Host controller 决定耐久状态与 mutation 结果，Client model 只维护最新可用的本地投影并编码「延迟响应与替换基线如何合并」（`docs/subsystems/web-client.md:54`）。

六条数据路径是这六层的具体走法（`docs/subsystems/web-client.md:66-75`；0009 起新增 Background jobs 一条：Host job registry → `job.list`/`job.follow` → `ClientJobs` 名册与输出视图）：durable Session display（Host log → packed Remote `follow`/`page` → `SessionEventLikeEntry` 窗口 → Conversation Context → target snapshot → slot view → React）、transient Session control、Workspace state、scoped interaction、user command。恢复语义也分层：durable journal 每个 generation 用开窗快照替换窗口，control/Workspace 流保留最后值再原子替换，普通转发的通知**不重放**（`docs/subsystems/web-client.md:77-87`）；不存在 monolithic Client `Runtime`、`HostFrame`、`events.mux` 或万能 `resync()`（`docs/subsystems/web-client.md:87`）。
