# 依赖、构建期环境与三处注册面

核验入口：[`packages/client/AGENTS.md`](../../../../packages/client/AGENTS.md)、[`tsconfig.client.json`](../../../../tsconfig.client.json)、[`packages/bundle/web-app/cordis.patch.yml`](../../../../packages/bundle/web-app/cordis.patch.yml)。

三节连起来回答：依赖怎么声明、构建期能读到什么、起一个新包要补哪三处注册面。

## 依赖声明

npm section 描述的是安装与开发关系，每个 build face 各自决定自己的产物里放什么（`packages/client/AGENTS.md:63`）：`verify-package-dependencies` 查并修这些规则，`verify-client-packages` 管 Client 载入与 module 请求（`packages/client/AGENTS.md:63`）。八条：每个 client 包在 `peerDependencies` 与 `devDependencies` 里保持匹配的 Cordis（静态包也算，因为它们的 Node 半边参与同一 Cordis 插件契约）（`packages/client/AGENTS.md:65`）；`packages/client/` 下的包永远被覆盖（`packages/client/AGENTS.md:66`），`dsh.client` 用来标记该目录之外的 Client/Host 包，被覆盖包的 Host 入口会被 scan，而只有 `./client` export 并不触发依赖策略（`packages/client/AGENTS.md:65`）；browser 与 type 关系是 development-only —— workspace 与第三方 Client import、type-only import、module augmentation、TypeScript project reference、`dsh.client.inject`、metadata-only peer 只能进 `devDependencies`，不出现在 import 里的配置项登记在 dependency policy，Node companion 值 import 走下面的 Host 规则（`packages/client/AGENTS.md:67`）；Host 值 import 需要分类过的 export —— 从 Host 入口到达的 workspace 值，只有当其精确 module specifier 与 runtime export 出现在 `safeHostDependencyExports` 时才进 `dependencies`，身份或 module state 必须共享的 export 进 `peerRequiredHostExports` 且整条包边保持 peer+dev 匹配，verifier 在 `--fix` 写 manifest 之前先拒绝未分类 export（`packages/client/AGENTS.md:68`）；只有 Host runtime 库需要安装依赖，browser-only 第三方实现无论在 `lib/client.js` 里内联还是作为静态 browser 库的裸 import 都进 `devDependencies`（`packages/client/AGENTS.md:69`）；Browser 与 Node build face 独立声明 externality —— 动态浏览器半边用 baseline 加 `dsh.client.external`，静态链接 face externalize 每个裸 specifier，Node face externalize 其 production dependencies，**把一个名字在 npm section 之间搬动不得悄悄改变 bundle 内容**（`packages/client/AGENTS.md:70`、[`packages/client/tsdown.client.ts`](../../../../packages/client/tsdown.client.ts)）；发布的 payload 要闭合，每个相对 runtime import 与产出的 asset 都必须被 `files` 覆盖（`packages/client/AGENTS.md:71`）；只有 root manifest 声明 React 类型包：`@types/react` 与 `@types/react-dom` 只进根 `package.json` 的 `devDependencies`，`verify-package-dependencies` 拒绝 `apps/*`、`packages/*/*`、`vendor/*` 下的任何声明（`packages/client/AGENTS.md:72`）。

## 新包必须补的三处注册面

起一个 `packages/client/<name>` 插件包时，**三处注册面缺一不可，缺任一处会在不同的、更晚的点失败**（`packages/client/AGENTS.md:146-147`）：一是 [`tsconfig.client.json`](../../../../tsconfig.client.json) 聚合里的 `references` 条目（该数组在 `tsconfig.client.json:55`，示例条目见 `tsconfig.client.json:58`）；二是 [`packages/bundle/web-app/cordis.patch.yml`](../../../../packages/bundle/web-app/cordis.patch.yml) 里的一条 `dsh.client` 行（browser roster 段落见 `packages/bundle/web-app/cordis.patch.yml:40-43`）；三是 [`packages/bundle/web-app/package.json`](../../../../packages/bundle/web-app/package.json) 的依赖（既有条目示例见 `packages/bundle/web-app/package.json:112`）。第三处的原因写得明确：profile boot 通过**计算出的 runtime resolution** 解析裸行名（装在 Node 解析器上的拦截层，不再写 `$DSH_HOME/profiles/node_modules`），所以**一个没有任何 manifest 声明的行会 import 失败**（`packages/client/AGENTS.md:147`）。

配套的 manifest 与流程语义：`dsh.client` 声明里 `platform: 'web'` 恒定，且该声明要求包有 `./client` export（没有时 scan 直接抛错）；`immediately: true` 只给 stage-one 预取的 infrastructure 行；`inject` 列的是包名依赖边，仅供 preflight 展示与 HMR diff，**不**排 entry 激活或 apply 顺序，激活顺序只由 Cordis fiber 对 service 的 inject 等待决定（`packages/client/AGENTS.md:148`）。新包骨架还包括 `package.json`（包名 `@deepseek-ai/dsh-client-<name>`、exports `.`/`./client`/`./src/*`/`./package.json`、`dsh.client` manifest、`files`；「可选 `./invariant`」不存在（运行时 invariant 机制已整族退役））、`tsconfig.json`、`tsdown.config.ts` 的 `clientBundle(id, ['lib/types/index.js'])`、空的 node 半边 `src/index.ts`、使用 CSS Modules 时的 `src/css-modules.d.ts`，以及带 Model Experience 段的 `README.md`（`packages/client/AGENTS.md:146`）。要在本地 `dsh web` 服务器上验证，先 `pnpm --filter <pkg> bundle` 重建 bundle，因为 registry 服务的是 `lib/client.js` 而不是源码（`packages/client/AGENTS.md:150`）。

## 构建期浏览器环境

Client 业务代码可以静态读 `process.env.DSH_CLIENT_*`，每个被引用的值都是公开产物内容（`packages/client/AGENTS.md:76`）。共享的 build-environment helper 让 Vite 与动态 tsdown bundle 拿到同一批 build-process 值，未设置的变量解析成 `undefined`，且**不暴露**动态查找或枚举（`packages/client/AGENTS.md:76`）：前缀常量是 `DSH_CLIENT_`（`scripts/client-build-environment.ts:14`），bundler 替换把 `process.env` 兜底成 `{}` 并对每个精确的 `process.env.<name>` 注入字面量，因此未设置的静态读取求值为 `undefined` 而不需要浏览器 `process` 全局（`scripts/client-build-environment.ts:254-271`）。一次完整 root build 记录确切的公开值与全部 client 产物的 digest，release 与 built-artifact 消费者拒绝缺失或过期的记录（`packages/client/AGENTS.md:76`）：记录落在 `.dsh-build/client-build-environment.json`（`scripts/client-build-environment.ts:32`），digest 覆盖 `apps/web/dist/**/*` 与各包的 `lib/client.js`/`lib/client.js.map`/`lib/client.*.js`/`lib/client.*.js.map`（`scripts/client-build-environment.ts:35-40`），按排序后的路径与内容算 SHA-256 与文件数（`scripts/client-build-environment.ts:338-345`），读取时若 count 或 digest 与当前产物不符即抛错要求重跑完整 build（`scripts/client-build-environment.ts:334-338`）。需要在 build 之后仍能改变的选项走 runtime configuration，而不是 build-time 变量（`packages/client/AGENTS.md:76`）。
