# Conversation Node 纪律

核验入口：[`docs/subsystems/web-client.md`](../../../../docs/subsystems/web-client.md)、[`packages/client/AGENTS.md`](../../../../packages/client/AGENTS.md)、[`docs/subsystems/slots.md`](../../../../docs/subsystems/slots.md)、[`docs/subsystems/client-modules.md`](../../../../docs/subsystems/client-modules.md)、[`docs/subsystems/conversation.md`](../../../../docs/subsystems/conversation.md)、[`docs/web-styling.md`](../../../../docs/web-styling.md)。机检方：[`scripts/verify-client-domain-graph.ts`](../../../../scripts/verify-client-domain-graph.ts)、[`scripts/verify-client-ui-i18n.ts`](../../../../scripts/verify-client-ui-i18n.ts)、[`scripts/verify-client-packages.ts`](../../../../scripts/verify-client-packages.ts)。包目录数量以 [`claims.json`](../../../harness-idea/claims.json) 的 `client-package-total` 为准；本页每条规则都覆盖它们。`client/ui-secret-mask` 属同一纪律范围：它对**已发送**用户文本里识别出的凭据做显示掩码，并在交互消息里给逐值揭示控件（`packages/bundle/web-app/cordis.patch.yml:388-389` 的罗盘行），是 client 侧安全相关行为的当前落点。（`ui-permission` 的包名是 `@deepseek-ai/dsh-client-ui-permission-presets`，目录 `ui-permission-presets/`，slot 行 id 仍是 `ui-permission`；`ui-settings-account` 与 `ui-sidebar-terminal` 的罗盘行在 `packages/bundle/web-app/cordis.patch.yml:144-145`、`:300-301`。）

这一页讲 Conversation 的扩展模型：一个业务特性一个 `ConversationNodeDefinition` 加一个 keyed renderer，事件 fold 不进 `Session`，也不进任何中央 dispatcher。

一个 Chat 业务特性注册**一个** `ConversationNodeDefinition` 加它的 keyed `conversation.chat.node` renderer；不得把该特性的事件 switch 或 fold 加进 `Session`、`SessionManager` 或某个中央 built-in dispatcher（`packages/client/AGENTS.md:107`）。`match(event)` 只读当前 `SessionEventLike`；多输入 Context 里的每个标量事件或 packed Assistant run 都要携带或独立派生出**同一个稳定业务 id**；`update` 把一次 Match 折进 State，并且必须能按逻辑 log `seq` 确定性地重放；packed 行是 update-only；消费 Assistant delta 的 Definition 必须同时实现标量与 `chunkrow/*` 两个分支而不展开成员（`packages/client/AGENTS.md:108`）。append 热路径与 renderer **绝不扫描**完整事件窗口、Contexts 或 Chat Nodes：累积靠 State，同一 Turn/Step 的事实经 `buildLocationData()` 发布，消费侧只用最终 Node 数据或受限的 Location hook（`packages/client/AGENTS.md:109`）。

引擎侧的对应事实：`ui-conversation` 每 Session 一个 identity-stable binding、一个 `ConversationNodeAssembler`，对每个已注册 Definition 全量施加并给每个已注册 view target 发布独立 source（`docs/subsystems/conversation.md:11`）；`match` 是身份提取器而不是 fold，只收当前事件并返回 Definition 局部 id 与生命周期 role（`docs/subsystems/conversation.md:246`）；`target` 与 `buildViewNode(context)` 必须同时出现，`context.key` 是 React 面身份，Node 发布后必须持续返回同一 key，离开可见流时用 `visibility: 'hidden'` 而不是 `null` 撤回（`docs/subsystems/conversation.md:250`）。

重放与热路径的边界由引擎给出：window 更新有三条路径 —— 开窗/重同步/补洞时 replace、prepend 一页旧历史、append 一条 live 事件，append 只对匹配到的 Context 做恒定时间查表（`docs/subsystems/conversation.md:280-282`）；因此有 D 个 Definition 时，一条标量事件或 packed run 只做 D 次当前输入匹配加匹配后的恒定时间 key 查找，Definition 代码必须保住这条性质（`docs/subsystems/conversation.md:284`）。Live Assistant delta 以 Client-only 的 `assistant/live-chunk` 到达（0.1.7 线起 transient 记录也可作 `start`，旧「update-only」限制已删），重连基线把活跃的进程内 compact stream 展开成同样的 transient 事件，而持久的 `assistant/message`/`assistant/attempt` 内嵌完整 compact stream 供历史重放；同一 Definition 在同一个 `match()`/`update()` 里同时处理 live chunk 与 durable settlement（`docs/subsystems/conversation.md:72`）。需要更早同类 State 时用 `start` 收到的 `ConversationContextReader` 调 `reader.previous<State>(kind)`，而不是接整个 Context 集合或扫描事件（`docs/subsystems/conversation.md:254`）。`publication` 控制 State 变化何时物化：结构性/终态用 `immediate`，高频可见 delta 用 `animation-frame`，只喂后续发布用 `none`（`docs/subsystems/conversation.md:286`）。

## 加一种节点要碰的三个注册面

Definition 经 `ctx.uiConversation.events.register(definition)` 登记（`packages/client/ui-chat/src/client/conversation-nodes/tool.ts:361`、`packages/client/ui-trajectory/src/client/trajectory-assistant-definition.ts:470`），keyed renderer 登记到 `conversation.chat.node` slot；只有聚合快照视图才走 `ctx.uiConversation.views.register(...)`（`packages/client/ui-chat/src/client/conversation-nodes/chat-snapshot-builder.ts:1243`）。服务键是 `'uiConversation'`（`packages/client/ui-conversation/src/client/conversation/assembly.ts:204`）——Host 没有这些 client registry，所以别指望在 Host 侧注册一个节点。

顺序是：定义 `match` / `update` / `target` / `buildViewNode` → `events.register` → slot 注册 renderer → 需要快照视图时再 `views.register`。不要在 `Session`、`SessionManager` 或任何中央 dispatcher 里为你的特性加分支；那是这条纪律唯一禁止的写法。
