# 认证与浏览器宿主

核验入口：[`packages/client/connection/src/browser-auth.ts`](../../../../packages/client/connection/src/browser-auth.ts)、[`packages/client/connection/src/rpc-host.ts`](../../../../packages/client/connection/src/rpc-host.ts)、[`packages/bundle/web-app/src/index.ts`](../../../../packages/bundle/web-app/src/index.ts)。

入口 URL 是一次性 token，之后是签名 cookie；桌面把同一个 web 应用当成本地宿主，因此认证链与 Web 完全相同。

**浏览器认证面**（web 与桌面同一条链）：入口 URL 是一次性 process-token URL——`authenticatedUrl(baseUrl)` 把启动 token 拼进 query（`packages/client/connection/src/browser-auth.ts:244`）；浏览器首个请求用它换取 `dsh-auth-` 前缀的 HMAC 签名 cookie（`:18` 的 `COOKIE_PREFIX`，HMAC secret 持久化在 credentials 体系 `client-connection/browser-session` 记录下，`:14` 的 `AUTH_RECORD_KEY`）；此后未认证请求一律 401（`packages/client/connection/src/rpc-host.ts:123-136` 的 `requestRejection` → `admit`）。web 的 stdout 行 0011 起只打一条 `dsh web: ${authenticatedUrl}`，不再附 LAN 地址（`packages/bundle/web-app/src/index.ts:231`；LAN 快照只服务 `/api` 的 trust fence 与 `ctx.webApp`）。
