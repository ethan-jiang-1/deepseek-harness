# architecture 扩展表对到源码

> 基线 `47f943859bef60e4160492346772ded9b24f765a`。表在 [`docs/architecture.md`](../../docs/architecture.md)「Where new behavior goes」。这里逐行给出登记点，不抄 cookbook。

介绍篇说那张表就是「挂插件，不要改 loop」的清单。对过源码之后，每一行都有一个 `ctx` key 或一条事件，没有隐藏的内核函数。

| 目标（表上的 Goal） | 源码登记点 |
|---------------------|------------|
| Add a model provider | `ctx.llm` 上登记 adapter（`packages/llm/llm`）。DeepSeek 实现：`dsh-llm-deepseek`。 |
| Add a model-facing capability | `ctx.tools.register` / `defineTool`（`packages/core/tools`）。schema 经 `systemPrompt` 进入组装。 |
| Give one session a different capability set | `packages/preset`：preset `cordis.yml`；服务行需要 `cordis:group` 的 `isolate` realm。header 持久化 `agentPreset`。 |
| Add shell execution | 子类化 `ShellExecutor`，插件登记为 `ctx.shell`。本地实现 `spawn` 经 `ctx.subprocess`。 |
| Add persistent terminal | `ctx.terminals` provider + Consumer `dsh-tool-terminal`（`packages/terminal`）。 |
| Add a human command | `ctx.commands.register`（`packages/interaction/commands`）。不经模型 turn。 |
| Add background work | `ctx.jobs` + `job_*` tools（`packages/jobs`）。与 shell start 的分界见 capability 专题。 |
| Add filesystem access or policy | `ctx.fs` provider，或听 `fs/*`。 |
| Confine spawned processes | `ctx.sandbox` backend；executor 在 spawn 前 `confine(argv)`。 |
| Intercept a request, tool, or turn | `agent/pre-step`、`agent/request`、`agent/turn-stopping`、`tools/pre-execute` 等。模式必须与 JSDoc `@mode` 一致。 |
| Add model-facing context | `agent.inject()` → inbox `next-step`、不 wakeup；下次获准请求变成 `user/message`。 |
| Add UI or editor integration | `ctx.agents.create` / `resume`，渲染 `session/event`。 |
| Add a Web Client Chat node | `ConversationNodeDefinition` + keyed renderer（`packages/client`）。 |
| Add durable session state | `declare module '@deepseek-ai/dsh-session/types'` 扩 `SessionEventMap`；读侧进 `KNOWN_SESSION_EVENT_TYPES`（跑 catalog 生成器）。 |
| Generate session titles | 唯一的 `ctx.sessionTitle` provider（`packages/session/session-title`）。title 事件 log-only。 |
| Manage a same-session objective | `ctx.goals`；续跑仍走 `agent/*`。 |
| Fork a live session | `ctx.sessions.fork(source, boundary?, childSessionId?)`。header 带 `parentSession` / `seedLength`。 |
| Scope a registration to one agent | 在 `agent.ctx` 上登记（`createScope` 的 key 是该 agent 对象）。 |

改 loop 合同本身（turn 何时开闭、inbox 语义、必须写哪些 session 事件）才动 `packages/core/agent-loop`，并且必须改 architecture 这张地图。那是表外的例外，不是默认路径。

`ctx.agentLoop` 存在，是因为默认驱动也是插件，要能被 bundle 插进去。扩展点仍然是上面这些，不是「给 loop 类加一个方法」。
