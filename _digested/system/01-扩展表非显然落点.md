# Architecture 扩展表的非显然落点

完整清单由 [`docs/architecture.md`](../../docs/architecture.md#where-new-behavior-goes) 的 “Where new behavior goes” 维护。本页只解释无法从 `ctx` 键直接看出的落点；模型、工具、shell、terminal、command、job、filesystem、sandbox、title、goal 与 fork 的常规登记点以该表和相应 package README 为准。扩展 cookbook 还索引了 [settings 卡片](../../docs/cookbook/adding-a-settings-card.md)。

源码核验入口：[`packages/preset/agent-presets/`](../../packages/preset/agent-presets/)、[`packages/client/ui-conversation/`](../../packages/client/ui-conversation/)、[`packages/client/ui-settings-plugins/`](../../packages/client/ui-settings-plugins/)、[`packages/core/session/src/known-event-types.ts`](../../packages/core/session/src/known-event-types.ts)、[`packages/core/agent/`](../../packages/core/agent/)、[`packages/core/agent-loop/`](../../packages/core/agent-loop/)。

## 每个 session 的能力组合

Agent preset 挂在 `agent.ctx` 的 scope 上。preset 中发布服务的行必须处于 `cordis:group` 的 `isolate` realm；`mountPreset` 会拒绝泄漏到进程根 realm 的服务，避免两个 session 共享本应隔离的实现。

初始 preset 写入 session header 的 `agentPreset`。空 session 改选 preset 时另写 `agent-preset/selected`，重建时以最后一次选择为准；只读 header 会把会话恢复到错误的工具和提示词组合。

## Web Client Chat 节点

Chat 节点属于浏览器侧 Cordis 树，Host 没有对应的节点注册表。插件把事件到节点状态的 Definition 经 `ctx.uiConversation.events.register(definition)` 登记——服务键是 `'uiConversation'`（[`packages/client/ui-conversation/src/client/conversation/assembly.ts`](../../packages/client/ui-conversation/src/client/conversation/assembly.ts) 以该键注册服务，[`event-registry.ts`](../../packages/client/ui-conversation/src/client/conversation/event-registry.ts) 的重复登记报错文案即写 `uiConversation.events.register(...)`）——再把 keyed renderer 登记到 `conversation.chat.node` slot。`conversationViews` 不是 `ctx` 键，也不是登记步骤：它是 conversation slot 的 hooks 快照（[`contract/slots.ts`](../../packages/client/ui-conversation/src/client/contract/slots.ts) 的 `conversationViews: ObservableSnapshot<readonly ViewTab[]>`）。

## 插件自有 settings 卡片

Web 设置页的 Plugins 段按命名空间键卡片。插件在 Host 半边用 `installSection(owner, ns, schema, entry, hooks)` 登记 namespace 与 schema（[`packages/settings/settings/src/index.ts`](../../packages/settings/settings/src/index.ts)），在浏览器半边把卡片登记到 `settings.plugin.item`；两边拼写同一个 namespace 就会自动配对。Host 提供每一个已登记的 settings namespace，经 settings-controller 这类 Remote 控制器暴露给客户端；`packages/host/apiproxy/` 已整体删除，不再有也不需要暴露白名单。加一张卡按 cookbook 做，对准现行 Host 侧 settings Remote 面。

## 持久 session 事件

新事件通过声明合并扩展 `SessionEventMap`。随后运行 `pnpm run gen-persistence-catalog`，让生成的 `KNOWN_SESSION_EVENT_TYPES` 与声明同步；持久化读取会拒绝未知且未标记 `ignorable: true` 的事件。渲染和模型历史都从日志重建，不能把持久事实只留在插件内存里。

> **ignorable 机制的历史**：#3087 曾删除 ignorable 机制，要求所有 event 必须被已知；#3325 随后回滚了这次删除，恢复了 ignorable。当前（`183f08e9c6`）ignorable 机制仍存在。

## 新后端存储 session

在新后端存储 session，是实现抽象 `SessionPersistence` 服务的五个方法（`create`/`open`/`flush`/`stat`/`list`，`packages/session/session-persistence/src/index.ts:147-198`）并复用共享 `SessionHandle` 脚手架（`read`/`append`/`flush`/`close`），而不是为每个后端重写文件格式与消费路径；`ctx.sessionPersistence` 是这个 seam 的键，已装后端是 `dsh-session-persistence-jsonl`，契约见 [`docs/subsystems/persistence.md`](../../docs/subsystems/persistence.md)。

## API Remote 架构（新落点）

架构迁移：`packages/host/apiproxy/` 中的 unary RPC 已大量迁移到 `packages/api/remotes/` + `packages/typert/` 的 **Remote 控制器**架构。这不是传统 seam（三角色），而是 BFF 层的新模式：Host 侧声明 Remote 控制器及其 schema，Typert 生成器自动导出 client stub；Client 侧（浏览器或 SDK）消费生成的 stub。迁移路径：settings、credentials、subagent control、agent-presets、workspace-controller、session-controller 已迁移；`packages/host/apiproxy/` 包已整体删除。directory-picker 要按两个面分开说：`ctx.directoryPicker` 是 Service seam（[`packages/host/directory-picker/`](../../packages/host/directory-picker/src/index.ts) 的 Service Definition），不是 Remote；另有 `ctx.directoryPickerController` 是 Host Remote 控制器（[`packages/api/workspace-controller/`](../../packages/api/workspace-controller/src/directory-picker.ts)，namespace `directoryPicker`）。

## 应用启动规则

`docs/architecture.md` 新增 **Application Launch** 规则（上游 #2988/#2977）：所有支持的 Node 应用必须从 `dsh` CLI + 具名 profile 启动。Vendored CLI、仅构建/测试可执行文件、进程内直接插件挂载都不是 Harness 应用启动器。`verify-application-entrypoints` 门禁维护显式分类。

## 实时拦截与 loop 例外

实时拦截使用事件声明指定的派发模式。`agent/pre-step`、`agent/request`、`agent/request-error`、`llm/stream` 与三条 `tools/*` 是 waterfall；`agent/turn-stopping` 是 serial，监听器可用 `agent.steer()` 提交续跑工作，驱动在关闭 turn 前重读 inbox。具体模式见 [`../cordis-runtime/02-waterfall-与事件合同.md`](../cordis-runtime/02-waterfall-与事件合同.md)。

`ctx.agents` 拥有公开的 `Agent` / `AgentFactory` 接口；默认 `dsh-agent-loop` 只是其中一个 factory provider。只有改变 turn 开闭、inbox 语义或必写 session 事件等驱动合同，才需要修改 loop，并同步更新 architecture 地图；替换默认驱动的义务见 [`../session-and-loop/03-换loop的半径.md`](../session-and-loop/03-换loop的半径.md)。
