# FAQ 03 · 四个内置模式（Standard / PTC / Minimal / Creator）各自特殊在哪？

## 背景与困惑

在 Web 界面新建任务时，模式选择器里有四个内置选项：**Standard（标准模式）**、**PTC 模式**、**Minimal（极简模式）**、**Creator（创造模式）**。

表面上看它们只是下拉框里的四个选项，但实际表现差别极大：PTC 连“模型怎么调用工具”都从逐个发 JSON 请求变成了写一段代码循环批处理；Minimal 把长篇系统提示词和仓库 `AGENTS.md` 全清掉了；Creator 甚至能让 Agent 反过来给 DSH 自己写插件、装插件、造新模式。

围绕这四个内置模式，有四个最实际的工程疑问：

1. **为什么不用写四套 Agent 循环？** 底层不改一行核心调度代码，只靠四份几十行的 `*.patch.yml` 补丁，是怎么在同一进程里拼出四种截然不同的工作方式、而且不同会话之间还不串台的？
2. **平时干活到底该选哪一个？** 默认的 Standard 给了哪些常规能力、又刻意把哪些高危工具挡在门外？遇到什么任务切到 PTC 真能省往返和上下文，什么情况完全没必要换？
3. **Minimal 砍掉了什么，又保留了什么？** 把系统提示词压成一句话、工具收窄到持久终端之后，隐藏在代码循环里的权限沙箱与长任务的上下文压缩还在不在？
4. **Creator 靠什么让 Agent 安全地扩展 DSH 自身？** 它多出来的宿主探查工具、`plugin_manager` 动态条件开关和四个创作技能怎么配合？此外，`preset` 与 `profile`、`minimal` 与 `sdk-minimal`、`Creator` 与 `cordis` 这些容易看串的名字各指什么？
