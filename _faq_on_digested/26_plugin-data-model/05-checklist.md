# 05 · 决策程序：十四问、四个例子、反模式与测试

## 这一篇回答什么

把前面几篇压成一张可以直接照做的清单：**先选承诺，再落到平面，最后才选 API**。然后给四个典型插件的数据切法，最后列出最容易踩的坑。

## 第零步：先选一个数据承诺

按顺序问，第一个“是”就是你的承诺：

1. **用户已经有这份数据了吗？** → P0 纯引用。你只需要路径和读取。
2. **能从会话/文件重新算吗？** → P1 会话派生。你只存可重建的检查点。
3. **必须跟项目一起走、被用户看见吗？** → P2 项目内文件。
4. **要跨会话记住、但用户不必编辑吗？** → P3 宿主账本 + 项目键。
5. **是关于这个人/账号的吗？** → P4 配置/凭据。
6. **需要每个项目一套进程/连接吗？** → P5，看 06 篇的 workspace scope。

承诺可以组合（例如 P2 项目文件 + P1 派生索引 + P4 偏好），但**每一块数据只能有一个主承诺**。

## 十四问（承诺选定之后）

按顺序问，不要跳步：

1. **用一句话说出这个事实**。说不出来，说明你还没决定要存什么。
2. **谁拥有它？** 用户（内容） / 会话（历史） / 插件（状态） / 没人（派生）。
3. **用户需要打开或编辑它吗？** 是 → 内容平面，写工作区。
4. **模型必须看见它吗？** 是 → 历史平面，落会话事件；否则不要让模型感知。
5. **重启后还要在吗？** 不要 → 内存/派生；要 → 继续。
6. **能从别的事实重算吗？** 能 → 派生层，写清重建路径；不能 → 状态平面。
7. **跟项目走还是跟人走？** 项目 → workspace 键；人 → home；只在这次对话 → session。
8. **项目键是什么？** 规范化路径（推荐）；不要用 `workspaceId` 当长期键。
9. **目录被删/被移/工作区被重加时，这条数据怎么办？** 写出清理/保留策略。
10. **它是秘密吗？** 是 → 只存 `CredentialRef`，调用点解析。
11. **它是大块文本/二进制吗？** 是 → 工作区文件、附件或 spill，不要塞 domain。
12. **它的 schema 会变吗？** 会 → 版本、兼容读或迁移；single 布局没有兼容读。
13. **并发写怎么保护？** domain 有单写链；文件用 `createIfAbsent` / `replaceIfVersion`；跨进程没有锁。
14. **怎么在隔离环境测试？** 独立 `DSH_HOME`，覆盖删除/重加、迁移、并发与模型可见面。

## 四个例子

### 例 1：代码检查器的分析缓存

- 事实：每个文件的检查结果，能重算。
- 平面：派生；作用域：workspace。
- 做法：home 域（`layout: 'per-record'`），键 = `realpath + 内容哈希`；记录里带 `lastSeenAt`。
- 失效：文件版本/哈希变了就重算；目录不存在就标记过期，定期清理。
- 反例：把结果存成权威、文件删了还推荐。

### 例 2：项目记忆（用户可读的知识）

- 事实：这个项目的约定、决策、术语。
- 平面：内容（用户可读）；作用域：workspace。
- 做法：项目内 `.your-plugin/memory.md`；索引是派生，可重建；用户可以直接编辑。
- 交付：不需要 `present`（它是工作文件，不是一次性产物）。
- 反例：把 memory 存进 home 域，用户找不到、换机器丢、删项目还留孤儿。

### 例 3：个人偏好

- 事实：跨项目的偏好（语气、默认模型、输出格式）。
- 平面：状态；作用域：home。
- 做法：简单、用户可调 → `Config` 的 `.volatile()` 字段（落 profile patch）；结构化、程序写入 → home 域的单例记录。
- 反例：每个项目存一份偏好，用户改十次。

### 例 4：报告导出

- 事实：用户要的报告文件。
- 平面：内容；作用域：workspace。
- 做法：写到会话 cwd 下的文件，`present` 声明；可选在 home 域记一条“最近导出时间”。
- 反例：把报告写进 `$DSH_HOME` 或附件库，然后告诉用户“去那里找”。

## 反模式清单

| 反模式 | 为什么会坏 | 替代 |
|---|---|---|
| 用户文件复制进 home 当真相 | 用户在外部修改，副本永久过期 | 只存路径/哈希；内容留在工作区 |
| `workspaceId` 当长期键 | 删除重加换 uuid，数据孤儿 | 规范化路径，或项目内标记文件 |
| 索引当权威 | 文件删除后仍被推荐 | 派生层 + 版本/哈希失效 |
| 秘密进 domain/settings/日志 | 明文落盘、随备份/导出泄漏 | credentials 引用 |
| settings 当数据库 | 每次写重写 profile patch；不是查询结构 | domain |
| 每个 workspace 一个 domain | `defineDomain` 静态，做不到 | 单域 + 路径键 |
| 用 `process.cwd()` 当项目 | 只是启动目录；服务多项目时全错 | 会话 `header.cwd` / 注册表 |
| 把插件状态写进会话日志 | 模型上下文污染；schema 绑死会话格式 | domain；只有模型可见事实才落日志 |
| 直接写 home/系统目录 | 绕过用户预期；可能破坏其他数据 | 只写当前工作区，必要时显式申请 |
| 用 spill 当交付 | 会过期；用户没有稳定入口 | 工作区文件 + `present` |

## 版本与迁移：插件自己的责任

- `single` 布局版本不等 → 拒绝打开；升级前先迁移文件。
- `per-record` 可以用 `compatibleVersions` 读旧记录；`invalidRecords: 'backup-and-skip'` 让坏记录不拖垮启动（仅派生/可丢弃数据）。
- 改语义、拆表、改键 → 新 domain 名字 + 一次性迁移；不要在原 domain 上偷偷改含义。
- 迁移要可重复、可校验（条数、抽样、读回），并在隔离 home 里演练降级。

## 并发与失败

- **domain**：每个域一条写链，`update` 在槽位上执行；内存只在校验通过后更新；写失败不留半状态。
- **文件**：`writeText` 的 `createIfAbsent` / `replaceIfVersion` 是并发保护；省略就是无条件覆盖。
- **跨进程**：JSON 后端没有锁；`domain/changed` 不跨进程。多 Host 共享 home 不是支持场景。
- **失败语义**：配置/schema 错误应在加载时 fail loud；用户数据的版本不匹配应给出可行动的错误，而不是静默重建。

## 测试策略

1. **隔离**：`DSH_HOME=$(mktemp -d)`，不要污染日常侧栏与会话列表（见 FAQ 25 的 Ungrouped）。
2. **生命周期**：建工作区 → 写数据 → 删工作区 → 重加 → 读数据；断言孤儿/保留符合设计。
3. **迁移**：旧版本 fixture → 新版本启动 → 读回 → 再降级，确认不写坏旧文件。
4. **并发**：两个 update 同时打同一个键；文件用版本守卫模拟外部修改。
5. **可见性**：断言 domain 数据没有进入模型请求；需要模型看的事实确实有事件。
6. **大小/二进制**：附件与 spill 的上限、失败路径、清理。

## 一张收尾的判断图

```text
用户已经有这份数据？ ──是──> P0 引用（Config + ctx.fs）
   │否
   ↓
能从日志/文件重算？ ──是──> P1 派生（projection / 缓存）
   │否
   ↓
要跟项目走、用户可见？ ──是──> P2 项目内文件（ctx.fs + present）
   │否
   ↓
跨会话记住、不必编辑？ ──是──> P3 home 域 + 路径键
   │否
   ↓
关于这个人/账号？ ──是──> P4 Config/凭据
   │否
   ↓
需要每项目运行时？ ──是──> P5 workspace scope（社区自建）
   │否
   ↓
回到 P1：也许你根本不需要持久化
```

注意：这张图的第一问不是“模型要看见吗”，而是“用户是不是已经有了”。**能不存就不存**，是社区里最省事、也最容易获得信任的路线。

## 边界

- 这套程序假设单 Host 账户；多租户需要部署层隔离，不是插件自己能解决的。
- “用户会编辑/带走”是产品判断；项目内文件与 home 域都能成立，选你能维护的那条。
- 本篇不评价具体后端的性能；写入频率高时优先 `per-record` 或 sqlite，并用基准验证。
