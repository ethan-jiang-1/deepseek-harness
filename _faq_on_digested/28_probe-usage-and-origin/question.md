# FAQ 28 · DSH 里的「探针」到底做什么？它是 DSH 的术语，还是一套工作法？

> **别从这篇开始读。** 想要一条缓坡就进 [00 五级台阶](./00-ladder.md)：从一句话爬到整套，每级只多一件事，读完一级就能停。本篇只记录「问题是怎么冒出来的」。

## 问题

写固件的人把探针接在 CPU 引脚上，从不怀疑那根针**属于**芯片；写 DSH 插件的人在用 `probes/` 这一类目录，却很难一句话答上来：探针是什么、为什么不用「测试」，这个词是 DSH 发明的吗？

这个问题在一轮对谈里被压成了五问：

1. **探针在 DSH 里是什么？** 是一个机制、一个包、还是约定俗成的一类脚本？
2. **它和测试（unit / e2e / snapshot）差在哪？** 既然都能「验证行为」，为什么还要第三样东西？
3. **「探针」是 DSH 独有的术语吗？** 换一个项目还叫这个名字吗？
4. **背后的原理是什么？** 为什么「先跑起来看一眼」这件事在 agent 系统里不是偷懒而是必需？
5. **该什么时候写一条探针，怎么写才不是自欺？**

## 为什么这个问题不好答

- **主仓没有这个东西。** 在 DSH 产品树里搜 `探针` 或 `probes/`，找到的是 registry probe、端口探针、`--probe` 这类**运行时自检**，是另一个概念。真正按「探针」组织的目录全部在插件仓（本篇第七节列了四个）。所以「DSH 里的探针」严格说不是产品能力，是**用 DSH 的人长出来的办法**。
- **和测试的界线是活的。** 同一条断言，写在 `tests/` 里叫测试，写在 `probes/` 里叫探针；区别不在断言，在**它连的是什么**（假的世界还是真的组合）。这条界线只能靠「外部依赖」和「确定性」来划，不能靠命名划。
- **词源容易误判。** 「探针」在中文里同时指硬件探针、医疗探针、以及 probe 的各种松散用法，很难从字面推出它在 DSH 语境里的严格含义。

## 要回答的问题

1. 探针在 DSH 语境里准确指什么，确定性的四个特征是什么？
2. 它与单测、e2e、录制会话快照的**分工表**长什么样？哪些能力只有它给得了？
3. 「探针」是 DSH 造的词吗？为什么社区和别的产品也用它？
4. 这套做法背后的原理：为什么 agent 系统的正确性不能靠断言穷举？
5. 什么时候该写探针？一条好探针的六条判据是什么？怎么证明探针本身没坏？

## 范围与边界

核验状态见 [核验基线登记](../00-baseline.md)。本篇引用的主仓机制（会话日志、`request/header`、`llm-replay`、快照分层）按该基线核；`probes/` 目录的实测读数来自本机四个插件仓，是可复现的观察，不是产品常量。

本 FAQ **不覆盖**：怎么从零搭一套探针基建（那是各仓的 `tools/lib` 与 `dev/probes` 的事）、录制会话快照的完整机制（见 [FAQ 21](../21_recorded-session-snapshots/answer.md)）、以及 DSH 内部那些同名的运行时 probe（registry probe 等，它们不是本篇的对象）。
