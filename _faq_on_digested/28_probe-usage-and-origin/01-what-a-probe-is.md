# 28/01 · 探针是什么：四个确定性特征

> **查询手册，不是读物。** 想知道「探针是什么」先从 [00 第 1 级](./00-ladder.md) 开始；本篇是给已经用过探针、需要把定义钉死的人。
>
> 本篇的探针范围：[03](./03-why-the-word.md) 列了主仓同名的五个落点（运行时能力探针、PATH 探针、复现探针、取证探针、诊断车道）；**本篇的四条特征描述的是「开发探针」那一类**——外仓 `probes/` 里的脚本与主仓的「复现 / 取证探针」。其余几类同名不同物，[03](./03-why-the-word.md) 有对照表。
>
> **「探针」是本文的说法，不是 DSH 的术语。** DSH 产品树里没有这个机制：`packages/` 不导出任何叫 probe 的 seam，`docs/` 也没有「探针」这一节。它是一套**围绕 DSH 长出来的开发工作法**，在插件仓里以 `probes/` 目录的形式落地。

## 一句话定义

**探针 = 驱动真实组合的一次诊断运行，产出带结构的事实，而不是产出「通过 / 失败」。**

拆成四个特征，四条同时成立才算探针：

| 特征 | 含义 | 反例（那就不是探针） |
|---|---|---|
| **驱动真的组合** | 从 `dsh` CLI 起真进程、起真浏览器、连真模型或真回放；被测对象是**装配之后**的东西，不是 `new` 出来的那一个类 | 直接 `new Session(...)` 的单测 |
| **一次性** | 不给下一个使用者留下需要维护的常驻负担：自己起、自己收，不做常驻服务；要复跑就再跑一次 | 一个需要人盯着开着的 dev server。**注意它和第二条的关系**：一次性说的是「不交付」，不是「不留档」——跑完留下的归档、判据函数、单测正是 [11](./11-what-probes-deposit.md) 说的沉淀，两者并不矛盾 |
| **产出结构化事实** | JSON 判决、会话日志片段、`sessionId`、截图 + DOM、逐相位 verdict；**事实**是可以被再解释的，「通过」不能 | 一句 `ok` 或一张看不到内容的图 |
| **不承诺稳定** | 不进 CI 门禁，不承诺每次都能跑（缺 Chrome、缺 key、缺 `zstd` 就 `BLOCKED`），也不承诺今天绿明天还绿 | 任何被 `pnpm test` 收集的东西 |

第四条是很多人会看漏的：**探针的价值不在于它稳定，而在于它诚实**。一个会随环境缺席而拒绝运行的探针，比一个在假环境里永远绿的测试更可信——因为前者至少不会冒充它证明不了的事。

## 三个近亲，别混

插件仓里与探针常常并排出现的是三类东西，判据是「它答的是哪个问题」：

| 东西 | 回答的问题 | 有没有基线 | 谁会红 |
|---|---|---|---|
| **探针（probe）** | 「现在到底是什么情况？」 | 无基线（第一次是**发现**） | 只有你，读判决时 |
| **期望（expected / snapshot）** | 「和上次比起来漂了吗？」 | 有基线（有 committed 期望） | 门禁，diff 非空就红 |
| **门禁（gate / smoke）** | 「能不能交给别人？」 | 有判据（必须全绿） | CI 或交接流程 |

一条探针跑稳之后，只要给它配一份基线、加一道门禁，**它就不再是探针了**。这也是各仓组织探针目录的第一条纪律：能进基线的不要占一个新脚本位。插件仓把这条写成了硬约束——能进 `web-face-check` 场景的**不进**新脚本，因为「场景有基线、有门禁、有人审」（见 08 的外仓校准表）。

## 它为什么长得像一个脚本

因为探针的产物是**证据**，而证据要能复跑。所以一条探针最终总是收敛成「一条命令 → 一个退出码 → 一个证据目录」：

```sh
pnpm preflight '<URL>'                    # 退出码 0 才把 URL 交给真人
pnpm web-expected '<URL>' --scenario <名>  # 退出码 1 = 漂移
node probes/browser-visual/cdp-probe.mjs '<url>' --evidence
```

这不是 DSH 规定的形状，是「证据要能被别人复核」这个要求自己长出来的形状：没有退出码就无法编排，没有证据目录就无法让别人相信你的判断，没有一条命令就无法在大脑里记住。

## 判据：一条脚本是不是探针

问三句：

1. **它能只靠假的世界跑吗？** 能 → 它更应该是测试。
2. **它跑完留下了什么？** 只有一句话 → 它是一条日志，不是探针。
3. **它敢不敢在前提缺失时拒绝运行？** 不敢 → 它会变成最坏的东西：一个在缺席条件下仍然报绿的检查（插件仓把它写成 `BLOCKED` + exit 2 的政策，正是为了堵死这条）。
