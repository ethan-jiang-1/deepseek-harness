# FAQ 23 · 桌面版（Desktop App）与 CLI/Web 各做到哪一步？插件怎么装、怎么隔离测试环境、全局 CLI 怎么安全升级？

## 问题背景

打开 DSH 官网下载页，提供的是独立的桌面安装包（macOS / Windows）；而翻开开发者文档和社区讨论，大家又习惯在终端里用 `npm install -g @deepseek-ai/dsh` 起 `dsh web`（默认 `3080` 端口）或跑无头命令，仓库文档里还不时出现 `standalone` 这个多义词。

对准备深度使用 DSH 或动手写插件的人来说，两套入口同时装在一台电脑上，立刻会碰上一连串具体疑惑：装了桌面端会不会覆盖 nvm 里的全局 `dsh`？两边看到的是不是同一份会话和插件？本地还在改的插件怎么跳过发 npm 包直接塞进去测？想开一个随便折腾的实验桌面又该怎么跟日常工作环境彻底隔开？

## 具体要回答什么

1. **两份发布物各做到哪一步、支持哪些系统？**
   独立桌面端（Desktop）与 CLI/Web 包各自打包了什么、进程怎么跑、签名公证与自动更新做到什么程度？macOS（Apple Silicon 与 Intel）、Windows、Linux 各自支持现状如何，社区反馈集中在哪些优缺点？

2. **同时装两套会互相污染吗？**
   可执行文件、插件依赖（`node_modules`）、界面设置、会话历史和 API 凭据，到底哪些按 Profile 天然隔离、哪些默认共用同一个 `$DSH_HOME`？

3. **插件怎么装，开发期怎么绕过正式发版？**
   Desktop 的六种装法、Web 页面和 `dsh plugin` 命令行有什么异同与生效边界？开发阶段有哪些免发包挂载本地代码与覆盖配置的手段？

4. **怎么搭双开隔离的实验环境，以及全局 CLI 怎么安全升级？**
   为什么双击图标环境变量会失效、`DSH_HOME` 与 `--user-data-dir` 怎么成对配合？全局 `@deepseek-ai/dsh` 走哪个通道升级、怎么预检与无损回滚？
