# Question 31 · 怎样长期维护高质量的 Agent Preset？

一个 preset 可以同时声明角色人格、工具、skills 和策略。刚写出来能工作，不代表经过多轮修改、共享内容调整、DSH 升级和模型变化后仍保持原来的职责与质量。

本专题面向独立 preset 项目的通用开发问题，对照 DSH 原生实现与质量纪律，并用 company-pack 的实际 presets、测试和脚本检验结论：

1. preset 与 persona、skill、profile、bundle 是什么关系？它实际交付什么？
2. 配置在哪个时点被验证，怎样从声明进入真实会话？旧会话、子会话和重启各采用哪一版？
3. “可加载”“能力正确”“遵守方法”“结果高质量”分别需要什么证据？
4. company-pack 已有做法保障了什么，哪些只是声明检查或有限场景，哪些还缺持续证据？
5. 修改内容、能力、共享方法或上游版本时，怎样选择检查并防止质量悄悄退化？
6. 怎样用真实失败改进 preset，而不把每次经验都堆进 persona 或制造更多同步义务？

读者无需先熟悉 DSH 内部结构。先读[主回答](./answer.md)，再按“定义与生命周期 → 案例证据 → 行为验收 → 长期维护”深入；研究页提供源码出处和核验记录。

本专题研究的是维护者怎样交付可靠的 preset。preset 内部的产出者/验证者流程也是被测产品，不能拿它代替开发与验收证据。
