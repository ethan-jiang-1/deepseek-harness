# 02 · 一层事实一个家，以及生成索引

## Tier taxonomy：把“哪里写”变成路由表

`docs/AGENTS.md` 的 tier taxonomy 是 DSH 文档组织的核心：

> The tier taxonomy: one home per fact
>
> Each fact has one home: the tier whose job it is; elsewhere, link there.
>
> —— `docs/AGENTS.md:15-17`（基线 `528c682e…`）

它明确划分了每个 tier 的职责和“不属于这里”的内容。例如：

| Tier | 拥有什么 | 不拥有什么 |
|---|---|---|
| Root `AGENTS.md` | standing orders，每个 1-3 行并链接 home | stories、worked examples、restated detail |
| `architecture.md` | 有序地图：composition、core packages、loop、seams、extension points | type definitions、package detail、decision rationale |
| subsystems | type definitions、semantics、generated Cordis API | behavior narration |
| Agent Notes | why、放弃了什么、验证 | migration plans、checklists、spec-speak |
| cookbook | step-by-step how-tos + verify | design rationale |
| Package README | 该包合同、config、semantics、limitations、Model Experience | JSDoc restatement、generated catalog restatement |
| Generated reference | 穷举英文源，从源码生成并 freshness-gated | hand edits |
| Skills | reusable workflows 与判定标准 | product/runtime contracts |

这解决了一个看似简单、实际很难的问题：**一个事实该写在哪里。** 当“哪里写”有唯一答案时，“去哪里找”也就有了唯一答案。

## 对模型的意义：路由是确定性的

模型遇到问题的路由变成查表：

- “怎么跑/怎么验证” → root AGENTS Commands、development、testing；
- “改代码前系统怎么组织” → architecture；
- “这个类型/服务的精确定义” → subsystems / generated cordis API；
- “为什么这样设计” → Agent Notes；
- “怎么一步步加包/加工具” → cookbook；
- “某个包到底提供什么、模型会看到什么” → package README；
- “全文搜索某个 API/事件/配置” → generated catalogs。

不是模型聪明地猜，而是文档体系把“猜”删掉了。

## 生成索引：穷举内容不占常驻上下文

DSH 最独特的一点是：**需要穷举的参考内容不由人写，也不要求模型预读。**

例如：

> <!-- Generated by scripts/gen-tool-catalog.ts — do not edit by hand. -->
>
> —— `docs/tool-catalog.md:1-2`

> <!-- Generated by scripts/gen-config-catalog.ts — do not edit by hand. -->
>
> —— `docs/config-catalog.md:1-2`

> <!-- Generated by scripts/gen-doc-graphs.ts - do not edit by hand. -->
>
> —— `docs/event-producer-consumer.md:1-2`

这些文件是查询面，不是阅读面。模型按图索骥时，索引永远存在且与源码一致；但索引不进入根 AGENTS 或 architecture 的预算，因为它按需加载。

## 链接必须是相对链接，且必须能解析

DSH 的文档规则要求用可检查的链接，而不是自由 prose 文件名：

> Link repository references with relative Markdown paths, never bare filenames or Agent Note numbers. `verify-md-links` rejects missing targets and dead `#fragment` anchors.
>
> —— `docs/AGENTS.md:75`（基线 `528c682e…`）

这对模型至关重要：地图上的每一条边都被机器验证过。按图索骥失败时，不是模型理解错了，而是 CI 会先红。
