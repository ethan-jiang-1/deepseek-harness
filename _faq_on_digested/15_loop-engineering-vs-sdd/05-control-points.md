# 05 · 控制点：让循环可见、可停、可审

## 使用范围

这是一份供你**试行**的控制点顺序，不是 DSH 插件作者的官方流程，也不是既经四仓验证的固定工时清单。只对跨多项工作、跨会话持续开发、又不想每笔都套完整 SDD 产物的独立插件仓提出建议。DSH 会话机制与 DSH 自身仓库纪律的区别见 [01 篇](./01-slice-vs-pipeline.md)，你已观察到的问题见 [04 篇](./04-owner-control-gap.md)。

## 一 · 先说清工作来源和谁能决定

对下一项工作，只保留一个权威来源：可以是现有 ROADMAP，也可以是 Issue 或 OpenSpec 的 change/tasks。每项至少让人看见**为何做、当前批准了什么、下一步是谁、遇到什么必须停下来问人**。不要在 goal、todo、提案和队列里分别维护互不相认的完整任务状态。你四仓的 ▶ 指针、`等人/可自主` 行标是可借鉴的实现，不是插件仓通用格式。

单会话 [goal](../../packages/goal/goal/README.md)是持续执行一个目标的状态，不是跨 feature 队列；会话 [todo](../../packages/todo/README.md)适合展示正在做的短任务。可以让 objective 引用**人已选定的当前项**、写明不做事项及停止条件，开始后由人用 `/goal` 等入口检查实际文字；若 agent 要扩大原范围，应请求新授权而不是仅仅 edit goal。轮次上限是安全边界，不是交付验收。goal 工具对某些动作要求直接人类输入的顶层轮次，仍允许模型代拟目标文字，见 [工具说明](../../packages/goal/tool-goal/README.md)。

## 二 · 在关键时点给人信息，而非要求每轮审批

建议把人工判断集中在三类事件：**开工前的范围与风险批准、进行中的重大偏离、结束时对需求与体验的验收**。小修复能从明确任务直接做并提交匹配测试；复杂需求可先写 spec、计划与场景让人审，实施中需要时再更新。Plan Mode 可用于具体计划呈批，但其[说明](../../packages/plan/README.md)明确「guides rather than restricts」，不能当成执行权限锁；你 20 个样本会话中的实际问询载体是 `ask_user_question`，不是 Plan Mode。重点应是**批准了什么且 agent 能否找回**，不是强求某个 UI 模式。

验证结果应逐项指回最初的目标：哪种测试、类型检查或实际操作覆盖了哪项外部行为，哪些判断仍未覆盖。绿灯不等于使用体验或需求解释正确；只信 agent 的自述也不够。DSH [测试政策](../../docs/testing.md#verify-the-world-not-the-self-report)同样强调检查外部世界而非自我报告。若人须审阅需求文本，使用 OpenSpec/Spec Kit 式产物是有效的选择，循环仍可在产物下反复实现与验证。

## 三 · 只把重复的、可判定的错误变成机器检查

你四仓已经对提案归属和失效指针尝试过校验；在某仓确有同类复发或损失风险时，补一个**针对那个错误**的检查，并用错误输入确认会失败。不要把「每个任务都要立卡」「一旦通过测试就算完成」之类仍须语义判断的要求冒充可自动决定的真理。外部插件仓可按需使用 `tasks.md`：上游 Note 不建集中 `INDEX.md` 的规则管的是 DSH 的 Note 树，不是所有插件仓的任务文件。选择一份能被新会话找到且由人能审的状态即可。

若出现多仓总览需求，可先建立**只指向各仓工作来源**的索引，避免复制并维护第二份完整进度；这尚是建议，未通过实际使用验证。不要先推广所有已有门禁到全部四仓。每个仓的状态载体和事故类型不同，先证明那项检查确有用。

## 四 · 用几笔工作检验，而非预告必然奏效

试行两三项不同大小的工作，每项记录：要不要临场提醒 agent 登记/计划、goal 有无未经批准的范围变化、审阅时是否知道哪些需求已验、完成后为何返工、机器检查是否抓到原本会漏的错误。如果只是状态变多却依旧要追问，检查的是**状态是否有一个可信来源、agent 是否真的在使用、人的审批是否产生可重访的记录**，而不是继续增加文件。如果需求有争议或多人必须审阅文本，就加厚规格与计划；若是一个明确的小修复，就让工作来源和测试保持轻量。

**最小可试的组合：人选择当前工作和停止/求助条件；agent 更新一个可见的执行状态并报告实际验证；人审范围变化及最终质量。SDD 产物可以提供这份可见状态，机器门禁只负责自己能判定的错误。是否足够，靠下一轮真实工作而不是本 FAQ 的工时估算验证。**
