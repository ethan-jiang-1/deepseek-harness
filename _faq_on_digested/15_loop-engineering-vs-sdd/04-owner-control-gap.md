# 04 · owner 复盘的机制定位：缺的不是把控力，是管线层的可见面

## 结论先行

owner 口述的五个体感缺口（B 路编码）逐条核对四仓证据后全部落在**管线层**，且每一条在四仓里都已经有对应的补面动作——补面是**痛点驱动**（每面都有「用户拍板/用户抱怨/用户要求」的原文锚点）、**事故续驱**（静默马拉松暴露的新失真以门禁封堵）的。残余的「把控力不够」由三件事构成：机制在场但未纪律化（TodoPanel 讽刺条）、两个权威面分工未对齐（ROADMAP 队列语义 vs goal 轮次语义）、跨仓无总览；三者共同的动力学是对话税还没完全资本化成结构（§4）。

## 第二节 事故驱动的补丁循环：没有阶段门时，失真怎么显影

09-25 三场 goal 静默马拉松（无人值守 8h/8h/4h；首场 12 提交、门禁咬作者一次）跑完的次日（09-26），四仓集中出现第二波补丁：▶ 指针失活事故 → `queue-pointer-live` 门禁；「代理推不动等人条目」→ `等人/可自主` 行标；「助手按计划办成了什么从信任面上消失」→ 在办/已办分组。没有阶段门时，把控缺口以**事故**形式暴露（机器跑起来后静默失真才成为真事故），然后以**门禁**形式固化。SDD 那边的缺口以「review 时发现偏离 spec」暴露，以改 spec/tasks 固化。两边都在学，显影剂不同：一边是门禁红和运行时事故，一边是阶段审阅。marathon 复盘（marathon-retrospective.md）本身就是这条回路的产物。

## 第三节 「goal 搞不清楚」的精确解释：goal 是 agent 的工作记忆，不是 owner 的仪表

会话日志（B4 路）给出比「双权威面」更硬的答案：20 个采样会话里**没有一例 owner 亲手创建的 goal**——所有 goal 创建事件都紧跟 agent 的 `create_goal` 调用；objective 数百字含判据，由 agent 多次 `edit` 精确吸收 owner 的对话更正（「信噪比是主线术语（用户更正）」「更新到 Paused Goal 里面成为 ongoing goal」）；`/goal` 人面与 plan mode 一样从未被使用。所以「搞不清楚」的机制是：**owner 把 goal 当作 agent 的工作记忆外包出去，只通过对话遥控其内容**——感知上自然只剩「一直被推进」（arch 会话 98 turns 中 73 次 goal 续轮、仅 24 条人类消息，「goal 追问」坐实）。双权威面的分工（ROADMAP=跨会话队列，goal=单条目执行器）本身健康且与上游「backlog 语义留给领域插件」的设计一致（iteration-rhythm:31-34），缺的只是把这句话写进入口链，以及 owner 偶尔用 `/goal` 看一眼而不必问 agent。

**修正一处流程写法与载体的分离**：四仓笔记写的「Plan Mode 呈批」门①，在 20 个会话里**零次**以 plan mode 执行——唯一一次 `exit_plan_mode` 调用直接报错（仅 plan mode 可用），agent 降级用 `ask_user_question` 呈批并被认真使用（38 次，含多次明确计划批准）。**批准回路的事实载体是 ask_user_question**；把控力评估应按实际载体计。

## 第四节 把控力的真实成本结构：对话税与「在场没人用」

口述里最高频的两个动作——「时不时提醒他计划计划」「要求显性化到 proposal 里头」——都是**对话税**：用对话轮次人工购买管线层可见性。B3 路的因果链显示这笔税后来被逐步资本化了：提醒 → 显性化（立卡/落盘）→ 门禁化（proposal-scheduled/pointer-live）。所以在这套跑法里，把控力走一条三步转化：**提醒（对话税）→ 显性化（文件/卡）→ 门禁化（机器拒绝）**；每走完一步，同类提醒就永久消失。另一条成本线是「在场的东西没人用」：todo/plan/goal 的人面机制一直都在，但没有进纪律就等于不存在——一旦写成反馈双门，机制才开始产出把控感。SDD 用户的问题正好相反：门一开始就在（阶段审批），但守门的是被约束的 agent 自己（02 篇第三节），最后同样要靠机械验收（yoaviram 自建编排层）收口。

## 最接近的一句话

**「把控力不够」对上的是管线层还没写完：四个 repo 里，可见性沿着「对话税 → 显性化 → 门禁化」在补，残余集中在双权威面对齐（ROADMAP vs goal）与跨仓总览。这两样是一页队列索引和一个 goal 写法约定的量级。公开的 loop engineering 还要求人能核的停止条件；那一条见 [05 篇](./05-control-points.md) 的 L3，不靠把官方流程改名为 loop engineering。**
