# FAQ 11 · 为什么很多人觉得“用 DSH 干活很省心、在仓库里改代码也很顺手”？它最自然的开发闭环是什么？

## 问题背景

翻开 DSH 仓库，第一印象往往是“规矩真多”：双层 `AGENTS.md`、十几套 `dsh-*` 技能、严格的文档双语配对、100% 单文件覆盖率门禁、还有专门记录设计取舍的 Agent Note。按常理说，约束这么密的地方写起东西来应该束手束脚才对；但实际用下来，不管是**在 Web/CLI 里指挥 DSH 干活的人**，还是**在仓库里带着 Coding Agent 提 PR、写插件的开发者**，普遍的体感反而是“省心、顺手、心里有底”。

这种“高约束下的轻松感”到底是从哪来的？DSH 骨子里最顺手的工作节奏长什么样？

## 具体要回答什么

1. “日常指挥 DSH 干活觉得省心”和“在 DSH 仓库里开发觉得顺手”，背后分别是哪套机制在起作用？
2. 在 DSH 仓库里，最顺着制度纹理走的开发闭环是哪几步？为什么它看上去像“规格驱动（SDD）”，因果顺序却刚好相反？
3. 哪些行为是 Harness 运行时硬性兜底的，哪些只是仓库写给 Agent 的工作纪律或团队习惯？
4. 这套模式有哪些真实的代价、延迟和适用边界（什么情况下并不轻松）？
