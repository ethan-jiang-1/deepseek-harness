# 04 · DSH 的独特判断与可迁移原则

## 独特判断

### 1. 对人和对模型的入口分离

README 明确把人引导到产品和贡献入口，把模型引导到 AGENTS。`CLAUDE.md` symlink 到 `AGENTS.md`，避免多 agent 协议各自维护一份规则。

这不是常见的“README 里加一段 AGENTS 说明”，而是把两类读者当成两个入口协议。

### 2. 根 AGENTS 是 standing orders，不是 onboarding essay

根 `AGENTS.md` 的任务是“每个 session 都必须在上下文里的规则”。因此它只保留：

- 布局；
- 命令；
- 不可违反的约定；
- 指向 home 的链接。

所有教程、故事、例子都被排除。**入口文档的目标不是让模型一次读完，而是让模型在每次 session 都带着正确的最小内核。**

### 3. 一个事实一个家

“写在哪里”先于“写得详细”。tier taxonomy 把事实分类，并把重复陈述列为 slop。这让导航可逆：从文件位置可以推出它拥有哪类事实；从问题类型可以推出应该去哪个文件。

### 4. 穷举与叙事分离

穷举内容由生成器维护；叙事内容受预算约束。模型不会因为“配置项太多”把 architecture 撑爆，因为 config catalog 是独立的生成文件。

### 5. 预算先 relocate，再 condense，最后 raise

渐进式披露通常缺少惩罚机制。DSH 的预算门禁给了一个明确的处理顺序：优先把内容送回 home，其次压缩，最后才允许扩大预算。这防止了“入口越来越厚”的熵增。

### 6. 历史、理由、当前状态分开

当前状态写进 prose；理由和放弃方案写进 Agent Notes；归档历史冻结且不当权威。模型读架构时看到的是 now，不会被 previously/now/renamed 干扰。

### 7. 图是机器可验证的

链接、预算、生成物、类型代码、双语配对全部有门禁。入口文档的可信度来自 CI，而不是“我们写得很认真”。

## 可迁移原则

如果要在另一个仓库复制这套做法，不必复制 DSH 的全部组织，但可以先复制这六条：

1. **先定义读者协议**：README 给人，AGENTS 给模型，CLAUDE.md 不另写事实。
2. **先定义 tier，再写文档**：每类事实只允许一个 home；重复就是 slop。
3. **给常驻入口设预算**：预算不是字数洁癖，而是上下文成本上限。
4. **把穷举交给生成器**：catalog 不是 hand-written 文档。
5. **把链接和新鲜度做成门禁**：模型按图索骥的前提是图不会悄悄断掉。
6. **把“为什么”和“现在是什么”分开**：current-state prose + Agent Notes。

## 边界

这套组织不是零成本：

- 它要求先有 tier taxonomy 和预算 manifest；
- 它要求维护生成器和门禁；
- 它更偏向 reference-heavy、agent 参与频繁的仓库；
- 它不替代教程，只是保证教程、参考、理由各有去处。

但对“模型第一次进入要能按图索骥”这个具体问题，DSH 的答案是目前最完整的一套：**把地图、容量和新鲜度都做成工程对象，而不是写作美德。**
