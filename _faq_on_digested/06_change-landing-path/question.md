# FAQ 06 · 在 DSH 里改一处功能，从想法到合入主干会落成哪些文件？哪些是每次必交的？

## 问题背景

[FAQ 04](../04_root-entry-doc/answer.md) 讲了 DSH 静态文档怎么做到“一个事实只放一个地方”，[FAQ 11](../11_native-development-loop/answer.md) 讲了日常开发的“窄切片闭环”怎么转起来。但真要往 DSH 仓库里合入一笔改动时，很多人还是会犯迷糊：

仓库里既有 GitHub Issue、又有 `proposed/` 和 `implemented/` 两种 Agent Note、还有会话里的 Plan Mode、`docs/` 架构文档、包 `README`、单测与录制快照、PR 模板和 CI 门禁——**改几行代码难道要把这八九道手续全走一遍吗？`docs/` 在里面到底算设计文档还是说明书？人和 Coding Agent 在这条链上各自管哪一段？**

## 具体要回答什么

1. 一笔变更涉及的意图、设计取舍、实施计划、代码、文档、测试和评审，在 DSH 里各自住在哪？哪些是**每次改行为都必交的**，哪些只是**按需升级的可选件**？
2. 为什么 `docs/` 严禁写“这次改了什么”，它在整条链路里扮演什么角色？
3. 小改一处 UI 和新增一整条跨包 capability seam，在真实 Git 历史里交付物有什么差别？
4. Push 之后的 PR 模板、CI 门禁、语义 Review 和人机职责边界是怎么配合卡关的？
