# 10 · 概念层：承诺、空间、家、作用域

## 这一篇回答什么

本目录用四套词描述同一件事。它们有固定顺序：**承诺 → 空间 → 家 → 作用域/键**。这一篇一次讲清四层的关系与边界，并规定"每个概念只有一章负责展开"；其余各章只引用，不再重复解释。

先看顺序，再看定义：

```text
承诺（对用户说什么）      P0–P5                          本篇 §1
   ↓ 落到
空间（这份事实属于谁）    插件包 / workspace / 账本 / 全局设置   15
   ↓ 用
家（DSH 用什么通道存）    内容 / 历史 / 状态 / 派生 / 客户端      11
   ↓ 寻址
作用域与键（怎么找到它）  session / workspace / profile / home / device   13
```

**顺序不能跳。** 跳过承诺就没有判据；跳过空间就不知道归谁；跳过家就会选错机制；跳过键就会留下孤儿。

![四层词汇：承诺 → 空间 → 家 → 作用域/键](../figures/10-taxonomy-flow.svg)

## 为什么需要这一层

三类最常见的混乱，都来自把两层压成一层：

- 把 **workspace 当可写性**：workspace 只给侧栏登记、会话 `cwd` 和沙箱根；能不能读写由 preset 的工具面决定（[17](./17-config-layers.md)）。
- 把 **账本当可重建**：账本里有可重建的索引，也有不可重建的绑定与选择；混在一起就会删错（[15](./15-four-spaces.md)）。
- 把 **profile 当账号**：profile 是安装单位；跨 profile 一致要靠 home 级文件（[17](./17-config-layers.md)）。

## 1. 承诺：P0–P5

承诺是作者对用户说的话：记住什么、放在哪、删了/换机器/升级后还算不算数。承诺定完，空间与键自动收敛。

| 承诺 | 一句话 | 主要落点 |
|---|---|---|
| **P0 纯引用** | 我不存，只读你已有的文件 | 用户文件原地 |
| **P1 会话派生** | 我不存聊天，只算统计/索引 | 会话日志 + 可重建检查点 |
| **P2 用户可见文件** | 数据跟项目或用户目录走 | workspace / 用户全局 |
| **P3 宿主账本** | 我按项目记，但东西在我这 | `$DSH_HOME` + 稳定路径键 |
| **P4 账号/安装配置** | 配一次，所有项目生效 | profile 配置 / home 域 / 凭据 |
| **P5 产品实例** | 这个 DSH 就是我的产品 | profile 组合 + workspace 根 + 全局设置 |

同一插件可以组合多种承诺，但**每一块数据只能有一个主承诺**。详细的数据卡与代价见 [00-answer](../00-answer.md) 与 [41](../40-advisor/41-checklist.md)。

## 2. 空间：四个

空间回答"这份事实属于谁"。四个空间各有权威、寿命与跨机器行为：

| 空间 | 权威 | 放什么 | 删了会怎样 |
|---|---|---|---|
| **插件包** | 发布版本 | 模板、种子、预设、客户端 bundle | 出厂能力消失，用户数据不动 |
| **workspace** | 用户 | 项目内容 | 删登记不删目录 |
| **账本** | 插件 | 索引（可重建）+ 绑定/游标（不可重建） | 索引可删；状态丢失即丢事实 |
| **全局设置** | 插件 | 跨 profile 的偏好 | 换机器就丢 |

展开与归属表见 [15](./15-four-spaces.md)。

## 3. 家：五个 + 一个只读层

家回答"DSH 用什么通道把它存下来"。它描述机制，不描述归属：

| 家 | 权威 | 例子 |
|---|---|---|
| **内容** | 用户（工作区文件） | 项目文件、交付物 |
| **历史** | 会话日志 | 消息、工具结果、事件 |
| **状态** | 宿主域 / Config / 凭据 | 索引、设置、秘密引用 |
| **派生** | 无（可重建） | 投影缓存、索引 |
| **客户端** | 浏览器/设备 | 面板状态、当前选择 |
| （只读层） | npm 包 | 包内模板与预设 |

展开见 [11](./11-five-homes.md)；状态三家的分工见 [12](./12-state-homes.md)。

## 4. 作用域与键

作用域回答"这条记录跟谁走"，键回答"怎么唯一地找到它"：

| 作用域 | 跟谁走 | 典型键 |
|---|---|---|
| session | 会话 | `SessionId` |
| workspace | 项目目录 | canonical path 哈希 |
| profile | 安装 | profile entry id |
| home | 这台机器/这个账户 | 单例或主题键 |
| device | 浏览器/设备 | origin + 本地键 |

键的规则见 [13](./13-scope-and-keys.md)；最容易犯的错是把 `workspaceId` 或裸路径当长期键。

## 两个读者入口

- **普通插件**（装在别人的 DSH 里）：承诺 → 家 → 作用域/键。空间只用到 workspace 与全局设置的边缘。
- **产品型实例**（这个 DSH 由一个插件决定）：承诺 → 空间 → 启动/配置 → 家。工具面决定架构，启动解析决定根。

## 五条常见混淆

1. **workspace ≠ 可写性**：可写性来自 preset 的工具面。
2. **账本 ≠ 可重建**：索引可重建，绑定与选择不可重建。
3. **profile ≠ 账号**：profile 是安装单位；跨 profile 一致靠 home 级文件。
4. **家 ≠ 空间**：家是 DSH 的存储通道，空间是产品视角的归属。
5. **产品型实例 ≠ 第七个作用域**：它是"profile 组合 + workspace 根 + home 级账本与设置"的合称，数据仍按 session/workspace/profile/home 落位。

## 边界

- 单 Host、单 `$DSH_HOME`；多租户与跨机器同步不在范围。
- 本目录的术语以本篇为准；与 DSH 官方文档冲突时，以 `docs/` 的当前合同为准。
