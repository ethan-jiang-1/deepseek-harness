# Research 09 · 生态经济学与企业需求证据（2026-08-27/28 外网检索）

本文件是 Answer 09 的外部证据层，回答两类问题：**同类生态商店/市场的成败先例** 与 **"审计可证明性"的企业需求证据**。规则：每条事实标来源与校验方式（live-check = 亲自 HTTP 复核；search = 来自检索结果但未逐字复读；secondary = 媒体报道/转述）。目录站数字为站方自报。

## A. 同类先例：商店/市场的成与败

- **GPT Store（反面范本）**：OpenAI 的收益分成从未超越一个小范围美国试点（[官方 FAQ](https://help.openai.com/ru-ru/articles/9119255-monetizing-your-gpt-faq)、[社区线程](https://community.openai.com/t/what-is-the-status-with-gpt-store-revenue-share/839172/4)，primary）；2026-08 中旬起对个人用户收紧 Custom GPT（[chatgptaihub 报道](https://chatgptaihub.com/openai-ends-custom-gpts-personal-plans-plus-pro-free-users-august-2026/)，live-check）。克隆/垃圾内容刷爆目录（[ecweb 综述](https://ecweb.ecer.com/topic/en/detail-256563-gpt_store_struggles_with_clones_spam_and_moderation.html)、[btw.media](https://btw.media/fr/le-gpt-store-openai-ne-repond-pas-aux-attentes)，secondary）。**结论：无分成 + 无门禁的目录 = 垃圾场**。DSH persona 市场若重复"免费上架等分成"的承诺，走的就是这条死路。
- **Koishi 的商店设计（正面范本 + 现状）**：官方市场只是 npm 之上的薄目录，发布到 npm 的 `koishi-plugin-*` 约 3 天自动同步（[官方论坛](https://forum.koishi.xyz/t/topic/12557/4)，primary）——**注册表即市场、目录不碰支付**。Koishi 仍活：npm 最新 v4.18.11、月下载 ~23.9k、GitHub 最后 push 2026-03（[registry API](https://registry.npmjs.org/koishi)、[api.github.com](https://api.github.com/repos/koishijs/koishi)，live-check）。线索：上一轮胜仗的生态今天仍在维护，且官方从未在目录里做支付。
- **Dify 路线**：官方插件 Marketplace 走精选目录 + Git 镜像仓库（[aliyun/dify-plugins](https://github.com/aliyun/dify-plugins)，primary）——开源 agent 框架的一致收敛形态是"免费精选目录"。
- **平台商店的货币化在退潮**：Chrome Web Store 移除内置支付、只剩 $5 开发者费（[官方废弃文档](https://developer.chrome.com/docs/webstore/cws-payments-deprecation)，primary）；Open VSX 以第三方注册表身份赢得被官方排挤的用户群，但因审查轻而出现恶意包（[Eclipse 博客](https://blogs.eclipse.org/post/thomas-froment/cant-download-vsix-vs-code-use-openvsx)、[Secure Annex 分析](https://secureannex.com/blog/these-vibes-are-off/)，secondary/live-check）。**结论：目录赚不到钱也守不住信任；信任只能靠 provenance + 机器检查，这正是官方该做的层。**
- **角色包/技能包市场在萌芽，但没有公开收入数据**：SkillHQ（[PeerPush](https://peerpush.com/p/skillhq)）、agensi.io（[cybercorsairs 报道](https://cybercorsairs.com/packaged-prompts-are-now-a-product-heres-the-marketplace-that-proved-it/)，secondary）；Lindy 等 "AI 员工" 按席位/额度订阅（$30–50/mo 入门，reviews）；行业口径转向**按 headcount 而非按 seat 定价**（[usagepricing 蓝图](https://www.usagepricing.com/blueprint/trends/agent-headcount-pricing)、[trends.vc](https://trends.vc/ai-employees-named-personas-cautionary-tale-outcome-pricing/)，secondary）。
- **支付轨道先于商店长好**：OpenAI × Stripe Agentic Commerce Protocol（[指南](https://agentic-commerce-protocol.com/docs/commerce/guides/get-started)，primary）、Google AP2（[Cobo 解读](https://www.cobo.com/post/ap2-protocol-complete-guide-to-agent-payments-for-web3-developers-2026)，secondary）、Stripe Sessions 2026 的 agent 支付（[KuCoin 报道](https://www.kucoin.com/news/flash/stripe-sessions-2026-stripe-integrates-stablecoins-agent-payments-and-treasury-into-mainstream-finance)，secondary）。**agent 价值链的资金流基建已在铺——"别人还没解决收款"不是借口，反而要防住"收款解决了、差异没解决"。**
- **DSH 生态的公开时间线**：v0.1 MIT 发布有主流日媒报道（[Gigazine 2026-08-14](https://gigazine.net/news/20260814-deepseek-harness-v0-1/)，live-check）；第三方 awesome 列表自述 developer preview 2026-08-13；社区目录站 imsai-sh 自报 **11,424** 个索引（README live-fetch），并衍生出 dsh-1024store 仓库、zat-dsh-engine 等互相竞争的前端。**发布两周内，目录、CLI、装进 DSH 内部的商店都出现了——分发层已被第三方占先。**（五个读数的对账见 [FAQ 08 research](../08_plugin-seam-maturity/research.md)。）

## B. "审计可证明性"的需求证据

- **法律侧（primary）**：EU AI Act Art. 12 要求高风险 AI 系统在其生命周期内技术上允许自动记录事件（日志）；Art. 19 要求 ≥6 个月日志留存（服从其他法律）；Arts. 11/18 要求技术文档留存 10 年（[artificialintelligenceact.eu Art.12 镜像](https://artificialintelligenceact.eu/article/12/)，primary 法条）。GPAI 义务 2025-08-02 生效、一般适用 2026-08-02，Digital Omnibus 把高风险义务推迟向 2027-12（[onvlaw 时程](https://onvlaw.ro/ai-act-delayed/)，search）。**日志/留存是法定义务不是卖点话术；DSH 的日志重建不变式直接落在这个义务上。**
- **需求侧（vendor 口径）**：Gartner 预测到 2027 年底前 >40% 的 agentic AI 项目将被取消，原因是 agent 经济学与**风险控制不足**（[官方预测](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027)，2026-08 复核时 403/反爬，仅保留 search 来源）。
- **竞品已经把"聊天里批 Agent"产品化了**：NanoClaw + Vercel 联合发布跨 **15 个消息应用**的 agentic 策略设置与审批对话（[VentureBeat](https://venturebeat.com/orchestration/should-my-enterprise-ai-agent-do-that-nanoclaw-and-vercel-launch-easier-agentic-policy-setting-and-approval-dialogs-across-15-messaging-apps)，secondary）；n8n 的 human-in-the-loop 教程（暂停工作流等 Slack/邮件批准，[官方文档](https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools)，live-check）；Temporal 的 durable Signal 审批模式（[官方 AI cookbook](https://docs.temporal.io/ai-cookbook/human-in-the-loop-python)，live-check）；Claude Code 还有未决 issue 要权限提示的 webhook/推送（[#29827](https://github.com/anthropics/claude-code/issues/29827)，primary）。**"从聊天审批"是现货，不是空白；现货里没有人做的是"成对的 ask/decide 审计事件 + fail-closed + 整请求可重建"——差异化在账本，不在聊天窗口。**
- **观测/追踪已是拥挤品类，"回放 agent 做了什么"不是空白**：LangSmith、Langfuse、Helicone、Braintrust、Phoenix、W&B Weave、AgentOps 都在 2026 年的 LLM/agent 可观测性对比清单里（[DevHelm 综述](https://devhelm.io/blog/best-ai-monitoring-tools)、[futureagi 的 Phoenix 替代清单](https://futureagi.com/blog/phoenix-alternatives-2026/)，secondary）；DeepInspect 的定位语直接是 "Replaying What an Agent Did and Authorizing What It May Do"（[DeepInspect vs AgentOps](https://www.deepinspect.ai/blog/deepinspect-vs-agentops)，secondary）。**这反证两点**："agent 审计"需求是真的、已被观测厂商验证；但没人做的是"loop 层强制、不可绕过 + 审批成对 + fail-closed"——这正是 DSH 的差异位，也是 answer 边界节单列它的原因。
- **沙箱与持久流程的资本佐证**：见 [FAQ 08 research](../08_plugin-seam-maturity/research.md) 补节（E2B/Daytona 融资、Temporal 两轮）。
- **MCP 安全事件支持 harness 级审计**：Invariant Labs 的 tool-poisoning 分析证明恶意 server 描述可劫持 agent 行为（[原文](https://invariantlabs.ai/blog/toxic-flow-analysis)，live-check）；MCP 已捐赠给 Agentic AI Foundation（[公告](https://modelcontextprotocol.info/blog/joins-agentic-ai-foundation/)，live-check）。**协议层没法给信任，信任只能由 harness 用日志重建兜底。**
