# FAQ 08 · “Everything is a plugin” 落到源码里：哪些领域已经够用，哪些还是真缺口？

## 问题背景

DSH 把自己定义为“all-plugin Cordis agent harness”。但口号落到真实工程里，无论是想给 DSH 写扩展的开发者，还是评估生态方向的人，都会先碰到两个很实际的问题：

第一，**哪些能力底座已经做得很扎实了，再从头造轮子纯属白费力气？哪些地方虽然留了接口（或者连接口都还没留），实际上还是真缺口？**

第二，仓库里有几百个包，很多能力默认没打开。**动手写新插件之前，怎么快速查清仓库里到底有没有现成轮子，避免写完才发现早就有了？**

## 具体要回答什么

1. 从源码和生成目录看，DSH 当前有多少条真正可替换的能力接缝（seam）？哪些已经多实现跑通，哪些还是单实现或空缺？
2. “能换掉 Provider”和“换了真的有差异”是一回事吗？只看数字容易产生哪些误判？
3. 结合仓库现状与外部社区自发造轮子的情况，当前最明确的生态缺口排在前面的是哪些？
4. 动手写代码之前，按什么顺序查清仓库里已有的服务、工具和未默认挂载的现货？
