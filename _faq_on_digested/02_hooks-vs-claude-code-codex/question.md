# 02 · DSH 有没有类似 Claude Code / Codex 的 hooks 机制？三家怎么比？

Claude Code 和 Codex CLI 都支持在配置文件里挂载 shell 命令钩子（hooks），在会话启动、prompt 提交、工具执行前后、回合结束等节点拦截动作、补充上下文或强制续轮。

很多人第一次看 DeepSeek Harness（DSH）时会问两个问题：

1. **DSH 有没有对应的 hooks？** 是跟 Claude Code / Codex 一样在配置文件里写 shell 脚本，还是走另一套路子？
2. **如果我已经有一套现成的 `hooks.json`，迁到 DSH 要重写吗？新写拦截逻辑又该选哪条路？**

本篇从五个实际维度把三家放在同一张桌子上对比，并给出清晰的选型边界：

- **声明与信任模型**：钩子写在哪、怎么合并、谁来决定能不能跑；
- **生命周期触发点与控制力**：能拦什么、能改什么、能不能注入上下文或强制继续；
- **执行与容错契约**：串行还是并发、超时怎么算、退出码与 JSON 输出怎么折算；
- **审计留痕**：钩子跑没跑、返回了什么，在会话日志里怎么查；
- **兼容桥与原生插件的分工**：什么场景直接挂兼容桥复用旧脚本，什么场景直接写几十行原生 Cordis 插件。
