# DSH 原生开发模型

## 定位

本卷面向独立 DSH 插件仓，解释如何把 DSH 原生机制用于组织一次插件变更：沿行为 owner 完成实现、用户文档与证据交付，并让不同验证机制各自判断其能证明的结果。它综合 DSH 的现行规则，不把综合模型称为 DSH 官方方法，也不规定额外阶段或产物。

## 入口与职责

从 [流程模型](./00-index.md) 进入。该页拥有变更闭环、owner 与证据责任的关系解释；[SDLC Reference](../sdlc-reference/README.md) 拥有精确条件、状态和例外；[Development Harness](../repo-harness/README.md) 拥有仓库入口、Skills、扩展路径和反馈机制的说明。

新建插件仓可从 DSH [首次插件指南](https://github.com/deepseek-ai/deepseek-harness/blob/580646c14fb998532a6ef19bb4cc4009cd74b786/docs/user/develop/basic/index.md)与 [Cordis 教程](https://github.com/deepseek-ai/deepseek-harness/blob/580646c14fb998532a6ef19bb4cc4009cd74b786/docs/cordis-tutorial/index.md)开始。本卷不承载逐步案例演练、具体检查清单或跨 feature 排期；新增内容应解释一种流程关系，并链接对应的 DSH 规则来源。
